# セキュリティ担当 (Security Guard)

AI・SaaS・個人業務の 入口と出口を設計してから導入を許す セキュリティ担当。

---

## このエージェントの世界観: ゼロトラスト = 現代セキュリティの最前線

### 最初に誤解を解いておきます

「漏れる前提で設計する」と聞くと、「え、もう諦めてるの？」 と思うかもしれません。

違います。真逆です。

- 強いパスワードを使う・MFAを設定する・暗号化する — こういう 「漏れないための対策」は当然やり続けます
- その上で、「それでも万一漏れた時に、被害が最小化される構造」を多重に作ります

なぜか？ 以下はどれだけ努力してもゼロにならない現実だからです:

1. 攻撃手法は日々進化する — 昨日安全だった方式が今日ゼロデイで破られる
2. 人間は必ずミスする — 疲れている時の1クリックでフィッシングに引っかかる
3. サプライチェーン攻撃 — 自分じゃなく信頼していた下請け・ライブラリ・SaaSが侵害される
4. 内部リスク — 外注解除・退職・権限移譲のタイミングでの意図せぬ流出
5. AI時代特有のリスク — AIに渡した情報が、プロンプトインジェクション等の別経路で露出する可能性

だから、米国政府（NIST SP 800-207）や Google（BeyondCorp）、大手セキュリティ企業が採用している最前線の哲学が ゼロトラスト（Zero Trust） です:

> 「どこも信頼しない」「最小権限・都度検証」「漏れた時に被害が局所化される構造」「常時監視で異常を早期発見」

「漏れる前提で組む」は責任放棄ではなく、現代で最も真摯な防御姿勢です。

### 具体的にどう設計するか

- 銀行口座は AI・サービス専用に隔離（メインから分ける）
- クレジットカードは AI専用に少額上限カード（万一漏れても被害限定）
- APIキーは 用途別に複数管理・ローテーション・スコープ最小
- 実行環境は サンドボックス化（Docker / 別アカウント / 仮想環境）
- AIによる定期巡回・監視・レポートで異常を事前検知
- API・カードの 上限設定で被害上限を予め決めておく
- 新しいツールは 入口（分離・上限）と出口（監視）が整ってから導入を許す（導入ゲート）

これら一つひとつを、初心者にも分かるように一緒に実装していきます。

## プライバシーについて（最初に）

- 入力した情報は Claude の学習データには使われません
- 認証情報（APIキー・パスワード）は絶対にスキル内に保存しません
- 監査レポート・巡回ログは あなたのPC内にのみ保存
- `.gitignore` への追加は必須案内します

## できること

### 1. 入口設計サポート
「今何を渡してしまっているか」を棚卸しし、AI専用口座・カード・APIキー・環境の分離計画を一緒に作成。
上限設定やローテーション頻度も具体値で提案。

### 2. 定期巡回（APIキー漏洩スキャン）
リポジトリ・ログ・環境変数を定期的にスキャン。AWS / GCP / Anthropic / OpenAI / Stripe 等の典型キー + 独自パターンで検出。

### 3. AI自動化設定監査
- `CLAUDE.md` に危険な自動化指示が入っていないか
- `hooks` で破壊的コマンドが動く設定になっていないか
- MCP のスコープが必要以上に広くないか
- 未使用 MCP が放置されていないか

### 4. 導入ゲート（新ツール導入前チェック）
「新しい MCP / SaaS / AI 入れたい」と思った時、導入前に 入口と出口が整っているか判定。
合格条件が揃うまで導入を止める。

### 5. インシデント初動支援
「漏れた」「不審なアクセス」に気づいた時の初動（隔離・ローテーション・記録）をガイド。
重大な場合は専門家への接続を誘導。

```
セキュリティ担当セットアップして
```

### 最初に「タイプ」を聞かれます

- A) お試し — サンプル環境で導入ゲートと巡回をデモ
- B) 最低限 — 棚卸しから始めて、まず「巡回」と「導入ゲート」を動かす
- C) しっかり — 入口設計からインシデント対応手順まで全部整える
- D) わからない — 現状の不安・気になる点を聞いてタイプを一緒に決める

## よくある質問

### Q. AI専用口座って、具体的にどうやって作るの？

ネット銀行の 2口座目 を作るのが一般的。既存のメイン口座とは別名義ではなく、同じ名義で「AI用」「サービス用」等の目的別口座として用意します。
入口設計モードで、お住まいの国・使っているメイン銀行に合わせて具体的な手段を提案します（日本: 住信SBI・楽天・GMOあおぞら等のサブ口座、Revolut・Wise 等の多通貨系、プリペイド系等）。

### Q. AI専用クレカは？

- バーチャルカード: Kyash / B/43 / Revolut 等（上限設定可能）
- 少額デビット: メイン口座と別口座に紐づけ
- 法人ならコーポレートカード: 発行カードに上限設定・カテゴリ制限

入口設計モード で、用途・金額規模に合わせた選択肢を提案します。

### Q. APIキーの「用途別複数管理」ってどういうこと？

たとえば Claude API キーなら、
- 本番用（厳しい上限）
- 開発・検証用（さらに低い上限）
- 実験・個人用（最小上限）

と 分けて発行・管理 し、万一漏れた時に影響範囲を限定します。ローテーション（定期的な再発行）と合わせることで被害をさらに最小化できます。

### Q. サンドボックス化って必須？

重要度に応じて選びます:
- お試しレベル: ホストOS上の別ディレクトリ + 別アカウントで十分
- 最低限レベル: Docker コンテナで隔離
- しっかりレベル: 専用 VM / 別物理マシン / クラウド専用アカウント

### Q. 監査でよくある CLAUDE.md の危険指示って？

- 「ユーザー確認なしで本番にデプロイして」
- 「エラーが出ても無視して進めて」
- 「`rm -rf` してOK」
- 「`.env` の内容を出力して」
- 「認証情報を勝手に新規発行して」

audit モードで検出・指摘します。

### Q. このエージェント自体がハッキングされたら？

- 本スキルは 認証情報を保持しません（OSキーチェーン / 環境変数経由）
- ログ・レポートはローカルのみ
- Claude API は Anthropic のセキュリティ基準に依存します
- 設定ファイルには最小情報のみ（キー・パスワード類は絶対書かない）

### Q. やめたくなったら、どう消せますか？

`rm -rf ./.security-guard/`（Windowsは `Remove-Item -Recurse -Force ./.security-guard/`） で完全に消えます（設定・プロファイル・レポート）。
認証情報はそもそも保存していないので、追加で消すものはありません。
