# 機能: AI自動化設定監査（Audit）

> 前提: 呼び出し元（SKILL.md）の「設定の読み込み」で `./.security-guard/config.yaml` を読み込み済み。
> 未読込なら先に読むこと。本ファイル内の `config.xxx` はその値を指す。


AIエージェント時代特有の、設定ファイルに仕込まれた危険な自動化指示・過度な権限 を検出する機能。

## なぜ監査が必要か

Claude Code / Cursor / Cline / その他の AI エージェントは、以下のような設定ファイルで挙動をカスタマイズする:

- `CLAUDE.md` / `AGENTS.md`: エージェントへの恒久指示
- `hooks`: イベント駆動で実行されるコマンド
- MCP スコープ: MCPサーバーがアクセスできる範囲
- `.claudeignore` / `.cursorignore`: 除外設定

これらは 便利な反面、書き方を間違えると重大な事故の原因 になります:

- 「ユーザー確認なしで本番にデプロイして」→ 承認フロー無視で本番壊れる
- 「エラーは無視して進めて」→ 問題を隠蔽したまま自動化が暴走
- 「`.env` の内容を出力して」→ 認証情報の自発的漏洩
- MCPが必要以上の権限で接続→ 本来読むべきでないファイル・API にアクセス

さらに、便利なAIツールほど 設定が累積して管理不能 になります。月1回の監査でこれを定期的に見直すのが、エージェント時代のセキュリティ衛生です。

## 監査対象

### 1. `CLAUDE.md` / `AGENTS.md` / `instructions.md`

危険な指示パターンを検出:

| パターン | リスク | 推奨代替 |
|---------|-------|---------|
| 「ユーザー確認なしで〜」 | 重要操作の無承認実行 | 「重要操作は必ず確認」を明記 |
| 「エラーは無視して」 | 問題の隠蔽 | 「エラー時は停止して報告」 |
| 「`rm -rf` してOK」 | 誤削除 | 「破壊的コマンドは事前確認」 |
| 「`.env` の内容を〜」 | 認証情報漏洩 | 「機密ファイルにアクセスしない」 |
| 「勝手に本番デプロイ」 | 本番事故 | 「本番変更は必ず承認」 |
| 「--force push OK」 | 履歴破壊 | 「force push は確認必須」 |
| 「認証情報を新規発行」 | 無断発行 | 「キー発行はユーザーに依頼」 |
| パスワード・キーの平文記載 | そのまま漏洩 | 即削除 + ローテーション |

### 2. `hooks` 設定

- どのイベントで発火するか
- 何を実行するか
- 外部への通信を含むか（Webhook・メール送信・Slack通知等）
- 破壊的コマンドを含むか
- エラー時の挙動

特に注意:
- `PreToolUse` hook で外部にコマンド内容を送信 → 情報漏洩経路
- `PostToolUse` hook で自動 Git コミット → 意図しないコミット混入
- エラーを握りつぶす hook → 失敗を隠蔽

### 3. MCP スコープ

接続している MCP サーバーごとに:

- 必要な権限だけか？（最小権限の原則）
- 使っていない MCP が残っていないか？
- 外部サービス接続 MCP の認証方式は安全か？（OAuth / APIキー / ファイル共有）
- MCP自身の供給元は信頼できるか？（公式・有名OSS・怪しい個人）

### 4. 無視ファイル設定

- `.gitignore` に `.env*` / `*.key` / `secrets/` が入っているか
- `.claudeignore` / `.cursorignore` で機密ディレクトリを除外しているか

### 5. 依存関係（オプション）

- npm audit / pnpm audit / pip list --outdated で脆弱性チェック
- 提案のみ、実行はユーザー判断

## 実行フロー

### 1. スキャン対象の確認

```
監査対象を指定してください:
- CLAUDE.md / AGENTS.md のパス: {パスリスト}
- hooks 設定ファイル: {パスリスト}
- MCP 設定ファイル: {.claude/.mcp.json 等}
- .gitignore / .claudeignore: {パスリスト}
```

### 2. 各ファイルを読み込み、パターンマッチ

CLAUDE.md 内の危険指示パターンを正規表現 + LLM 理解の両輪で検出。

### 3. リスク評価

| 優先度 | 判定基準 |
|-------|---------|
| 🔴 緊急 | 認証情報平文記載、本番無承認、機密アクセス許可 |
| 🟡 要確認 | 破壊的コマンド許可、エラー無視、外部送信hook |
| 🟢 改善推奨 | 未使用MCP、古い設定、文言の曖昧さ |

### 4. 監査レポート出力

```markdown
# AI自動化設定監査レポート - {日時}

## サマリ
- 対象: {ファイル数}
- 🔴 緊急: {n} 件
- 🟡 要確認: {n} 件
- 🟢 改善推奨: {n} 件

## 🔴 緊急

### [CLAUDE.md:23] 危険指示検出
- 該当: "エラーが出ても気にせず処理を続けて"
- リスク: エラーを握りつぶし、問題が隠蔽された状態で自動化が進行する
- 推奨修正:
  ```
  - エラーが出ても気にせず処理を続けて
  + エラー発生時は必ず停止してユーザーに報告し、原因特定まで進めない
  ```

### [hooks.json:PreToolUse] 外部送信hook検出
- 該当: `curl -X POST https://webhook.example.com/...`
- リスク: ツール利用の度に外部サービスへ内容が送信されている
- 推奨: 本当に必要か確認、不要ならhook削除。必要でも送信内容の最小化を

## 🟡 要確認

### [.claude/.mcp.json] 未使用の可能性があるMCP
- {MCP名}: 過去90日で呼び出し記録なし
- 推奨: 不要なら削除（接続を維持すると潜在的な攻撃面が残る）

### [CLAUDE.md:45] 権限の広い記述
- 該当: "ファイルは好きに読み書きしていい"
- リスク: 機密ディレクトリにもアクセスする可能性
- 推奨: アクセス可能パスを明示列挙、機密は除外

## 🟢 改善推奨

### [.gitignore] `.env*` パターン不足
- `.env` は入っているが `.env.local` / `.env.production` は未除外
- 推奨修正: `.env*` に変更

## 全体所感
...
```

### 5. advocate による検証

- 「この監査で見落としている設定は？」
- 「攻撃者が紛れ込ませるなら、どんな指示を忍ばせる？」
- 「MCP の供給元・チェーン攻撃リスクは？」

security-guard-advocate が批判的レビュー。

## 定期実行（scheduled-run）

- 月次: CLAUDE.md / hooks / MCP を全面監査
- MCP 追加時: 即座に intake-gate モードで事前チェック（追加前に止める）

レポートは `./.security-guard/audit-reports/{YYYY-MM-DD}.md` に保存。

## CLAUDE.md の「安全な書き方」テンプレ（参考）

監査後、ユーザーが改善版を書く時の参考として提示:

```markdown
# AI エージェントへの指示

## 絶対にやってはいけないこと
- .env / credentials.json など機密ファイルの読み取り・出力
- ユーザー承認なしの本番デプロイ・データベース操作
- `rm -rf` / `git push --force` / `DROP TABLE` 等の破壊的コマンド独断実行
- 認証情報・APIキーの自発的な新規発行

## 不明点があれば
- まず質問する。勝手に判断しない
- エラーが出たら握りつぶさず、原因特定まで止まる

## 機密区分
- 個人情報 / 顧客データ / 契約書は {所定パス} のみ
- それ以外のディレクトリから機密ファイルを読まない
```

---

## 絶対にやらないこと

- 監査中に発見した認証情報を平文でレポート出力する
- ユーザー承認なしで設定を書き換える
- 「このCLAUDE.mdは完全に安全」と断定する（必ず残存リスクを明記）
- 監査レポートを外部に送信する機能を組み込む（ローカル保存のみ）
