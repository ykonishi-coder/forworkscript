# セットアップウィザード

初回起動時に、ユーザーのタイプを確認してから3プランに分岐する。

## Q0: タイプ確認

> セキュリティ担当です。
> 最初にあなたの状況を教えてください。
>
> - A) お試し — まず何をしてくれるのか、サンプルで動かしてみたい
> - B) 最低限 — ひとまず「巡回」と「新ツール導入前チェック」だけ動かしたい
> - C) しっかり — AI専用口座・カード・キー管理・監査・巡回まで全部整えたい
> - D) わからない — 何が不安か言うので、一緒にタイプを決めたい

### D を選んだ場合

次のような観点で、不安レベルを引き出す:

> どれが一番心配ですか？（複数OK）
>
> 1. APIキー・パスワードが漏れていないか
> 2. AIに危険な設定を渡してしまっていないか（CLAUDE.md / hooks）
> 3. AIに使わせるカードや口座を、メインから分けるべきか
> 4. 新しいMCPやSaaSを入れる判断が正しいか不安
> 5. すでに漏れたかもしれないので対応したい
> 6. 家族・会社のメンバーにも同じ仕組みを広げたい

- 1 → B（最低限・巡回から）
- 2 → B（最低限・監査から）
- 3 → C（しっかり・入口設計）
- 4 → B or C
- 5 → incident-response モード直行
- 6 → C（しっかり）

---

## プラン A: お試し

### 目的
「このエージェントが何をしてくれるのか」の体感。設定ファイルは作らない。

### 流れ
1. サンプルの危険 `CLAUDE.md` を提示し、audit モードでどう指摘するかデモ
2. 架空リポジトリの漏洩 `.env` を提示し、patrol モードの検出例を見せる
3. 架空のSaaSを提示し、intake-gate モードで「入口と出口が揃っていない」判定のデモ
4. 「次は B プランで実データでやる？」と案内

ファイルは作らない。所要時間 5〜10分。

---

## プラン B: 最低限

### 目的
最小構成で「巡回」と「導入ゲート」を動かす。

### ヒアリング（3問）

1. スキャン対象: どのディレクトリ・リポジトリを巡回する？（絶対パスで複数可）
2. 主な利用サービス: Claude / ChatGPT / GitHub / AWS / その他 （漏洩検知のキー形式を絞る）
3. 巡回頻度: 週1 / 月1 / 手動のみ

### 出力

- `./.security-guard/config.yaml` を作成
- patrol モードの実行準備完了
- intake-gate モードでいつでも相談可能
- 次のステップ（C プランへのアップグレード）を案内

所要時間 15〜20分。

---

## プラン C: しっかり

### 目的
入口から出口までゼロトラストで再設計し、エージェント時代の情報セキュリティ体制を構築する。

### ヒアリング

#### ステップ1: 棚卸し（現状把握）

##### 金融・決済
- メイン銀行口座はどこ？そこにAI用途も混ざっている？
- クレジットカードは？AI/SaaS の自動課金はメインカード？
- サブスク管理はどうしている？

##### 認証情報
- APIキーは何種類くらい持っている？
- パスワードマネージャー使っている？（1Password / Bitwarden / Apple Keychain 等）
- 二要素認証（MFA）は全部入れている？

##### 実行環境
- AIを動かしている環境は？（ホストOS直 / Docker / VM / クラウド）
- リポジトリに `.env` を git-ignore 忘れたことがある？
- 自宅ルーターのパスワード変更したことある？

##### AI自動化設定
- `CLAUDE.md` の中身を自分で管理している？
- `hooks` は使っている？どんな hooks？
- MCP は何個入れている？

##### インシデント経験
- 過去に漏洩・乗っ取り・不審アクセスの経験がある？
- 直近で「あれ？」と思った事象がある？

#### ステップ2: リスク評価

各要素について「漏れたら何が起きる？」を一緒にシミュレーション。
たとえば:
- メインカードが漏れたら → 全生活の金銭被害 + 不正利用停止中の支払い詰み
- AI専用カード(上限3万)が漏れたら → 最大3万の被害で済む

### 設計ロードマップ

ヒアリング結果から、優先度付きロードマップを生成:

| 優先度 | 項目 | 所要時間 |
|--------|------|----------|
| 🔴 最優先 | AI専用カード開設（上限設定） | 1日〜1週間 |
| 🔴 最優先 | パスワードマネージャー導入 + MFA 全面化 | 数時間 |
| 🟡 次 | AI専用口座 / サブ口座の分離 | 1〜2週間 |
| 🟡 次 | APIキーの用途別分割・ローテーション | 数時間 |
| 🟢 継続 | Docker / サンドボックス化 | プロジェクト単位 |
| 🟢 継続 | 週次 patrol / 月次 audit のスケジュール | 初期化 |
| ⚪ 必要時 | インシデント対応手順書の用意 | 数時間 |

### 成果物

- `./.security-guard/config.yaml`
- `./.security-guard/zero-trust-profile.md`（自分の環境プロファイル）
- 週次 patrol スケジュール登録
- 月次 audit スケジュール登録
- インシデント対応カード（紙 or 別ファイル）

所要時間 1〜2時間（一気にやらず段階的が推奨）。

---

## 共通: 終了時に必ず伝えること

1. このエージェントは専門家の代替ではない
2. 重大インシデントは必ず専門家・警察サイバー課に相談
3. 認証情報は絶対にスキル内・Gitリポジトリに書かない
4. `.gitignore` に `./.security-guard/` / `security-guard/*.yaml` を追加
5. 次に呼ぶべきモード（patrol / intake-gate / audit）の使い方

## プライバシーの再確認

- このウィザードで受け取った情報は Claude の学習には使われない
- 設定・プロファイルは ローカル保存のみ
- 認証情報は 保存しない
