# 機能: インシデント初動支援（Incident Response）

> 前提: 呼び出し元（SKILL.md）の「設定の読み込み」で `./.security-guard/config.yaml` を読み込み済み。
> 未読込なら先に読むこと。本ファイル内の `config.xxx` はその値を指す。


「漏れたかもしれない」「不審なログイン・課金があった」「ランサム被害に気づいた」など、インシデントが起きた直後の初動をガイドする機能。

## 大前提

このエージェントは 情報セキュリティ専門家・弁護士・警察の代わりではありません。

重大なインシデント（顧客データ流出・ランサム被害・金銭被害発生・個人情報含む情報漏洩）では、必ず以下へ連絡:

- 所属組織の情報セキュリティ責任者
- JPCERT/CC（日本の場合）
- 警察サイバー犯罪相談窓口
- 個人情報保護委員会（個人情報が含まれる場合）
- 法務・顧問弁護士
- 契約しているサイバー保険会社

本エージェントの役割は、連絡するまでの 時間を無駄にしない初動 を案内することに限定します。

---

## 初動の原則

### 1. 落ち着く
- パニックで証拠を壊さない（ログを消さない・デバイスを初期化しない）
- 初動5分で取り返しのつかない操作をしないのが最重要

### 2. 切り離す
- 疑いのあるデバイスはネットワークから切断（Wi-Fi OFF / LAN抜く）
- ただし電源は切らない（メモリ上の証拠が消える）

### 3. 時系列を記録
- 気づいた時刻・操作・画面・エラーメッセージを 別のデバイスから 記録
- スクリーンショット・動画・メモ（侵害されていない別環境で）

### 4. 連絡と並行して止血
- 専門家連絡と並行して、被害拡大を止める操作（キー無効化・カード停止）

## カテゴリ別の初動ガイド

### A) APIキーが漏れた・漏れたかもしれない

1. 該当キーを即時 Revoke（無効化）
   - Anthropic: https://console.anthropic.com/ → API Keys → Revoke
   - OpenAI: platform.openai.com → API keys → Delete
   - AWS: IAM → セキュリティ認証情報 → Access key を Deactivate → Delete
   - GitHub: Settings → Developer settings → PAT → Delete
   - その他: 各サービスの最新手順を WebSearch で確認

2. 新しいキーを発行し直す
   - 用途別に分けて発行（漏洩前より被害範囲を狭める）
   - 上限設定を忘れずに

3. 使われた形跡がないか確認
   - コンソールの利用履歴・課金履歴
   - 普段と違うIPアドレス・時間帯・API呼び出し

4. 漏洩経路を特定
   - Git履歴にコミットしてしまった → 公開リポなら拡散済み前提
   - ログファイルに出力していた → そのログの共有範囲
   - スクショに写り込んだ → どこに共有したか

5. 影響範囲を棚卸し
   - そのキーで何にアクセスできたか
   - 顧客データ・社内データに触れた可能性
   - → 個人情報含む場合は法務・個人情報保護委員会への報告検討

6. 関係者・ユーザー通知の判断
   - 重大な場合は弁護士・広報と相談

### B) アカウントが乗っ取られた疑い

1. 別の安全な端末から即時パスワード変更
2. 全セッションを強制ログアウト（各サービスにその機能あり）
3. MFA（2要素認証）を有効化・再設定
4. 不審なログイン履歴・連携アプリ・メール転送設定を全確認
5. リカバリメール・電話番号が書き換えられていないか確認
6. 連携アカウント（SSO）の波及を確認
7. クレカ・決済情報が登録されているなら、不正利用履歴を確認

### C) 金銭被害（不正課金・不正送金）

1. 該当カード・口座を即時停止
   - カード会社のサポート電話・アプリで即時停止
2. 不正利用の異議申し立て
   - 多くのカード会社は60日以内申請で補償
3. 警察被害届
   - サイバー犯罪相談窓口 or 管轄警察
4. 保険（サイバー保険・個人賠償責任保険）の確認
5. 契約中のAI / SaaS サービスの課金履歴全部確認

### D) マルウェア・ランサム被害の疑い

1. ネットワークから切断（ただし電源は切らない）
2. 身代金要求には 即応しない（払っても復旧しないケースが多い・犯罪助長）
3. 警察・専門会社にすぐ連絡
4. バックアップの隔離を確認（バックアップにも感染が及ぶケースあり）
5. 自力復旧を試みる前に 証拠保全（フォレンジック会社が後で解析できるように）

### E) フィッシングに引っかかった疑い

1. 入力したパスワードを即時変更（別端末から）
2. 入力したサービスのMFA再設定
3. 同じパスワードを使い回していた他サービスも全部変更
4. 連携アカウントの乗っ取り可能性確認
5. クリックしたリンク・ダウンロードしたファイルは即時削除
6. 該当メール・SMSを保全（ヘッダー情報含む）

### F) AI自動化が意図せぬ動作をした

1. 自動化を即停止（hooks 削除・cron 停止・MCP 切断）
2. 何が実行されたかログから追跡
3. 外部への送信・削除・書き換えが発生したか確認
4. 被害があれば上記A〜Eに従う

## 時系列テンプレート

```markdown
# インシデント記録 - {YYYY-MM-DD HH:MM}

## 気づいたきっかけ
- 時刻:
- 状況:
- 画面:

## 初動
| 時刻 | 操作 | 実施者 |
|------|------|--------|
| 10:03 | 該当APIキーを Revoke | 本人 |
| 10:05 | 新キー発行・環境変数更新 | 本人 |
| 10:08 | Anthropic Console で利用履歴確認 | 本人 |
| 10:15 | Git履歴を調査 → 3日前のコミットに漏洩確認 | 本人 |
| 10:20 | 公開リポだったため拡散済み前提で対応 | 本人 |
| 10:30 | セキュリティ担当・法務に連絡 | 本人 |

## 影響範囲（暫定）
- 漏洩期間: X日
- アクセス可能だった範囲: ...
- 実際の利用履歴: ...

## 連絡先
- 組織内: ...
- 外部: ...

## 次のステップ
- [ ] ...
```

保存先: `./.security-guard/incidents/{YYYY-MM-DD-HHMM}.md`（`.gitignore` 必須）

---

## 原則: これだけは守る

1. 証拠を壊さない（ログ削除・デバイス初期化を急がない）
2. 時系列を必ず残す（別端末から）
3. 独断で対外発表しない（法務・広報と調整）
4. 「たいしたことない」と自己判断で済ませない
5. 再発防止は後回しでいい、まず止血と連絡

## advocate との連携

初動対応の最中に security-guard-advocate を呼び、

- 「今やろうとしていること、証拠を壊していないか」
- 「他に止血すべき経路は残っていないか」
- 「広報・法務・警察へ連絡すべきタイミングはいつか」

を冷静な第三者視点で確認する。

## 絶対にやらないこと

- 専門家の代わりに判断する
- 身代金を独断で支払う（犯罪収益への加担）
- 被害者・顧客への連絡を独断で行う（法務と調整）
- 攻撃者への直接連絡・反撃（違法になり得る）
- 「軽いから黙っておこう」（隠蔽は後で致命傷になる）
