# チェックリスト集

各モードで使える具体的なチェックリスト。初心者が「何から整えればいいか」迷わないための足がかり。

---

## 1. ゼロトラスト基礎チェックリスト（最低限）

「これだけは今日やる」の8項目:

- [ ] パスワードマネージャーを1つ導入し、全サービスのパスワードを保存
- [ ] メール・主要SaaS・銀行・GitHub にMFAを設定
- [ ] AI・SaaS課金用に、メインと別のカード or バーチャルカードを用意
- [ ] 端末にスクリーンロック（タイムアウト短め）を設定
- [ ] Wi-Fi管理者パスワードを初期値から変更
- [ ] 使っていないSaaS・アカウント・MCPを棚卸しして削除
- [ ] `.gitignore` に `.env*` / `*.key` / `secrets/` が入っているか確認
- [ ] CLAUDE.md / hooks に危険指示が入っていないか一度 audit

---

## 2. AI専用カード・口座 発行チェックリスト

### カード発行前

- [ ] 月額利用想定額は？
- [ ] 1回利用上限はどこまで許容？
- [ ] 海外決済は必要？
- [ ] 名義は個人 / 法人どちら？
- [ ] 不正利用時の補償額・期間を確認

### カード選定時

- [ ] 上限設定機能があるか
- [ ] リアルタイム利用通知があるか
- [ ] カテゴリ別制御（EC・実店舗・海外）ができるか
- [ ] 即時停止・再発行が可能か
- [ ] アプリで管理できるか

### 発行後

- [ ] 上限設定（月額・1回）を入れる
- [ ] 不要なカテゴリをOFFにする
- [ ] 利用通知をONにする
- [ ] パスワードマネージャーに登録
- [ ] 会計ソフト側で「AI専用カード」と明細が見分くように設定

---

## 3. APIキー発行チェックリスト

### 発行前

- [ ] 用途を1つに絞れるか（用途別に分けるのが原則）
- [ ] 必要な権限スコープを最小限に絞ったか
- [ ] 上限設定（quota / 金額）が設定可能か
- [ ] 期限付き発行ができるか

### 発行時

- [ ] 発行したキーをパスワードマネージャー（or シークレットマネージャー）に即保存
- [ ] 別のチャット・メール・メモ帳に貼らない
- [ ] スクショ撮らない（撮ったら即削除）

### 運用中

- [ ] 四半期に1回ローテーション予定をカレンダー登録
- [ ] 利用量を定期監視
- [ ] 未使用なら即Revoke

---

## 4. 新ツール導入前チェックリスト（入口）

- [ ] 専用アカウントで登録できるか
- [ ] 専用決済で払えるか
- [ ] 必要な権限だけの認証で接続できるか
- [ ] キー・トークンをローテーションできるか
- [ ] 上限設定ができるか
- [ ] サンドボックス or 別環境で試せるか
- [ ] 公式供給元か（野良は警戒）
- [ ] 直近90日で重大な脆弱性報告がないか

## 5. 新ツール導入前チェックリスト（出口）

- [ ] 操作ログ・アクセスログが残るか
- [ ] 異常時にアラートが飛ぶか
- [ ] patrol / audit の監視対象に入れられるか
- [ ] やめたい時に即停止・完全削除できるか
- [ ] データをエクスポートできるか

---

## 6. AI自動化設定監査チェックリスト

### CLAUDE.md / AGENTS.md

- [ ] 「ユーザー確認なしで」系の文言がない
- [ ] 「エラーは無視」系の文言がない
- [ ] 「`rm -rf` / force push / 本番デプロイを独断」系がない
- [ ] 「.env / credentials を読んで」系がない
- [ ] パスワード・APIキーが平文で書かれていない
- [ ] 機密区分（どのディレクトリは触らない）が明記されている

### hooks

- [ ] 外部送信 hook がある場合、送信先と内容を把握している
- [ ] 破壊的コマンドを含む hook がない
- [ ] エラーを握りつぶす設計になっていない
- [ ] PreToolUse / PostToolUse に機密アクセスがない

### MCP

- [ ] 使っているMCPを全部把握している
- [ ] 未使用MCPを削除している
- [ ] それぞれのMCPの権限スコープを把握している
- [ ] 公式・信頼OSS のMCPだけ使っている

### 無視ファイル

- [ ] `.gitignore` に `.env*`
- [ ] `.gitignore` に `*.key` / `secrets/`
- [ ] `.claudeignore` / `.cursorignore` で機密ディレクトリ除外

## 7. 週次 patrol チェックリスト

- [ ] ワークツリーのスキャン実行
- [ ] 新規コミット分のスキャン実行
- [ ] ログファイルのスキャン実行
- [ ] 検出結果のトリアージ（即対応 / 要確認 / 誤検知候補）
- [ ] 即対応分のキーを Revoke + 再発行
- [ ] レポートを `./.security-guard/patrol-reports/` に保存
- [ ] ゼロ件だった項目もレポートに残す（監視が動いていた証跡）

---

## 8. 月次 audit チェックリスト

- [ ] CLAUDE.md / AGENTS.md を再読して危険指示確認
- [ ] hooks 設定を再確認
- [ ] MCP の棚卸し（追加 / 削除 / 未使用）
- [ ] .gitignore / .claudeignore の更新
- [ ] 前月の patrol レポート全件を振り返り
- [ ] 前月にインシデントが発生していたら再発防止策の定着確認
- [ ] 次月以降の改善アクションを1〜3個設定

---

## 9. 四半期 ゼロトラスト診断チェックリスト

- [ ] 全キーの一覧と用途を棚卸し
- [ ] 未ローテーションのキーを全件ローテーション
- [ ] パスワードマネージャー内の古いエントリを整理
- [ ] サブスク・アカウントの棚卸し（解約候補）
- [ ] カード・口座の利用状況レビュー
- [ ] MFA適用状況の棚卸し
- [ ] バックアップの復元テスト（本当に戻せるかを確認）
- [ ] インシデント対応手順書の更新

---

## 10. 年次 全面見直しチェックリスト

- [ ] ゼロトラスト診断を全項目再実施
- [ ] 環境プロファイルの更新
- [ ] 退職者・外注解除に伴うアクセス権はがし漏れがないか
- [ ] サイバー保険の契約内容見直し
- [ ] 法改正（個人情報保護法・各国規制）への対応確認
- [ ] 家族・メンバーにも同じ運用を展開しているかレビュー

---

## 使い方

- setup モードで、ユーザーのタイプに合わせて関連するチェックリストを提示
- intake-design / intake-gate / audit モードで該当リストを逐次消化
- 進捗は `./.security-guard/zero-trust-profile.md` に記録（達成済み項目は済チェック）
