# 定期実行セットアップ

秘書を自動で動かすためのスケジュール設定ガイド。

## 安心事項

- 定期実行は あなたのPCで動く仕組み（cron / タスクスケジューラ / `/schedule`）を使う
- 外部サーバーに常時接続する仕組みではない
- 停止したいときはエントリを削除するだけで完全に止まる
- 自動実行されるのは「下書き作成」「サマリ生成」までのみ。実送信や予定変更は絶対にしない

## 設定する機能

秘書で定期実行できる機能は、config の `schedule.functions` で有効化する:

- `email_reply`: メール返信下書きの自動作成
- `schedule_check`: 朝の予定サマリ生成

両方有効にする、片方だけにする、どちらも無効（手動のみ）にすることが可能。

## 頻度パターン

### 1) 1日1回（朝のスタート時）

- 推奨時刻: 平日 8:00 〜 8:30
- 実行内容: 朝のサマリ（予定） + 過去24時間の新着メール返信下書き
- メリット: 1日の始まりに秘書が準備完了している
- 向いている人: メール処理をまとめたい、朝に整えたい

### 2) 1日2回（朝・夕方）

- 推奨時刻: 8:30 / 17:00
- 朝: その日のサマリ + 前日夕方以降のメール
- 夕方: 明日のサマリ + 日中届いたメール
- 向いている人: 取引先とのやり取りが多い

### 3) 2〜3時間おき

- 推奨: 9:00, 12:00, 15:00, 18:00
- メリット: リアルタイム性
- デメリット: API利用コスト増加
- 夜間は停止推奨

### 4) 毎時

- コストと効果のバランスが悪いことを案内
- 本当に必要か再確認

### 5) 手動のみ

- 定期実行なし、必要なときだけ呼ぶ

## 実装手段

### 手段A: Claude Code の `/schedule` スキル（推奨）

- 条件: Claude Code で `/schedule` が使える
- メリット: 設定が簡単
- 設定:
  ```
  /schedule
  → cron式: "30 8 * * 1-5"（平日8:30）
  → コマンド: "秘書の定期実行を動かして"
  ```

### 手段B: OS 標準 cron（macOS / Linux）

```bash
crontab -e
```

追記例:
```
30 8 * * 1-5  cd /path/to/your-project && claude -p "秘書の定期実行を動かして" >> ./.secretary/logs.txt 2>&1
```

確認:
```bash
crontab -l
```

停止: 該当行を削除。

### 手段C: macOS launchd / Windows タスクスケジューラ

GUI で管理したい場合の選択肢。plistまたはGUI設定。

## 登録フロー（ウィザードから呼ばれた場合）

### Step 1: 手段の選択

> 定期実行の方式を選んでください:
>
> 1) Claude Code の `/schedule` を使う（一番かんたん・おすすめ）
> 2) OS の cron を使う（ターミナルに慣れている方向け）
> 3) OS 標準のタスクスケジューラ
> 4) いまは登録せず、設定ファイルだけ作って後で自分で
>
> 迷ったら 1) がおすすめ。

### Step 2: 時刻と頻度の確認

Q4（ウィザード）の回答を元に、cron 式を生成:

- 1日1回（平日8:30） → `30 8 * * 1-5`
- 1日2回（8:30と17:00） → `30 8,17 * * 1-5`
- 2時間おき（9-17時） → `0 9-17/2 * * 1-5`
- 毎時（9-18時） → `0 9-18 * * 1-5`

### Step 3: cron式の提示

必ずユーザーに見せてから実行:

> 以下の cron 式で登録しようとしています:
>
> `30 8 * * 1-5` （= 月〜金の 8:30）
>
> これで進めてよろしいですか？

### Step 4: 登録

承認後に登録を実行。

### Step 5: 動作確認

> 登録が完了しました。今すぐ試しに1回実行してみますか？
> （任意です。明日の朝まで待っても問題ありません）

## 停止・変更

### /schedule を使っている場合

```
/schedule list
/schedule remove {id}
```

### cron を使っている場合

```bash
crontab -l
crontab -e  # 該当行を削除または修正
```

### 完全削除

1. 上記手順でスケジュール削除
2. `rm -rf ./.secretary/`（Windowsは `Remove-Item -Recurse -Force ./.secretary/`）
3. これで痕跡なし

## 安全装置

### 多重起動防止

- ロックファイル `./.secretary/.lock` で排他制御
- 前回分が実行中ならスキップ

### 実行ログ

- `./.secretary/logs.txt` に結果を追記
- 処理件数、エラー有無を記録
- 月1でローテーション

### 異常時の自動停止

以下で自動停止しユーザー通知:
- 連続3回エラー
- 1回の実行で想定外に多く処理しようとした（例: 100件以上）
- 認証エラーで接続不能

手動で復旧するまで再開しない。

## よくある質問

### Q. 夜間・休日は動かないようにできますか？

cron式で制御可能。
- `30 8 * * 1-5` → 平日のみ
- `0 9-18 * * 1-5` → 平日の 9-18時

### Q. 出張中・休暇中に一時停止したい

cron行を一時的にコメントアウト（行頭に `#`）。戻ったら `#` を外す。

### Q. 勝手に送信される事故が心配

秘書は送信機能・変更機能を持たない。下書き保存・表示までで必ず止まる。
- Gmail MCP 等は「送信権限」を渡さない設定
- Calendar も「読み取り権限」のみ

### Q. 複数PCで同じ設定を使いたい

`./.secretary/` を両PCにコピー（認証情報はPCごとに別途設定必要）。
