# 機能: メール返信下書き作成

> 前提: 呼び出し元（SKILL.md）の「設定の読み込み」で `./.secretary/config.yaml` と
> `./.secretary/style-profile.md` を読み込み済み。
> 未読込なら先に読むこと。本ファイル内の `config.xxx` は config.yaml の値を、
> 「文体プロファイル」「style-profile.md から取得」は style-profile.md の蓄積内容を指す。
> style-profile.md が未生成またはデフォルトのままなら「汎用ビジネス文体で生成」と明示すること。


秘書の email-reply モード から呼ばれる詳細手順書。

## 安心事項（再掲）

- 実送信は絶対に行わない。下書き保存までが上限
- 入力メール本文は処理時に Claude API に送られるが、学習データには使われない
- 下書きは指定された保存先（Gmail下書き／ローカルファイル／表示のみ）に置くだけ

## 入力として受け取るもの

### 必須
1. 元メールの本文（貼り付け、またはファイル、または連携経由で自動取得）

### できれば
2. 返信の意図（承諾 / 辞退 / 質問 / 保留 / 情報提供 / その他）
3. 相手との関係性（社外初対面 / 継続取引 / 社内 / 上司 / 顧客）
4. 温度感（短め / 標準 / 丁寧）
5. 言語（日本語 / 英語 / 元メール準拠）

意図が不明な場合、質問は1往復にまとめる。段階的に何度も質問しない。

## 手順

### 1. 元メールを読み解く

以下を抽出:
- 差出人の立場（肩書き・組織・初対面か既知か）
- 要旨（1行）
- 求められているアクション（返事/日時調整/資料送付/決裁など）
- 明示されている期限
- 相手のトーン

### 2. 文体プロファイルを読み込む

`style-profile.md` から以下を取得:
- 宛名パターン（社外/社内の使い分け）
- 書き出し定型句
- 一人称
- 敬語レベル
- 締め句
- 頻出表現
- 絵文字の使用方針
- 署名

プロファイルが空やデフォルトの場合、汎用ビジネス文体で生成。

### 3. 返信方針を確定する

- スタンス: 承諾 / 条件付き承諾 / 辞退 / 保留 / 質問返し / 情報提供
- 長さ: 短（3〜5行）/ 標準（6〜10行）/ 丁寧（10行以上）
- 言語: 元メールと同じ言語が原則

### 4. 構成テンプレを当てはめる

#### 日本語
```
件名: Re: 〜（元件名継承、必要なら補足括弧）
宛名: 〜様（初出はフルネーム、2通目以降は苗字のみ可）
書き出し: お世話になっております。〜の{自分}です。
本文: 要件（結論→理由→補足の順）
締め: 引き続きよろしくお願いいたします。
署名: {style-profile.md の署名}
```

#### 英語
```
Subject: Re: ...
Greeting: Hi {First Name}, / Dear {Full Name},
Opening: Thanks for your note / Thank you for reaching out.
Body: 結論ファースト
Closing: Best regards, / Kind regards, / Best,
Signature: {署名}
```

### 5. 複数案を提示する

原則として 3案:

1. 短め版: 承諾・辞退など結論が明快なとき
2. 標準版: 通常。理由・補足を1〜2文添える
3. 丁寧版: 社外の重要な相手、初対面、謝罪・辞退

各案はコードブロックで分ける。

### 6. プレースホルダで埋められないものを残す

勝手に推測して埋めない。`{}` 形式で残す:

- 相手の氏名・役職が不明 → `{相手氏名}様`
- 自分の署名・所属 → `{署名}`（通常は style-profile から埋まる）
- 日時の再調整候補 → `{候補日時1}/{候補日時2}/{候補日時3}`
- 金額・数量・期間 → `{金額}` `{期間}`
- 元メールにない固有名詞 → `{プロジェクト名}` 等

ドラフト提示後、「要確認プレースホルダ」を必ず一覧で添える。

### 7. 保存先に下書き保存

`config.mail.integration` に応じて:

- `gmail_mcp` / `graph_api` / `applescript`: API経由で下書き保存
- `manual`: 表示のみ。ユーザーが手でメールツールに貼り付ける

保存 or 表示後、以下を伝える:

> 下書きを保存しました（{保存先}）。送信前に必ずご確認ください。
> プレースホルダ `{}` の箇所は手動で埋めてから送信してください。

### 8. 送信はしない

- メール実送信
- CC/BCC の自動追加
- 宛先アドレスの変更

送信系を求められたら「本機能はドラフト生成・保存のみです」と明示。

## 出力フォーマット

```markdown
## 元メールの読み取り
- 差出人: {名前 / 所属}
- 要旨: {1行}
- 求められているアクション: {1行}
- 期限: {あれば記載 / なければ「明示なし」}

## 返信方針
- スタンス: {承諾 / 辞退 / ...}
- 長さ: {短 / 標準 / 丁寧}
- 言語: {日本語 / 英語}

## ドラフト

### 案1: 短め版
{件名から署名まで、そのままコピペできる完成形}

### 案2: 標準版
（同上）

### 案3: 丁寧版
（同上）

## 要確認プレースホルダ
- {プレースホルダ1}: 何を入れるべきか
- {プレースホルダ2}: 何を入れるべきか

## 次のステップ
- 下書きは {保存先} に保存しました / 表示のみ（コピペしてご利用ください）
- プレースホルダを埋めて、内容を確認してから送信してください
```

## やってはいけないこと

- 元メールに書かれていない事実を創作しない
- 相手のメールアドレス・電話番号を推測で書かない
- 「〜とのことで承知しました」など、実際には承知していない内容を入れない
- 絵文字を勝手に入れない（相手がカジュアルな場合のみ検討、プロファイル準拠）
- 過度な謙譲表現や二重敬語を重ねない
- 長大な前置きを入れない

## トラブル時の対応

- ドラフトが長すぎる: 「短め版だけ出して」と指示されたら案1のみ提示
- 意図が不明確: 先の質問リストを1回だけ返し、回答を待ってから着手
- 怪しいメール（金銭要求・機密情報の要求など）: ドラフトは作らず、ユーザーに注意喚起してから対応方針を相談

## 英語メールの注意点

- `Dear Sir/Madam,` は相手名不明時のみ
- `Please find attached ...` は古い定型。`I've attached ...` で自然に
- 依頼形は `Could you ...?` / `Would you be able to ...?` が汎用
- `Thanks in advance.` は押し付け感が出ることがあるので多用しない
- `Best regards,` は万能。`Kind regards,` はやや丁寧、`Best,` は社内カジュアル

## 定期実行時の挙動

`scheduled-run` モードでこの機能が呼ばれた場合:

1. 設定の `target` に従い対象メールを取得
2. 各メールに対してこの手順を実行
3. 下書き保存
4. 結果レポート（処理件数、エラー件数）

暴走防止:
- `target.max_per_run`（デフォルト20）を超える場合は停止
- 連続3件でエラーが出たら停止
