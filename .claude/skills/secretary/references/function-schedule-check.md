# 機能: スケジュール確認（表示系）

> 前提: 呼び出し元（SKILL.md）の「設定の読み込み」で `./.secretary/config.yaml` を読み込み済み。
> 未読込なら先に読むこと。本ファイル内の `config.xxx` はその値を指す。


秘書の schedule-check モード から呼ばれる詳細手順書。

重要: この機能は 表示系のみ。予定の追加・変更・削除は行わない。提案まで。

## 安心事項（再掲）

- 予定の追加・変更・削除は絶対にしない
- 予定情報は処理時に Claude API に送られるが、学習データには使われない
- 設定・プロファイルはローカル保存のみ

## 提供する表示機能

| 機能 | 使い方の例 |
|------|----------|
| 今日の予定サマリ | 「今日の予定教えて」「今日のスケジュール」 |
| 明日の予定サマリ | 「明日の予定」「明日何ある？」 |
| 次の予定 | 「次の予定は？」「この後の予定」 |
| 空き時間検索 | 「今週の空き時間」「明日の空いている時間」「〇〇時以降の空きは？」 |
| 候補日提示 | 「〇〇さんとの打ち合わせ候補出して」（会議提案のための空き時間提示） |
| 所要時間見積もり | 予定名から準備時間・移動時間を含めた実質所要時間を試算 |
| 準備物の洗い出し | 会議名から想定される持ち物・事前準備をリスト化 |

## 入力として受け取るもの

### ケース1: 自動連携あり（Google Calendar / Outlook / Apple Calendar）

ユーザーが予定を渡す必要なし。API経由で取得。

### ケース2: 手動コピペ

ユーザーに以下のように依頼:

> 予定情報を貼り付けてください。以下のどれでもOKです:
>
> - カレンダーからコピーしたテキスト
> - 「9:00-10:00 〇〇会議、11:00-12:00 打ち合わせ」のような箇条書き
> - iCal ファイル (.ics)
> - スクリーンショットからの読み取り結果

## 手順

### 0. 機能判定

ユーザー発話から、どの表示機能が求められているかを判定:

- 「今日」「今」「本日」 → 今日の予定サマリ
- 「明日」 → 明日の予定サマリ
- 「次」「この後」「今度」 → 次の予定
- 「空き」「空いてる」「暇」 → 空き時間検索
- 「候補」「打ち合わせしたい」 → 候補日提示
- 「準備」「持ち物」「何持っていく」 → 準備物洗い出し

不明な場合は1回だけ確認。

### 1. 予定取得

#### 自動連携の場合

- Google Calendar: MCP or API 経由で、該当期間のイベント一覧取得
- Outlook: Graph API 経由
- Apple Calendar: AppleScript 経由

#### 手動の場合

ユーザーに貼り付けを依頼（上記「ケース2」参照）。

### 2. 予定の正規化

取得した予定を以下の形式に整える:

```yaml
- title: "〇〇会議"
  start: "2026-04-22T10:00+09:00"
  end: "2026-04-22T11:00+09:00"
  location: "会議室A" | "オンライン: Zoom" | null
  attendees: ["田中さん", "山田さん"]
  notes: "事前資料を読んでおく"
```

### 3. 機能別の処理

#### 今日の予定サマリ

```markdown
## 今日の予定（YYYY-MM-DD）

### 時系列
- 10:00-11:00: 〇〇会議（田中さん・会議室A）
- 14:00-15:00: 打ち合わせ（オンライン）
- 17:00-18:00: 1on1（上司）

### 注目ポイント
- ⚠️ 10:00の会議の前に資料確認が必要です
- ⏱️ 14:00と17:00の間に空き時間があります（2時間）
- 📍 オフィス予定1件、オンライン2件

### 今日のペース
朝：会議1本 / 午後：打ち合わせ2本 / 空き時間：合計◯時間
```

#### 次の予定

```markdown
## 次の予定
14:00-15:00 打ち合わせ（オンライン）

- あと 1時間 30分
- 参加者: 山田さん
- 場所: Zoom（リンク: {ある場合は記載、なければ「カレンダー記載を確認」}）
- 事前準備: {notesに記載があれば表示}

お昼を挟む余裕があります（1時間）。
```

#### 空き時間検索

```markdown
## 空き時間（今日・明日）

### 今日
- 09:00-10:00（1時間）
- 11:00-14:00（3時間）★ ランチ可能
- 15:00-17:00（2時間）
- 18:00以降（業務時間外）

### 明日
- 09:00-12:00（3時間）
- 14:00-18:00（4時間）

連続2時間以上の空き: 今日 11:00-14:00 / 明日 09:00-12:00、14:00-18:00

会議を入れたい時間の目安を教えてください（30分？1時間？）。候補をさらに絞ります。
```

#### 候補日提示

```markdown
## 打ち合わせ候補日（30分の会議の場合）

### 今週
- 水曜 10:00-10:30
- 水曜 15:00-15:30
- 木曜 11:00-11:30

### 来週
- 月曜 14:00-14:30
- 火曜 10:00-10:30

一番都合の良さそうな3つを先方にお送りできるよう、文面を整えますか？
（→ 「はい」と言われたら `function-email-reply.md` を呼び出して候補日メールのドラフトを作る）
```

#### 所要時間見積もり

会議名から以下を試算:

- 外部会議（社外の訪問先）: 会議時間 + 移動時間（目安） + 予備10分
- 社内会議: 会議時間 + 予備5分
- オンライン会議: 会議時間 + 接続確認5分
- 1on1: 会議時間そのまま

結果:

```markdown
## 「〇〇社訪問」の所要時間見積もり

- 会議: 60分
- 移動（片道30分×2）: 60分
- 予備: 10分

合計: 130分（2時間10分）

出発時刻の目安: {会議開始時刻} の30分前
```

#### 準備物の洗い出し

```markdown
## 「〇〇会議」で想定される準備

- 会議資料（前回議事録、今回アジェンダ）
- {会議名や相手から推測される準備物}
- 名刺（初回訪問の場合）
- PC充電アダプタ

不足分があれば教えてください。
```

### 4. 提案は行うが実行しない

「候補日をメールで送りたい」「この予定をリスケしたい」と言われた場合:

- メール作成まで: `function-email-reply.md` を呼び出して ドラフト作成まで
- 予定の追加・変更・削除: この機能の範囲外。ユーザーに「カレンダーで手動で操作してください」と伝える

「空き時間に自動で打ち合わせを入れて」と言われた場合:

> 予定の追加・変更はこの機能では行いません。候補時間をお伝えしますので、カレンダーアプリで手動で追加してください。

## 定期実行時の挙動

`scheduled-run` モードで schedule_check 機能が有効な場合:

### 毎朝の予定サマリ（デフォルト）

1. その日の予定を取得
2. 「今日の予定サマリ」を生成
3. config で指定された保存先（ファイル / 通知 / 何らかの形）に出力

出力先オプション:
- `log`: ログファイルに記録（デフォルト）
- `file`: 日付ごとに `daily-YYYY-MM-DD.md` として保存
- `notification`: OS通知（対応環境のみ、設定時）

注意: メール送信や他者への配信は行わない。自分宛の備忘のみ。

## やってはいけないこと

- 予定の追加・変更・削除
- 他者のカレンダーへの書き込み
- 予定情報の外部送信（Claude API 以外）
- 予定リストを手元ファイルに長期保存（ローカルログは日次で整理・古いものは削除）

## トラブル時の対応

- 予定が取得できない → 手動コピペに切り替えを提案
- 予定が多すぎる（1日に50件超など） → ユーザーに確認し、重要度でフィルタリング
- 機密度の高い会議名（社名・人名が含まれる） → プロファイル設定で「詳細表示しない」選択肢を提示
- タイムゾーンの不整合 → config の `timezone` 設定を確認、必要ならユーザーに再確認

## プライバシー配慮

- 予定に含まれる人名・会社名は、長期保存しない（処理時のみ使用）
- 会議名に機密情報が含まれる場合、ログ出力時はマスキングを検討（`include_sensitive_content: false` 時）
- 「このメール相手との会議を自動検出して準備メール送って」のような連鎖処理は、1回ずつユーザー承認を取る
