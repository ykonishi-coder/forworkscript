# 秘書 初回セットアップウィザード

setup モードで SKILL.md から呼ばれる詳細手順書。ユーザータイプに応じて 3つのプラン（お試し / 最低限 / しっかり）に分岐する。

大事な前提: 初心者は「何を答えればいいか分からない」状況になりがち。まずユーザータイプを聞いて質問量そのものを調整 する。

## ウィザード開始時のあいさつ

> これからAI秘書の初期設定を始めます。
>
> 秘書ができること:
> - メール返信の下書き作成
> - スケジュール確認（今日の予定、空き時間、次の予定）
> - 今後: タスク管理、リマインド、その他
>
> 安心事項:
> - お答えいただく内容は あなたのPC内のファイル にだけ保存されます
> - Claude の学習データには使われません
> - 氏名・署名などの個人情報も、秘書作業のために手元で参照するだけです
> - わからない項目は「スキップ」で大丈夫です
> - 後からいつでも設定を変えられます
>
> まず1つだけ、秘書の使い方のイメージを教えてください。

## Q0（最重要）: ユーザータイプ

> Q0. AI秘書をどう使っていきたいですか？
> ざっくりで大丈夫です。あとでいつでも変更できます。
>
> A) まず何ができるか試してみたい / とりあえず動かして様子を見たい
> B) 最低限だけ設定して、すぐ使い始めたい
> C) しっかり設定して、自分に合わせて便利に活用したい
> D) まだよく分からない / 選べない

### 回答による分岐

- A → A プラン: お試しモード
- B → B プラン: 最小セットアップ
- C → C プラン: フルセットアップ
- D → B プランを案内して実行

記録: `config.user_type` に `trial` / `minimal` / `full` を保存。

## A プラン: お試しモード（質問ゼロ・約3分）

### 手順

1. 「サンプルで動作を見せます。ファイルは作りません」と案内
2. どの機能を試すか聞く:

   > どちらを試してみますか？
   > 1) メール返信の下書きを作ってみる
   > 2) 今日の予定サマリを見てみる
   > 3) 両方とも見てみる

3. 選ばれた機能をサンプルデータで動作:
   - メール返信 → サンプルメール3種から選んでもらい、デフォルト文体でドラフト生成
   - スケジュール → サンプル予定リストから、今日のサマリ・空き時間を表示
4. 続ける意思を確認:

   > 続けて使い始めますか？
   > 1) 最低限の設定（Bプラン・3問）
   > 2) しっかり設定（Cプラン・6問）
   > 3) 今回はここで終わる（ファイルは作られません）

安心フォロー: お試しモードでは PCに何も書き込みません。

## B プラン: 最小セットアップ（3問・約5分）

自動連携は聞かず、手動コピペ前提で最小構成で進める。

### BQ1: 主に使うメール・カレンダー環境

> Q. あなたが主に使っているツールを教えてください。
>
> メール:
> 1) Gmail  2) Outlook  3) Apple Mail  4) Thunderbird  5) その他
>
> カレンダー:
> 1) Google Calendar  2) Outlook  3) Apple Calendar  4) 使っていない/その他

自動連携は設定しない（すべて `integration: manual`）。

### BQ2: 署名情報（任意・スキップ可）

> Q. メールの末尾に入れる署名を教えてください。
>
> スキップしても大丈夫です。出したい範囲だけでOK（名前だけ、会社名だけ、等）。
>
> ```
> {氏名}
> {会社名} {部署}
> {連絡先}
> ```
>
> 安心してください: この情報はあなたのPC内のファイルに保存されるだけで、外部に送られることも Claude の学習に使われることもありません。

### BQ3: 定期実行の有無

> Q. 秘書を定期的に動かしますか？
>
> 1) 使いたいときだけ手動で（「メール返信下書いて」等と呼ぶ）
> 2) 1日1回、朝に自動で下書きと予定サマリを用意しておく
> 3) まだ決めない
>
> 迷ったら 1) がおすすめです。慣れてから 2) に切り替えられます。

### 記録するデフォルト値

- `integration.email: manual`
- `integration.calendar: manual`
- `functions.email_reply.enabled: true`
- `functions.schedule_check.enabled: true`
- その他は `templates/config.template.yaml` のデフォルト

### 完了後の案内

> 秘書のセットアップ、完了しました。
>
> 使い方:
> - 「このメール返信して」とメール本文を貼ると、ドラフトが3案出ます
> - 「今日の予定教えて」と予定を貼ると、サマリと空き時間が出ます
> - コピペで渡した情報は、一時的に処理するだけで保存されません
>
> もっと便利にしたくなったら:
> - 「Gmail と連携させて」と言うと、Gmail MCP の最新連携を調査して案内します
> - 「しっかり設定し直して」と言うと、Cプランに切り替えます

## C プラン: フルセットアップ（約15分）

### Q1: 使っているツール（詳細）

メール・カレンダーのそれぞれについて、使用頻度、Webか アプリか、会社用/個人用の使い分けも聞く。

### Q2: ツール連携方式（最新情報を調査して提案）

固定リストで提示しない。その場で WebSearch / WebFetch で最新情報を調査してから提案する。

#### 前置き

> 連携は必須ではありません。「手動コピペ」だけでも十分動きます。
> むしろセキュリティ的には、連携なしが最も安心な選択肢です。

#### 調査

- Gmail 関連: `Gmail MCP Claude {今年}` 等で検索
- Google Calendar 関連: `Google Calendar MCP Claude {今年}` 等で検索
- 公式優先で WebFetch

#### 提示テンプレート

```
## 調査した時点: {YYYY-MM-DD}

### メール連携 選択肢A: {方式名}
- できること / リスク / AIおすすめ度 ★★★★☆

### メール連携 選択肢B: 手動コピペ
- AIおすすめ度 ★★★★★（安心重視の場合）

### カレンダー連携 選択肢A: {方式名}
- できること / リスク / AIおすすめ度 ★★★★☆

### カレンダー連携 選択肢B: 手動コピペ
- AIおすすめ度 ★★★★★（安心重視の場合）
```

迷ったら 手動コピペ を推奨。

### Q3: 返信下書きを作る対象メールの絞り込み

- ラベル/フォルダ
- 送信者
- 新着何時間以内
- 除外したいもの（広告・通知）

### Q4: 定期実行の頻度

- 1日1回（朝） / 1日2回（朝・夕） / 2〜3時間おき / 毎時 / 手動のみ

### Q5: 文体学習

- 過去の送信メールから学習するか
- 自動読み込み（連携あり時）or 貼り付け or スキップ

### Q6: 署名情報（フル）

- 氏名・役職・会社名・連絡先をすべて、または出したい範囲で
- 社外用・社内用で使い分けがあれば

### Q7: スケジュール確認の好み

- 毎朝のサマリを何時に出すか
- 通知に含める内容（時間・相手・場所・準備物・所要時間）
- 空き時間の定義（何分以上を「空き」と見なすか）

### Q8: プライベートと仕事の分離

- 仕事用カレンダーのみ対象 / プライベートも含める
- 仕事用メールのみ対象 / プライベートも含める

## セットアップ完了処理

### 1. 保存先の確認

> 設定ファイルの保存先を選んでください:
>
> 1) `./.secretary/`（プロジェクト直下・推奨）
> 2) 現在のプロジェクト直下 `./.secretary/`
> 3) 任意のパスを指定

### 2. ファイル生成

- `config.yaml` ← `templates/config.template.yaml` から生成
- `style-profile.md` ← `templates/style-profile.template.md` から生成

### 3. .gitignore への追記提案

リポジトリ内に置く場合:

```
.secretary/
```

### 4. 初回テスト提案

> セットアップ完了です。動作確認しますか？
>
> 1) サンプルメールで返信下書きを試す
> 2) 今日の予定サマリを試す（予定を貼り付け）
> 3) 両方試す
> 4) セットアップだけで終える

### 5. 定期実行の登録案内（該当する場合）

`references/schedule-setup.md` の手順に従い、cron または `/schedule` の登録方法を案内。

## プライバシー関連FAQ（ウィザード中で聞かれたら）

Q: 入力した情報は Claude の学習に使われますか？

> いいえ。Anthropic の Claude API はデフォルトで、送信内容をモデル学習に使わない方針です。

Q: 予定情報が外部に漏れないか心配

> 設定ファイル・プロファイルはローカル保存のみ。ドラフト生成時には Claude API に情報が送られますが、学習には使われません。不安な場合は「手動コピペ」方式にしてください。あなたが選んだ情報だけが渡ります。

Q: 会社のPCで使って大丈夫？

> 設定は全部ローカルですが、処理時にはメール本文や予定情報が Claude API に送られます。会社の情報セキュリティポリシーに照らして、IT部門に確認してからご利用ください。

Q: やめたくなったら、どう消せますか？

> 設定フォルダ（例: `./.secretary/`）を削除するだけで、秘書が持っていた情報は完全に消えます。
