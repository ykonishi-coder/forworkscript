# タスク管理ツール連携 調査フレームワーク

Todoist / Linear / Notion / Asana / Jira 等のタスク管理ツールとの連携は、実行時にネット検索で最新方式を確認 してユーザーに提案する設計。固定手順に頼らない。

## 大原則

1. 連携は強制ではない: ローカルファイルのみで全機能が動く
2. 毎回その場で調査: MCP / API の最新状況を確認
3. リスクを隠さない: 書き込み権限の有無、認証情報の扱いを明示
4. 認証情報をスキル設定に保存しない: OS キーチェーン・環境変数管理
5. 書き込み操作はユーザー承認必須: 勝手にタスク追加・削除しない

## 調査プロセス

### Step 1: 環境確認
- 使っているタスク管理ツール
- OS / Claude Code 環境
- 既存の連携設定

### Step 2: WebSearch

```
Todoist Claude MCP {今年}
Linear MCP Anthropic {今年}
Notion MCP latest
Asana API integration Claude
Jira MCP server
task management Anthropic skills
```

### Step 3: 公式優先の WebFetch
- Anthropic 公式: `github.com/anthropics/skills`, `modelcontextprotocol.io`
- 各サービス公式 API ドキュメント
- 信頼できる連携例

### Step 4: リスク評価

| 観点 | 確認事項 |
|------|---------|
| 認証方式 | OAuth / APIトークン / どこに保存 |
| 権限スコープ | 読み取りのみで動くか / 書き込み必須か |
| データ経路 | 取得したタスクデータの流れ |
| 公式性 | Anthropic / サービス / コミュニティ |
| メンテナンス | 直近更新日 |
| 破壊的操作の可能性 | タスク削除・プロジェクト削除 |

### Step 5: AIおすすめ度

- ★5: 公式、読み取りのみで十分動く、安全
- ★4: 公式、書き込みが必要だが承認フロー確実
- ★3: 非公式 or 設定が複雑
- ★2: メンテナンス停止気味
- ★1: 実験的

ローカルファイルのみ運用（連携なし）は常に ★5 として併記

### Step 6: 提案

```markdown
## タスク管理連携（YYYY-MM-DD 調査時点）

### 選択肢A: {ツール} MCP
- 公式性: {Anthropic公式 / サービス公式 / 非公式}
- できること: 読み取り ○ / 書き込み {○ / △ / ×}
- リスク:
  - 認証情報: {保管場所}
  - 書き込み権限: {必要 / 不要}
  - データ経路: {説明}
- セットアップ難易度: {初心者可 / 中級 / 上級}
- AIおすすめ度: ★★★★☆

### 選択肢B: {別ツール} API
- ...

### 選択肢C: 連携なし（ローカルのみ）
- AIおすすめ度: ★★★★★（安心重視）
- できること: 目標管理はすべてローカル Markdown ファイルで完結
- リスク: なし

迷ったら選択肢Cから始めるのが最も安心です。必要になったら後から追加できます。
```

## 書き込み系操作の扱い

### 原則

書き込み系（タスク追加・更新・削除）は、必ず 以下のフロー:

1. 実行前にプレビュー表示
2. ユーザー承認を取る
3. 実行
4. 結果レポート

### 自動書き込みは禁止

- 定期実行（scheduled-run）では書き込みしない
- 目標ファイルの更新に伴う自動反映もしない（承認必須）

### プレビューフォーマット

```markdown
以下の操作を実行します:

### Todoist に追加
- タイトル: "〇〇プロジェクトの進捗レビュー"
- 期限: 2026-04-28
- プロジェクト: "仕事"
- 優先度: 高

実行してよろしいですか？ (yes / no / modify)
```

## 調査情報の鮮度管理

### config.yaml に記録

```yaml
integration_research:
  todoist:
    date: "YYYY-MM-DD"
    summary: "Todoist MCP (公式, ★4) | API (中級, ★3)"
  linear:
    date: "YYYY-MM-DD"
    summary: "..."
```

### 再調査トリガー

- `date` から30日以上
- 連携エラー発生
- ユーザーから新情報（「最近 〇〇 出たらしい」）
- 明示的な「見直して」指示

### 再調査時のユーザー告知

> 前回調査から30日以上経っています。最新の連携方法を調べ直しますか？
> 新しい MCP が出ていれば案内します。

## トラブルシュート

### 連携エラー
1. 認証切れ → 公式再認証フロー
2. レート制限 → 一時停止、再試行タイミング案内
3. 仕様変更 → 最新情報再調査、手動モードへフォールバック

### 権限エラー
- 各ツールの公式認証フローで対応
- スキル設定ファイルに認証情報を書かせない

### 「APIキーを設定ファイルに書いて」と言われたら
- 丁寧に断る
- 代替: 環境変数、OS キーチェーン、ツール公式フロー
- 理由: git コミット事故・バックアップ漏洩のリスク

## 特定ツール参考情報（古い可能性あり、実際の判断は最新調査結果）

### Todoist
- 公式 REST API v2
- MCP サーバーの存在は都度確認
- APIトークン管理: 環境変数 or OSキーチェーン

### Linear
- GraphQL API
- 公式 MCP の登場を都度確認
- 組織管理者承認が必要な場合あり

### Notion
- Notion API
- MCP エコシステムに実装例多数
- データベース構造に合わせた読み書き

### Asana / Jira
- 各公式 API
- 企業環境では管理者承認必須

## まとめ

- 都度ネット調査で最新選択肢を確認（固定手順は使わない）
- 連携なしでも全機能動作（ローカルファイル）
- 書き込みは毎回承認
- 認証情報はスキル外で管理
