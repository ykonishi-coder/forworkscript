# 機能: 振り返り（レビュー）

> 前提: 呼び出し元（SKILL.md）の「設定の読み込み」で `./.goal-tracker/config.yaml` を読み込み済み。
> 未読込なら先に読むこと。本ファイル内の `config.xxx` はその値を指す。


期間の振り返りを構造化してサポートする。

## 入力

1. 対象期間（今週 / 今月 / 今四半期 / カスタム）
2. 対象目標（未指定ならすべて）

## 手順

### 1. 期間の確定

ユーザー発話から判定:
- 「先週の振り返り」 → 前週
- 「今月の振り返り」 → 今月全体 or 月初から今日まで
- 「四半期末レビュー」 → 四半期全体

### 2. 対象目標の読み込み

指定期間にアクティブだった目標ファイルを読み込む:
- `goals/2026-04.md` (月次)
- `goals/2026-Q2.md` (四半期)
- アクティブな GTD プロジェクト

### 3. 構造化質問で振り返りサポート

単なる「振り返りして」では人は書けない。構造化された質問を投げる:

#### 基本4観点（KPT 式）

```markdown
## 今期の振り返り（YYYY-MM-DD）

### Keep（続けたいこと）
うまくいったこと、続けたい習慣・工夫:
1. ...
2. ...

### Problem（やめたい・解決したいこと）
うまくいかなかった、課題として残っていること:
1. ...
2. ...

### Try（次期に試したいこと）
Problem を踏まえて、次期はこう変える:
1. ...
2. ...
```

各項目を1つずつ聞く:

> Keep について 教えてください。
> 今期うまくいったこと・続けたい習慣は3つまでで教えてください。

### 4. 目標ごとの達成判定

各目標について、ユーザーに判定を促す:

```markdown
### 目標: {目標タイトル}

フレームワーク: SMART

設定時の目標:
- S: {当時の記述}
- M: {目標値}
- ...

現状:
- {最新の記録}

達成判定:
- [ ] 達成（全部できた）
- [ ] 部分達成（一部できた）
- [ ] 未達成（できなかった）
- [ ] 中止（途中で方針変更）

判定の理由: {ユーザー記入}
```

### 5. OKRの達成度計算（該当する場合）

```markdown
## OKR 達成度

### Objective: {Objective}

- KR1: 80/100 = 0.80
- KR2: 30/50 = 0.60
- KR3: 8/10 = 0.80

平均達成度: 0.73 (73%)

判定: OKR では 0.6-0.7 が理想的な「ストレッチゴール達成」とされる。
この達成度は...

→ Claude は判定結果を押し付けず、解釈を提示してユーザーに委ねる
```

### 6. 学びの抽出

```markdown
### 今期の学び・気づき

1. {自分について}: 例「朝のうちに難しいタスクをやると捗る」
2. {仕事について}: 例「ステークホルダー調整を早めにすべきだった」
3. {目標設定について}: 例「OKRのKRが多すぎた、3個で十分」

→ これらは次期の目標設定やワークスタイル改善に活かす
```

### 7. 次期への引き継ぎ

```markdown
### 次期への引き継ぎ

継続する目標:
- {目標A}: そのまま継続
- {目標B}: 期限延長して継続

新規立てたい目標:
- {アイデア1}
- {アイデア2}

次期の優先度:
- 最優先: {1つ}
- 注力: {1〜2個}
- バランス: {その他}

次期の目標設定セッション:
- いつ行うか: YYYY-MM-DD
- どう立てるか: SMART / OKR / KPI / 他
```

### 8. ファイル保存

振り返りは別ファイルに保存:

```
{保存先}/reviews/{期間タイプ}/YYYY-MM-DD.md
```

例:
- `reviews/weekly/2026-04-22.md`
- `reviews/monthly/2026-04.md`
- `reviews/quarterly/2026-Q2.md`

### 9. 目標ファイルの更新

振り返り結果を、対応する目標ファイルの末尾に記録:

```markdown
### 振り返り記録

#### YYYY-MM-DD
- 判定: 部分達成
- 達成度: 73%
- 学び: ...
- 次期への引き継ぎ: 継続
```

## フレームワーク別の振り返りコツ

### SMART の振り返り
- Specific: 目標は具体的だったか？
- Measurable: 測定できたか？
- Achievable: 現実的だったか？
- Relevant: 重要だったか？
- Time-bound: 期限設定は適切だったか？

→ 次回の SMART設定の精度向上に繋げる

### OKR の振り返り
- Objective: インスパイアされたか？
- KR: 正しく測定できたか？
- 達成度 0.7 前後が理想、0.3以下や1.0超は要見直し

### KPI の振り返り
- 目標値は妥当だったか？
- アクションと結果の因果関係
- 予測と実績のギャップ

### GTD の振り返り
- ネクストアクションは適切だったか？
- 未完了の Someday/Maybe の見直し
- プロジェクトリストの更新

## 感情への配慮

振り返りは 感情的にしんどい ことがある。

### 達成できなかったとき
- 責めない、原因を事実ベースで整理
- 次に活かせる学びを必ず見つける
- 「できなかった」を「できなかった理由がわかった」に変換

### 達成できたとき
- 十分に祝う
- 運 vs 努力 の切り分け
- 次に同じことを繰り返せるか確認

## 定期実行時（scheduled-run）

- 毎週月曜: 先週の振り返り準備ファイル生成
- 毎月初: 前月の振り返り準備
- 四半期末: 振り返りテンプレ生成

準備ファイルには、読み込むべき目標・記録された進捗を事前に整理しておく。ユーザーが起動したときに即座に振り返りが始められる状態にする。

## やってはいけないこと

- ユーザーを責める表現（「もっと頑張れば」等）
- 強引なポジティブ変換（「失敗は成功の母」的な押し付け）
- 勝手に判定する（達成 / 未達成は本人の判断）
- 過去の振り返りを改変（追記のみ）

## 完了メッセージ

```markdown
## 振り返り完了

期間: YYYY-MM-DD 〜 YYYY-MM-DD
対象目標数: 3
保存先: {パス}

### サマリ
- 達成: 1
- 部分達成: 1
- 未達成: 1

### 主な学び
1. ...
2. ...
3. ...

### 次期へ
- 「来期の目標立てたい」で set-goal モードを起動できます
- 継続目標は引き継ぎ済み

お疲れ様でした。
```
