# 目標管理フレームワーク解説

各フレームワークの基本・使いどころ・書き方のコツ。

## SMART

### 概要
5つの基準を満たす目標の立て方。

- Specific（具体的）
- Measurable（測定可能）
- Achievable（達成可能）
- Relevant（関連性）
- Time-bound（期限あり）

### 使いどころ
- 個人目標
- プロジェクト目標
- 汎用的（どんな目標でもこの形で整理できる）

### 良い例 vs 悪い例

悪い:
> 「英語を勉強する」

良い (SMART):
> S: TOEIC 800点取得
> M: 模擬試験で800点以上
> A: 現650点、月50点上げは現実的
> R: 海外プロジェクトに参加するため
> T: 2026年10月の試験まで

### コツ
- 測定可能にするのが難しい目標もある（「健康になる」等）
  → 「週3回30分ジョギング」のように行動で測れる目標にする
- 達成可能性が高すぎると成長しない、低すぎると挫折する
  → 「やや背伸びするが、3ヶ月で到達できる」レベルが理想

## OKR（Objectives and Key Results）

### 概要
Google が広めた目標管理手法。

- Objective: 定性的・インスピレーショナルな目標
- Key Results: 3〜5個の測定可能な結果

### 使いどころ
- 組織・チーム単位
- 四半期など、中期的な目標
- チャレンジング（ストレッチ）な目標
- 会社の戦略を個人までカスケード

### 良い例

Objective: 業界内で圧倒的な存在感を示す

Key Results:
- KR1: 業界カンファレンスで3回登壇する（現状0回）
- KR2: 業界紙での取り上げを5件達成（現状1件）
- KR3: 月間PVを50万に到達（現状10万）

### コツ

#### Objective のコツ
- 数値を入れない（それは KR の役割）
- 「倍増」「圧倒的」「確立」などインスパイアする語
- 四半期で達成したい方向性

#### KR のコツ
- 3〜5個（多すぎるとフォーカスがブレる）
- 各 KR が独立している（重複しない）
- ストレッチゴール（70%達成で成功、と考える）
- Objective への貢献が論理的に明確

### 達成度の読み方
- 0.7以上: 目標が低すぎた可能性
- 0.6-0.7: 理想的（ストレッチ達成）
- 0.3-0.5: 学びが多い
- 0.3以下: 目標設定に問題あり、見直す

## KPI（Key Performance Indicator）

### 概要
ビジネスの健全性・成功を測る数値指標。

### 使いどころ
- 営業（売上、成約率、商談数）
- マーケ（CVR、CAC、LTV、MAU）
- 運用（稼働率、エラー率、対応時間）
- 製造（不良率、納期遵守率）

### KPI の階層

例: 事業全体 → 部門 → チーム → 個人

```
事業KPI: 年商10億
  ├── 営業部: 新規売上 5億
  │     ├── 東日本チーム: 2億
  │     │     └── 田中: 4000万
  │     └── 西日本チーム: 3億
  └── 既存事業: 5億
```

### コツ
- 計測できる指標を選ぶ（データが取れないなら KPI にしない）
- 先行指標（leading indicator）と結果指標（lagging indicator）を区別
  - 例: 商談数（先行） → 成約数（結果）
- 多すぎる KPI は追いきれない。5個以内が目安

### ありがちな失敗
- 「売上」だけを見る → プロセスが見えない
- 先行指標を持たない → 予測できない
- KPI を増やしすぎる → 何が重要かわからなくなる

## GTD（Getting Things Done）

### 概要
David Allen のタスク整理手法。目標を「プロジェクト」に分解し、各プロジェクトの「ネクストアクション」を明確にする。

### 使いどころ
- 日々のタスク管理
- 複雑なプロジェクトの整理
- やることが多すぎて頭がパンクしそうなとき

### 5ステップ

1. Capture（収集）: すべてのタスク・アイデアを書き出す
2. Clarify（明確化）: 行動可能か？必要なアクションは何か？
3. Organize（整理）: リスト・プロジェクト・Someday/Maybe に分類
4. Reflect（見直し）: 週次でリストをレビュー
5. Engage（実行）: リストから選んで実行

### ネクストアクションの書き方

悪い:
> 「プロジェクトAを進める」

良い:
> 「@電話 田中さんに進捗確認する」

- 動詞＋対象＋文脈（@電話、@PC、@外出）
- 本当に次の1ステップを書く

### コツ
- 「2分でできることは今すぐやる」ルール
- 週次レビューが命（溜まったリストは価値がない）
- Someday/Maybe リストで「いつかやる」を可視化

## シンプル箇条書き

### 概要
フレームワークなし。「やりたいこと」を箇条書きで書くだけ。

### 使いどころ
- SMART/OKR が窮屈に感じる
- まずは書き出したい
- カジュアルな目標

### 例
```
今月やりたいこと:
- 読みたい本を3冊読む
- 友人と2回会う
- 新しいカフェを開拓する
- Blender の基礎を覚える
```

### コツ
- 箇条書きだからといって、達成度を記録しないわけではない
- チェックボックスで達成記録

## フレームワーク選びのガイド

```
個人の生活目標・習慣形成
  → SMART か シンプル箇条書き

個人の仕事の目標・成長
  → SMART

組織・チームの四半期目標
  → OKR

組織の継続的KPI管理
  → KPI

大量のタスクとプロジェクト整理
  → GTD

複数目標の組み合わせ
  → OKR + KPI + GTD のハイブリッド
```

## フレームワークを使わない選択

「フレームワークで書くのがしんどい」と感じたら、書かないことも選択肢。

- 書くこと自体が目的化するのは本末転倒
- 3ヶ月くらいはシンプルに、慣れたらフレームワーク、の段階的採用もOK
- フレームワークはツール。自分に合わなければ別のを試す

## 時間軸での使い分け

| 時間軸 | 推奨 |
|-------|------|
| 1日 | GTD（ネクストアクション） |
| 1週 | GTD + 目標へのリンク |
| 1月 | SMART / 箇条書き |
| 1四半期 | OKR |
| 1年 | OKR（年次Objective + 四半期分解） |
| 3年 | ビジョン + 年次マイルストーン |
