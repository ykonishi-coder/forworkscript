# 機能: 目標設定

> 前提: 呼び出し元（SKILL.md）の「設定の読み込み」で `./.goal-tracker/config.yaml` を読み込み済み。
> 未読込なら先に読むこと。本ファイル内の `config.xxx` はその値を指す。


ユーザーの目標を、選んだフレームワークに沿って構造化して保存する。

## 入力

1. 目標の内容（ざっくりで良い）
2. フレームワーク（config.frameworks.default or ユーザー選択）
3. 期間（〇月 / 〇四半期 / 〇年 等）
4. 分類（仕事 / プライベート / プロジェクト名）

不明なら1往復で聞く。

## 手順

### 1. ヒアリング

ユーザーの「目標」をそのまま受け取るのではなく、5W1H を引き出す:

- Why: なぜこの目標？（背景・動機）
- What: 具体的に何を達成する？
- When: いつまで？
- How: どうやって測る？
- Who: 誰が関わる？

### 2. フレームワーク適用

#### SMART

```markdown
## 目標: {目標タイトル}

フレームワーク: SMART
期間: YYYY-MM-DD 〜 YYYY-MM-DD
分類: {仕事 / プライベート / プロジェクト}

### S (Specific) - 具体的に
{何を達成するか、明確に}

### M (Measurable) - 測定可能に
{成功をどう測るか、数値やチェックリスト}

### A (Achievable) - 達成可能に
{実現可能か、必要リソース}

### R (Relevant) - 関連性
{なぜこの目標が重要か、大きな目的との繋がり}

### T (Time-bound) - 期限
{具体的な期限、マイルストーン}

### マイルストーン
- [ ] YYYY-MM-DD: {中間目標}
- [ ] YYYY-MM-DD: {中間目標}
- [ ] YYYY-MM-DD: {最終達成}

### 記録
- 作成日: YYYY-MM-DD
- 進捗更新日: （未更新）
- ステータス: active  # active / achieved / abandoned / paused
```

#### OKR

```markdown
## Objective: {定性的な目標}

フレームワーク: OKR
期間: YYYY-Q1 （YYYY-MM-DD 〜 YYYY-MM-DD）
分類: {会社 / チーム / 個人}

### Objective
{インスピレーショナルで定性的な目標}

### Key Results（3〜5個）

- KR1: {測定可能な結果} — 現状: 0 / 目標: 100
- KR2: {測定可能な結果} — 現状: 0 / 目標: 50
- KR3: {測定可能な結果} — 現状: 0 / 目標: 10

### 進捗ログ
（週次 or 月次で更新）

### 記録
- 作成日: YYYY-MM-DD
- 最終更新: （未更新）
- 達成度: 0%
- ステータス: active
```

#### KPI

```markdown
## KPI: {指標名}

フレームワーク: KPI
期間: YYYY-MM 〜
分類: {営業 / マーケ / 運用}

### 指標定義
- 名前: {例: 月間売上、CVR}
- 計算方法: {具体的な算出ロジック}
- 単位: {円 / % / 件}

### 目標値
- 月間目標: {数値}
- 週間目標: {数値}
- 日次目標: {数値}

### 過去実績
| 期間 | 実績 | 達成率 |
|------|-----|-------|
| 2026-03 | 95 | 95% |
| 2026-02 | 80 | 80% |

### アクション
- 目標達成のために何をするか

### 記録
- 作成日: YYYY-MM-DD
- 最終更新: YYYY-MM-DD
- ステータス: active
```

#### GTD

```markdown
## 目標: {目標タイトル}

フレームワーク: GTD
期間: YYYY-MM-DD 〜
分類: {プロジェクト名}

### 望ましい結果（Desired Outcome）
{完了したとき、世界がどうなっていれば成功か}

### プロジェクト一覧
1. プロジェクトA: {プロジェクト名}
   - [ ] ネクストアクション: {次にやる具体的な1ステップ}
2. プロジェクトB: {プロジェクト名}
   - [ ] ネクストアクション: ...

### ネクストアクションリスト
- [ ] {@電話} 〇〇さんに確認
- [ ] {@PC} 〇〇の調査
- [ ] {@外出} 〇〇の購入

### Someday/Maybe
- いつかやるかもしれないアイデア

### 記録
- 作成日: YYYY-MM-DD
- 最終見直し: （未実施）
```

#### シンプル箇条書き

```markdown
## {タイトル}

フレームワーク: シンプル
期間: YYYY-MM-DD 〜

### 達成したいこと
- ...
- ...
- ...

### なぜ
- ...

### どうやって
- ...

### 記録
- 作成日: YYYY-MM-DD
- ステータス: active
```

### 3. ファイル保存

保存パス:
```
{config.workspace.base_path}/goals/{期間}.md
```

例:
- 月次目標: `goals/2026-04.md`
- 四半期OKR: `goals/2026-Q2.md`
- プロジェクト目標: `goals/project-xyz.md`

既にファイルがあれば、上書きせずにユーザーに確認。

### 4. 振り返り登録

ユーザーに振り返りのタイミングを確認:

> この目標の振り返りはいつにしますか？
>
> 1) 週次（毎週月曜朝に進捗確認）
> 2) 月次（月末に振り返り）
> 3) 四半期末
> 4) カスタム（日付指定）
> 5) 振り返りなし（必要なときだけ）

config.reminders に記録（通知はしないが、scheduled-run で準備ファイル生成）。

## SMART 目標設定のガイド

### 悪い例
> 「英語を頑張る」

### SMART化
> Specific: TOEIC 800点取得
> Measurable: 模擬試験で800点以上
> Achievable: 現在650点、月50点アップは現実的
> Relevant: 海外プロジェクト参加のため
> Time-bound: 2026年10月の公式試験まで

## OKR設定のガイド

### Objective のコツ
- 数値ではなく定性的に（「売上倍増」より「市場で存在感を示す」）
- インスピレーショナル
- 四半期で達成したいこと

### Key Results のコツ
- 3〜5個
- 測定可能
- Objective への貢献が明確
- ストレッチゴール（70%達成で成功と考える）

## やってはいけないこと

- ユーザーの目標を勝手に書き換える（提案はするが最終判断はユーザー）
- 非現実的な目標を「達成可能」と肯定する（Achievability は指摘する）
- プライベートな目標を仕事目標と混ぜる（分類ルールに従う）
- 既存ファイルを確認なく上書き

## 完了メッセージ

```markdown
## 目標を設定しました

タイトル: {タイトル}
フレームワーク: {SMART / OKR / KPI / etc}
期間: YYYY-MM-DD 〜 YYYY-MM-DD
保存先: {パス}

### 次のステップ
- 進捗記録: 「進捗記録」と依頼すると track モードが起動します
- ダッシュボード: 「目標状況見せて」で全目標を一覧表示
- 振り返り: 期末に「振り返りしよう」で review モード

頑張ってください！
```
