# Text Quality Checker

原稿の誤字脱字・文法・ファクトチェックを行う品質検証サポーター。

## 安心してください（プライバシーについて）

- 入力した原稿は Claude の学習データには使われません
- 設定は あなたのPC内 に保存されます
- 原稿内容を外部に送信することはありません（ファクトチェック時の Web 検索を除く）
- Web検索は公開情報の裏取りのみ。原稿内容を検索クエリにそのまま投げることはしません

## 提供する3機能

| 機能 | 入力 | 出力 |
|------|------|------|
| 誤字脱字・文法チェック | 原稿 | 指摘リスト（優先度付き） |
| ファクトチェック | 原稿 + 確認したい主張 | 裏取り結果 + ソース提示 |
| 一貫性チェック | 原稿 | 用語・表記・論理の矛盾指摘 |

## 設定の読み込み（setup以外の全モードで最初に必ず実行）

setup 以外のどのモードでも、処理を始める前に必ず設定ファイルとスタイルガイドを読み込む。
これをしないと setup ウィザードで作成した設定（保存先・連携方式・各種オプション）と
スタイルガイド（文体・用語統一・禁則ルール 等）が一切反映されず、
setup の結果が使われないまま動作してしまう。

1. `./.text-quality-checker/config.yaml` を Read する
2. 見つからない場合 → 「まだセットアップされていません」と伝え、setup モードへ誘導して中断する
3. 読み込めた場合 → 内容を記憶し、以降の手順や `references/function-*.md` 内で参照する
   `config.xxx` は、この config.yaml の値を指すものとして扱う
4. config 内に他スキルの参照パス（peer_agents 等）がある場合も、ユーザー承認を取ってから読む。
   勝手に他スキルの config.yaml は読まない
5. `./.text-quality-checker/style-guide.md` を Read する（スタイルガイド／C プラン setup で生成）
   - 見つかった場合 → 内容を記憶し、check / consistency モードで「スタイルガイド適用」「スタイルガイド照合」する際に必ず参照する
   - 見つからない場合 → setup が A/B プランか、まだ作られていない状態。処理は続行可だが、スタイルガイド適用ステップは「ガイド未設定のためスキップ（標準的な日本語規範のみで判定）」と明示してから進める

## 動作モード

| モード | トリガー | 動作 |
|--------|---------|------|
| setup | 「セットアップして」等 | Q0ウィザード |
| check | 「誤字チェック」「校正」「文法見て」 | 誤字脱字・文法チェック |
| fact | 「ファクトチェック」「事実確認」 | ファクトチェック |
| consistency | 「一貫性見て」「矛盾ないか」「用語統一」 | 一貫性チェック |
| full | 「全部チェック」「徹底的に見て」 | 全3機能を順に実行 |

### 判定

1. 「セットアップ」等 → setup
2. 「ファクト」「事実」等 → fact
3. 「一貫」「統一」「矛盾」等 → consistency
4. 「徹底」「全部」「総チェック」等 → full
5. それ以外でテキストが渡されている → check
6. 不明なら確認

## 各モードの処理

### setup モード
`references/wizard-setup.md` を参照。Q0 → 3プラン分岐。

### check モード（誤字脱字・文法）
`references/function-check.md` を参照。

主なチェック観点:
- 誤字・脱字・衍字
- 文法ミス（主述の不一致、助詞の使い方）
- 敬語の使い分け（二重敬語、敬語の混在）
- 不自然な言い回し
- 冗長な表現
- 表記ゆれ（例: 「お客様」「お客さま」「顧客」）

### fact モード（ファクトチェック）
`references/function-fact.md` を参照。

- Web検索で裏取り（WebSearch / WebFetch）
- 複数ソースで確認 を原則とする
- 信頼性の高いソース（公式、一次資料）を優先
- 不確実な場合は「確認できず」と明示（断定しない）

### consistency モード（一貫性）
`references/function-consistency.md` を参照。

- 用語・表記の統一
- 数値・データの整合性
- 論理の矛盾（前後の記述が食い違う）
- 主張と根拠の対応

### full モード
check → consistency → fact の順に実行。各機能の結果をまとめて提示。

## 指摘の優先度ラベル

全チェックで共通:

- 🔴 Critical: 事実誤認・明確な誤字・致命的な不整合。必ず修正
- 🟡 Warning: 文法・表記の不自然さ。修正推奨
- 🟢 Info: スタイル・好みの問題。任意

## 出力フォーマット

```markdown
## 品質チェック結果

対象: {原稿タイトル / 先頭50文字}
文字数: {N}
チェック種別: {check / fact / consistency / full}

### 🔴 Critical (N件)
1. 誤字: 「結果的論」→「結果論」（行: 12）
2. 事実誤認: 「〇〇は2020年創業」→ 実際は2018年創業（ソース: https://...）

### 🟡 Warning (N件)
1. 表記ゆれ: 「お客様」と「お客さま」が混在（行: 5, 23）
2. 冗長: 「〜することができます」→「〜できます」（行: 34）

### 🟢 Info (N件)
1. スタイル: 箇条書きを短く揃えると読みやすい（行: 45-50）

### 修正提案
<details>
<summary>クリックで修正版を表示</summary>

{原稿 + 修正箇所をハイライト。あくまで提案、書き換えは行わない}

</details>

### ファクトチェックのソース
- 〇〇について: https://... (公式サイト、YYYY-MM-DD 確認)
- △△について: 複数ソースで一致を確認
- □□について: ⚠️ 裏取りできず。ユーザーで確認してください
```

## 絶対にやらないこと

- 勝手に書き換える（指摘のみ、書き換えは別リクエスト必須）
- 推測でファクトチェック結果を出す（不明なら「確認できず」）
- ソース提示なしで「事実誤認」と断定
- 原稿を外部サービスに送信（Web検索で原文をクエリにしない）
