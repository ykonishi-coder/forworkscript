# 機能: ファクトチェック

> 前提: 呼び出し元（SKILL.md）の「設定の読み込み」で `./.text-quality-checker/config.yaml` を読み込み済み。
> 未読込なら先に読むこと。本ファイル内の `config.xxx` はその値を指す。


原稿内の事実関係を Web 検索で裏取りし、誤認を指摘する。

## 大前提

### 確実性の原則
- 複数ソース で確認できた事実のみ「確認済み」扱い
- 1ソース しかない場合は「要確認」と明示
- 裏取りできなかった 主張は「確認できず」と明示
- 断定調で誤りを指摘しない（「誤りの可能性」として提示）

### プライバシー配慮
- 原稿本文をそのまま検索クエリにしない
- 主張の固有名詞・数値・引用 だけ を抽出してクエリ化
- 機密情報が含まれる場合はユーザーに確認してから検索

## 手順

### 1. 原稿から「事実主張」を抽出

以下の型に当てはまるものをリストアップ:

- 数値: 「売上〇〇億円」「ユーザー数〇〇万人」
- 固有名詞 + 属性: 「〇〇社は△△で設立された」
- 日付・時期: 「2020年に創業」「昨年発表された」
- 引用: 「〇〇氏は『〜〜』と発言した」
- 因果関係: 「〇〇が理由で△△が起きた」
- ランキング・比較: 「業界1位」「最大手」
- 定義的記述: 「〇〇とは△△である」

### 2. チェック対象の絞り込み

設定の `fact_check_depth` に応じて:

- 軽い: 明確な数値・固有名詞のみ
- 標準: 主要な主張・データ
- 深い: すべての事実主張

### 3. Web検索で裏取り

#### 検索クエリの作成

原文をそのまま投げず、事実の核心部分を抽出してクエリ化:

原文: 「XYZ社は2018年に〇〇市で設立され、現在の従業員数は500人です。」

検索クエリ（良い例）:
- `XYZ社 設立年`
- `XYZ社 本社 所在地`
- `XYZ社 従業員数`

検索クエリ（悪い例）:
- 原文全部をそのまま投げる（プライバシー・意図漏洩）

#### 検索対象

WebSearch で:
- 公式サイト（`{会社名} 公式` 等）
- ニュース（信頼できるメディア）
- 公的情報（行政サイト、公開データ）
- 論文・学術資料（学術的主張の場合）

#### 信頼性の評価

- ★★★★★ 公式・一次資料
- ★★★★☆ 大手メディア・専門誌
- ★★★☆☆ 業界誌・信頼できるブログ
- ★★☆☆☆ まとめサイト、個人ブログ
- ★☆☆☆☆ SNS、信頼性不明

★★★☆☆ 以下は補助情報として扱い、断定の根拠にしない。

### 4. 結果の判定

#### 複数ソース一致 → ✅ 確認済み
> 「XYZ社は2018年設立」 → 公式サイト + 帝国データバンク で一致

#### 1ソースのみ → ⚠️ 要確認
> 「〇〇が業界1位」 → 1つの記事で言及あり、他ソースで未確認

#### ソース間で矛盾 → 🔴 不整合あり
> 「XYZ社は2018年設立」 → 公式は2018年、あるメディアは2017年と記載
> → 原文通りが正しい可能性が高いが、両方の根拠を提示してユーザー判断

#### 裏取りできず → ⚠️ 確認できず
> 「〇〇業界で最大」 → 該当する情報が検索で見つからず

#### 原文と明確に矛盾 → 🔴 事実誤認の可能性
> 原文: 「2020年創業」
> 公式: 「2018年創業」
> → 根拠URL を付けて「事実誤認の可能性」として報告

### 5. 出力フォーマット

```markdown
## ファクトチェック結果

対象: {原稿タイトル}
検証した主張: 15件
結果: ✅ 10件 / ⚠️ 3件 / 🔴 2件

### 🔴 事実誤認の可能性（2件）

1. 「XYZ社は2020年に創業」（行12）
   - 公式サイトでは「2018年創業」
   - ソース: https://xyz.com/company (公式、{YYYY-MM-DD} 確認)
   - ソース: https://teikoku-db.com/... (帝国データバンク、一致)
   - 修正案: 「XYZ社は2018年に創業」

2. 「〇〇技術は△△年に発明された」
   - 主要文献では「△△年前後」と幅を持った記述
   - 複数ソースで一致しない
   - 修正案: 「△△年代に開発された」程度に弱める

### ⚠️ 要確認（3件）

1. 「業界売上1位」（行25）
   - 1つの記事で言及あり
   - 最新の業界レポートで未確認
   - 推奨: ソースを追加するか、「一部資料によると」など留保を入れる

### ✅ 確認済み（10件）

（クリックで展開）

<details>
<summary>詳細</summary>

- 主張: 「〇〇の設立は△△年」 → 公式サイト一致
- ...

</details>

### 検索に使ったソース

- 公式サイト: 5件
- 大手メディア: 8件
- 業界誌: 3件
- その他: 2件

注意: 本ファクトチェックは {YYYY-MM-DD} 時点の情報です。事実関係は時間経過で変わる可能性があります。最終的な確認はユーザーでお願いします。
```

## やってはいけないこと

- 推測でファクトチェック結果を出す（「多分正しい」「おそらく」は NG）
- 断定的に誤りを指摘する（常に「可能性」として）
- ソース提示なしで判断
- 機密情報を含む原文全体を検索クエリに使う
- ユーザーの業界に関する意図的な表現を「誤り」と指摘（例: マーケ文脈で「業界最高」は誇張表現として許容されるケース）

## 原文の意図を尊重

一部の表現は事実でなくても許容される:
- 比喩・誇張: マーケティングコピーの常套句
- 意見: 「〇〇が最強」は意見、事実主張ではない
- 文脈的な言い回し: 「〇〇と言われている」は断定ではない

これらを「誤り」として指摘しない。事実として断定されている主張だけを対象にする。

## 時限的な事実の扱い

「現在〇〇である」系の主張は、時期を明示して扱う:

```markdown
主張: 「現在、〇〇は△△市場で最大シェア」
確認日: 2026-04-22
ソース: 業界レポート 2026年版
→ ✅ 2026年時点で確認。時間経過で変わる可能性あり
```

原稿公開時期を考慮し、「当時の情報」なら許容する場合もある。

## 長文の扱い

事実主張が多い長文では:
1. 主張をリストアップ → ユーザーに「全部チェックするか、重要なものだけか」確認
2. 重要なもの優先で実施
3. 後半は要望次第で追加チェック
