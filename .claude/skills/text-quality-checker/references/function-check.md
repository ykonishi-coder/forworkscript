# 機能: 誤字脱字・文法チェック

> 前提: 呼び出し元（SKILL.md）の「設定の読み込み」で `./.text-quality-checker/config.yaml` を読み込み済み。
> 未読込なら先に読むこと。本ファイル内の `config.xxx` はその値を指す。


## 手順

### 1. 原稿の受け取り

- テキスト貼り付け
- Markdown ファイル
- 長文の場合は段落ごとに分割して処理

### 2. チェック観点

#### 誤字・脱字
- 同音異義語の間違い（成果 ⇔ 成績 / 効果 ⇔ 効能）
- タイポ（指の滑り）
- 漢字変換ミス
- 衍字（余計な文字）
- 脱字（抜け落ち）

#### 文法
- 主述の不一致
- 助詞の誤用（「が」「を」「に」「で」の混同）
- 時制の不整合
- 係り受けの混乱

#### 敬語
- 二重敬語（「お伺いさせていただく」等）
- 敬語の混在（ですます調とである調）
- 間違った敬語（「了解いたしました」を目上に使う等）

#### 不自然な表現
- 直訳調
- 冗長表現（「〜することができます」→「〜できます」）
- 意味不明な文

#### 表記ゆれ
- 「お客様」「お客さま」「顧客」
- 「AI」「A.I.」「エーアイ」
- カタカナ表記（「コンピューター」「コンピュータ」）
- 数字（全角 / 半角）
- 単位（「人」「名」「人々」）

### 3. スタイルガイド適用

`style-guide.md` があれば、それに準拠:
- 文体（ですます / である）
- 用語統一
- 禁則ルール

### 4. 指摘の優先度付け

#### 🔴 Critical
- 明確な誤字（辞書にない書き方）
- 致命的な文法エラー
- 意味が通らない文

#### 🟡 Warning
- 不自然な言い回し
- 冗長な表現
- 表記ゆれ
- スタイルガイド違反

#### 🟢 Info
- さらに洗練できる表現
- 読みやすさの提案

### 5. 出力

```markdown
## 誤字脱字・文法チェック結果

文字数: 1,234
指摘件数: 🔴 3件 / 🟡 8件 / 🟢 5件

### 🔴 Critical
1. 誤字（行12）
   - 現状: 「結果的論」
   - 修正案: 「結果論」
   - 理由: 「結果論」が正しい

2. 文法（行28）
   - 現状: 「〇〇を△△がします」
   - 修正案: 「〇〇を△△がする」または「〇〇を△△します」
   - 理由: 主述のねじれ

### 🟡 Warning
1. 二重敬語（行5）
   - 現状: 「お伺いさせていただきます」
   - 修正案: 「伺います」または「お伺いします」
   - 理由: 「お〜する」と「〜させていただく」が重複

2. 表記ゆれ（行15, 23, 47）
   - 「お客様」「お客さま」「顧客」が混在
   - 推奨: どれかに統一（スタイルガイドでは「お客様」）

### 🟢 Info
1. 冗長（行34）
   - 現状: 「〜することができます」
   - 簡潔案: 「〜できます」
```

### 6. 修正版の提示（依頼された場合のみ）

デフォルトは指摘のみ。「修正版も見せて」と言われたら:

```markdown
### 修正版（提案）

<details>
<summary>修正版を表示</summary>

{修正箇所を示した原稿。勝手に置き換えずに、提案として示す}

</details>

注: これはあくまで提案です。最終判断はユーザーでお願いします。
```

## やってはいけないこと

- 勝手に置き換えて書き換え版だけ返す（指摘も必ず出す）
- 意図を読み間違えての指摘（「わざと不自然にしている」可能性）
- 好みの押し付け（ですます vs である は文章スタイル次第）
- 不確実な指摘を断定調で出す

## 迷ったときの対応

- どちらでも正しい表記 → 指摘しないか Info レベルで
- 文脈で判断できない → ユーザーに確認
- 特殊な表現（方言、専門用語、比喩） → 指摘せず、不確実なら「確認してください」と添える

## 長文対応

文字数が多い場合（例: 5000字以上）:
- 段落ごとに分割して処理
- 進捗を報告しながら実行
- 大量の指摘があれば、優先度別にサマリ → 詳細 の構成に

## 言語別対応

- 日本語: デフォルト
- 英語: 英文法・スペル・style（AP / Chicago）チェック
- 混在（日英）: それぞれのルールで
- その他: 対応可能な範囲で（完全ではないことを明示）
