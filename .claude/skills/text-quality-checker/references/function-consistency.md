# 機能: 一貫性チェック

> 前提: 呼び出し元（SKILL.md）の「設定の読み込み」で `./.text-quality-checker/config.yaml` を読み込み済み。
> 未読込なら先に読むこと。本ファイル内の `config.xxx` はその値を指す。


原稿内の用語・表記・論理の矛盾を検出する。

## チェック観点

### 1. 用語・表記の統一

#### 表記ゆれ
- 「お客様」と「お客さま」と「顧客」の混在
- 「AI」と「A.I.」と「エーアイ」
- 「ウェブ」と「Web」と「WEB」
- カタカナの長音（「コンピュータ」「コンピューター」）
- 漢字/ひらがな（「頂く」「いただく」）

#### 略称と正式名称の混在
- 「株式会社〇〇」と「〇〇社」と「〇〇」（省略）
- 「日本経済新聞」と「日経」と「日経新聞」

→ 初出でフルネーム、以降は略称など、一貫したルールを推奨

#### 数値の表記
- 全角 / 半角（1, １）
- 3桁区切り（1,000 / 1000）
- 単位の付け方（10万人 / 10万名 / 100,000人）

### 2. 文体の統一

- ですます調 / である調の混在
- 敬語レベルのばらつき
- 体言止めの多用 / 少用

### 3. 数値・データの整合性

- 冒頭で「100人を対象に調査」→ 後半で「N=80」と矛盾
- 「先月は10%増」「先月は20%伸びた」のように同じ事象で数値が違う
- 合計値が足し合わせと合わない

### 4. 論理の矛盾

- 主張 A と主張 B が両立しない
- 結論と根拠の不整合
- 時系列の矛盾（2020年に開始 → 2019年に完成）
- 因果関係のねじれ

### 5. 主張と根拠の対応

- 強い主張（「必ず」「100%」）に弱い根拠
- 具体的な結論に抽象的な根拠
- 「〜のため」「〜だから」でつなげたが因果関係が弱い

### 6. 定義と使用の整合

- 冒頭で定義した用語 vs 本文での使い方が食い違う
- 略語を定義せずに使う

## 手順

### 1. 原稿全体をスキャン

長文の場合、段落ごとに分けつつ、全体を通した辞書を作る:

- 頻出用語リスト
- 表記ゆれの候補リスト
- 数値・データのリスト
- 主張リスト

### 2. 各観点でチェック

#### 表記ゆれ検出
- 同じ意味の異なる表記を見つける
- 出現位置を全件リスト化
- どれが頻度最多か判定

#### 数値整合チェック
- 同じ指標が複数箇所に出たら突合
- 合計・内訳の算数チェック

#### 論理整合チェック
- 主張同士を対比
- 前後の記述を比較

### 3. スタイルガイド照合

`style-guide.md` があれば:
- 指定の表記になっているか
- 禁則事項に違反していないか

### 4. 指摘の出力

```markdown
## 一貫性チェック結果

### 🔴 Critical: 数値の矛盾（1件）
対象: ユーザー数
- 行5: 「ユーザー数は10万人」
- 行34: 「ユーザー数は8万人」
- 対応: どちらが正しいか確認が必要

### 🟡 Warning: 表記ゆれ（3件）
対象: 「お客様」の表記
- 「お客様」: 行5, 18, 45 (3回)
- 「お客さま」: 行12 (1回)
- 「顧客」: 行23, 67 (2回)
- 推奨: 「お客様」に統一（頻度最多）

対象: 文体の混在
- ですます調: 大半
- である調: 行38-42 (段落)
- 推奨: ですます調に統一、または章ごとに統一ルール

### 🟡 Warning: 略称・正式名称（2件）
対象: 企業名
- 「株式会社XYZ」: 行1（初出）
- 「XYZ」: 行10, 15, 20, 30
- 「XYZ社」: 行25
- 推奨: 初出はフルネーム、以降は「XYZ社」に統一など

### 🟢 Info: 論理の整理提案（1件）
対象: 根拠の明示
- 行45: 「〇〇が最重要」という主張
- 根拠として挙げられている事実が弱い
- 提案: もう一歩具体的な根拠を添えると説得力が増す
```

## やってはいけないこと

- ユーザーが意図的に使い分けている表記を「ゆれ」と誤判定（文脈を読む）
- 文体の意図的変化を矛盾扱い（引用部分は元の文体、本文は別、など）
- 自動的な書き換えを勝手に実行
- 好みの押し付け（どちらも正しい表記を「統一しろ」と強く言わない）

## 例外ケース

### 意図的な使い分け
- 「お客様」: 社外向け
- 「顧客」: 分析文脈
- 混在でも、文脈を読み取れれば許容

### 引用
- 引用部分は元の表記を尊重
- 本文の表記ゆれとは別扱い

### 専門用語
- 業界の標準に合わせる（技術文書で「ユーザ」か「ユーザー」かは分野の慣例）

## 一貫性チェック後の推奨アクション

```markdown
### 一括置換の提案

以下の置換を行いますか？（勝手には実行しません）

1. 「お客さま」→「お客様」（1箇所）
2. 「XYZ」→「XYZ社」（一部、初出は「株式会社XYZ」として保持）

実行を依頼される場合は、具体的な指示（「1だけ実行して」等）をお願いします。
```

実行も ユーザー指示に応じて のみ。勝手に書き換えない。
