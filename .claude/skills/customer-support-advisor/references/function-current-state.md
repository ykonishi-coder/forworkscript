# 機能: 現状ヒアリング

> 前提: 呼び出し元（SKILL.md）の「設定の読み込み」で `./.customer-support-advisor/config.yaml` を読み込み済み。
> 未読込なら先に読むこと。本ファイル内の `config.xxx` はその値を指す。


CS の現状を丁寧に聞き出す。

## ヒアリング項目

### 1. ビジネス概要
- 事業形態（BtoB / BtoC / EC / SaaS 等）
- 業種
- 主要商品・サービス
- 顧客規模

### 2. チャネル
- 現在の問い合わせチャネル（メール / 電話 / チャット / LINE / SNS / フォーム / 対面）
- チャネル別の問い合わせ比率
- 各チャネルの対応時間

### 3. ツール
- 使っている CS ツール（あれば）
- CRM
- ヘルプページ / FAQ
- ナレッジベース
- チャットボット

### 4. チーム
- CS 担当者数（専任 / 兼任）
- スキル・経験
- シフト・営業時間

### 5. 規模
- 月間問い合わせ数
- チャネル別の内訳
- ピーク時間・時期

### 6. 問い合わせ内容
- カテゴリ別の比率
- よくある質問 Top 10
- 難問の頻度

### 7. 現状 KPI（あれば）
- 平均レスポンス時間
- 解決時間
- 満足度（CSAT / NPS）
- 解決率
- エスカレ率

### 8. 課題
- 最大の課題
- ボトルネック
- 優先度

### 9. 目標
- 短期（1-3ヶ月）
- 中期（3-12ヶ月）
- 理想状態

### 10. 予算・リソース
- 月額予算
- 導入初期予算
- 学習リソース（時間）

## ヒアリングのコツ

### 構造化質問
チェックボックス・選択肢で答えやすく。

### 数値化
「多い・少ない」ではなく具体的な数字を。

### 深掘り
- 「その課題はいつから？」
- 「試した対策は？」
- 「なぜ効果が出なかった？」

### 現場との乖離
- トップの認識 vs 現場の実態

## 現状レポートの活用

- 改善策の提案の根拠
- ツール選定時の要件定義
- KPI 改善の基準値
- 進捗測定の出発点
