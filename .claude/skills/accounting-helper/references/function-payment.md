# 機能: 入金・支払管理

> 前提: 呼び出し元（SKILL.md）の「設定の読み込み」で `./.accounting-helper/config.yaml` を読み込み済み。
> 未読込なら先に読むこと。本ファイル内の `config.xxx` はその値を指す。


売掛金（入金予定）と買掛金・未払金（支払予定）を管理する。

## 管理対象

### 売掛金（入金予定）
- 請求書発行後、入金待ち
- 回収予定日・金額
- 回収状況

### 買掛金・未払金（支払予定）
- 受け取った請求書
- 支払予定日・金額
- 支払状況

## 手順

### 1. インデックス管理

```
{保存先}/payments/
├── receivables.md    # 売掛金一覧
└── payables.md       # 買掛金・未払金一覧
```

各ファイルは Markdown のテーブル形式:

```markdown
# 売掛金一覧

| ID | 請求先 | 請求額 | 請求日 | 入金予定 | 状況 |
|----|-------|-------|--------|---------|------|
| R001 | {顧客A} | 110,000 | 2026-04-01 | 2026-04-30 | 🟡 待機 |
| R002 | {顧客B} | 55,000 | 2026-04-15 | 2026-05-15 | 🟢 正常 |
| R003 | {顧客C} | 88,000 | 2026-03-01 | 2026-03-31 | 🔴 滞留 |
```

### 2. アラート

scheduled-run で定期チェック:

- 入金予定日が過ぎたのに未入金 → 🔴 滞留
- 支払予定日が近い → 🟡 要対応
- 支払予定日を過ぎた → 🔴 遅延

アラートファイル生成:
```
{保存先}/alerts/payment-YYYY-MM-DD.md
```

通知は送らない。ユーザーが次回起動時に確認。

### 3. 入金消込

ユーザーから入金があった報告:

```markdown
入金確認しました:
- 日付: 2026-04-30
- 入金元: {顧客A}
- 金額: 110,000円

### 消し込み処理

売掛金 R001 を入金済みにします:
- 請求額: 110,000円
- 入金額: 110,000円（完全一致）
- 差額: 0円

### 会計ソフトへの仕訳

| 借方 | 金額 | 貸方 | 金額 |
|------|-----|------|-----|
| 普通預金 | 110,000 | 売掛金 | 110,000 |

進めてよろしいですか？
```

承認後、売掛金インデックスを更新、仕訳ドラフト生成。

### 4. 差額発生時の処理

入金額が請求額と異なる場合:

```markdown
⚠️ 差額発生

請求額: 110,000円
入金額: 109,780円
差額: -220円

### 考えられる原因
1. 振込手数料が先方負担のはずが自社負担になっている
2. 一部誤入金
3. 相殺

### 処理候補
A) 差額を「支払手数料」として処理（振込手数料として）
B) 残額を再請求（先方確認）
C) その他

どの処理にしますか？
```

### 5. 支払管理

買掛金・未払金も同様:

```markdown
## 支払予定（今月）

| ID | 支払先 | 金額 | 支払予定 | 状況 |
|----|-------|-----|---------|------|
| P001 | {仕入先A} | 330,000 | 2026-04-30 | 🟡 要振込 |
| P002 | {外注B} | 88,000 | 2026-05-15 | 🟢 予定通り |

### 🟡 今週中に振込必要
- P001: {仕入先A} 330,000円（4/30）
  - 振込手続きしてください
```

### 6. 支払処理

振込完了報告を受けて、支払済みに:

```markdown
振込完了の記録:
- 日付: 2026-04-28
- 支払先: {仕入先A}
- 金額: 330,000円
- 振込手数料: 550円（自社負担）

### 仕訳

| 借方 | 金額 | 貸方 | 金額 |
|------|-----|------|-----|
| 買掛金 | 330,000 | 普通預金 | 330,550 |
| 支払手数料 | 550 | | |
```

## 入金サイクルの分析

定期的に集計:

```markdown
## 売掛金の年齢分析（YYYY-MM-DD 時点）

| 期間 | 件数 | 金額 |
|------|-----|-----|
| 当月分 | 10件 | 800,000 |
| 1ヶ月超 | 3件 | 250,000 |
| 2ヶ月超 | 1件 | 88,000 ⚠️ |
| 3ヶ月超 | 0件 | 0 |

### 🔴 要対応: 2ヶ月超の滞留
- R003: {顧客C} 88,000円
  - 催促の検討を（メール作成なら secretary と連携）
```

## 他エージェント連携

- secretary: 催促メール作成
- spreadsheet-operator: 売掛・買掛を Excel で管理している場合
- report-writer: 月次レポートに入金状況を含める

## やってはいけないこと

- ユーザー承認なしで会計ソフトに入金・支払登録
- 催促メールの自動送信（ドラフト作成まで）
- 消し込みの自動判断（完全一致でも承認を取る）
