# レポートタイプ別ガイド

各レポートタイプごとの特徴・書き方・雛形。

## 共通原則

- 結論ファースト
- 1章1メッセージ
- 根拠と出典の明記
- 対象読者を意識した密度

## 1. 週次／日次業務報告

対象読者: 上司・チームメンバー
分量: A4 1枚、読了3分
更新頻度: 週1回 or 日次
雛形: `templates/weekly-report.template.md`

### 構成
1. サマリ（今期の結論1文）
2. 完了タスク
3. 進行中タスク
4. 課題・相談事項
5. 次期計画

### 注意点
- 時系列よりカテゴリー順
- 数値化できるものは数値で（進捗率%、件数、時間）
- 「課題・相談事項」は議論のきっかけを作る
- 読み手が5秒で要点を掴めるサマリ

### よくある失敗
- 「頑張った」系の主観表現を書いてしまう
- 完了と進行中の区別が曖昧
- 次週計画を書かず「やることたくさん」で終える

## 2. 提案書・企画書

対象読者: 決裁者・客先
分量: A4 3〜10枚、読了10〜20分
目的: 意思決定を促す
雛形: `templates/proposal.template.md`

### 構成
1. エグゼクティブサマリ
2. 背景・課題
3. 提案内容
4. 期待効果
5. 実行計画
6. リスクと対策
7. 費用
8. 付録

### 注意点
- 読者の「なぜ？」を先回り する
- 費用対効果を定量化
- リスクを隠さない（対策とセットで）
- 実行計画は具体的に（いつ、誰が、何を）

### 強い提案書の条件
- 1ページ目で決裁者が「やる」を判断できる情報が揃う
- 数字の根拠が出典付きで示される
- 代替案と比較されている
- 失敗時のリカバリが示されている

## 3. 調査レポート

対象読者: 依頼者・関係部門
分量: A4 5〜20枚
目的: 意思決定の材料提供
雛形: `templates/research-report.template.md`

### 構成
1. 調査目的・方法
2. 主要発見（エグゼクティブサマリ）
3. 背景
4. 調査結果の詳細
5. 分析・考察
6. 結論・提言
7. 付録（データ・引用）

### 注意点
- ファクトチェック必須
- 1次情報（公式・論文）を優先
- 2次情報（記事・ブログ）は補足扱い
- 複数ソースで確認
- 意見と事実を区別

### 強い調査レポートの条件
- 調査範囲と限界が明記されている
- 反対意見・代替解釈も提示
- 時期を明示（〇年〇月時点）
- 次に調べるべきテーマが示される

## 4. KPIレポート

対象読者: マネジメント・経営層
分量: A4 2〜5枚
目的: 数字で現状を伝え、次のアクションを引き出す
更新頻度: 月次 / 四半期

### 構成
1. ハイライト（今期の要点）
2. 主要KPIの達成状況
3. 前期比較・トレンド
4. 要因分析（良かった点・悪かった点）
5. 次期の見通し・アクション

### 注意点
- グラフ・表で視覚化
- 達成/未達の原因分析
- 言い訳より打ち手
- 予測は幅を持たせる

### 強いKPIレポートの条件
- 1ページ目でKPI全体が一覧できる
- 良かった/悪かった が色分けされている
- 次期の具体的なアクションが書かれる
- 前期と同じ失敗を繰り返していない

## 5. インシデント／障害報告書

対象読者: 上司・関係部門・場合により客先
分量: A4 2〜5枚
目的: 原因究明・再発防止・信頼回復

### 構成
1. 概要
2. 発生状況（時系列）
3. 影響範囲
4. 原因
5. 対応内容
6. 再発防止策
7. 学び（ポストモーテム）

### 注意点
- 事実ベース、責任追及より原因分析
- 時刻は分単位で記載
- 影響を具体的に（ユーザー数、金額、時間）
- 再発防止策は具体的（誰が、何を、いつまでに）

### 強いインシデント報告の条件
- ブレームレス（個人を責めない）文化を踏襲
- 原因を「直接原因」「根本原因」に分けて分析
- 再発防止策が実行可能
- 学びを組織知として残す

## 6. プロジェクト進捗レポート

対象読者: PM・ステークホルダー
分量: A4 2〜4枚
更新頻度: 週次 or 隔週

### 構成
1. 全体進捗サマリ
2. マイルストーン達成状況
3. 完了した主要タスク
4. リスク・ブロッカー
5. 次期の計画
6. 支援・意思決定のお願い

### 注意点
- 進捗率は主観を避け、成果物ベースで
- リスクは早めに開示
- 意思決定を要する事項は最前面に

### 強い進捗レポートの条件
- RAG（Red/Amber/Green）で状態表示
- 遅延は理由と回復計画を添える
- ステークホルダーが次のアクションを判断できる

## 7. 経営層向けサマリ

対象読者: 経営層
分量: A4 1枚
目的: 短時間で意思決定を促す

### 構成
1. 結論（1文）
2. 3つの要点
3. 提言・意思決定依頼

### 注意点
- 超凝縮: 詳細は付録 or 別ファイル
- 数字で示せるものは数字
- 1枚に収めるのが規律
- 読了1〜2分で終わるように

### 強い経営サマリの条件
- タイトルを見るだけで結論が分かる
- 忙しい人が5秒で判断できる
- 疑問が出たら詳細を掘れる構造

## 8. カスタム

上記以外のレポート。既存の雛形に近いものを流用し、ユーザーの指定に合わせて章立てを調整。

## タイプ判定

ユーザーから依頼が来たとき、director がタイプを推定:

- 「週次」「日次」「定例」「進捗」 → 週次報告 or プロジェクト進捗
- 「提案」「企画」「稟議」 → 提案書
- 「調査」「リサーチ」「分析」 → 調査レポート
- 「KPI」「業績」「数字」 → KPIレポート
- 「障害」「事故」「ポストモーテム」 → インシデント報告
- 「経営層」「役員」「CEO」「サマリ」 → 経営層向けサマリ

複数タイプに該当する場合、ユーザーに確認。
