# 工程間引き継ぎフォーマット

director ⇄ 各担当、各担当同士の引き継ぎ標準形式。

## director から各担当への依頼ブリーフ

```markdown
# 依頼ブリーフ

## 宛先
report-{ROLE}

## 案件
{案件名}

## 担当工程
{工程名（素材収集 / 構成設計 / 執筆 / 品質検証）}

## 前工程までの成果物
- work/report-writer/{案件}/01-director-brief.md
（前工程があればそれも列挙）

## 作業内容
- {具体的な指示}

## 期待アウトプット
- 形式: Markdown
- 粒度: {詳細 / 要点のみ}
- 分量: {目安}

## 制約
- {禁止事項 / 注意点}

## 納期
{目安時刻、または「可能な限り速く」}
```

## 各担当から director への完了報告

```markdown
# 完了報告: report-{ROLE}

## 案件
{案件名}

## 成果物
- パス: work/report-writer/{案件}/0X-{ROLE}.md

## 要点
1. {重要ポイント1}
2. {重要ポイント2}
3. {重要ポイント3}

## 判断ポイント（director / ユーザー判断が必要）
- {判断が分かれる箇所とその理由}

## 懸念事項
- {あれば。なければ「特になし」}

## 次工程への申し送り
- {後工程の人が迷わないよう、意図や文脈を補足}
```

## 各担当が成果物末尾に書く「申し送り」

原則、director を介して次工程に伝えるが、成果物ファイルの末尾に以下を書いておくと次担当がスムーズ:

```markdown
---
## 次工程への申し送り

### 意図・文脈
- {なぜこう判断したか}
- {考慮した制約}

### 使ってほしい素材
- {特に重要な部分}

### 避けてほしいこと
- {この方向には行かないでほしい、などがあれば}
```

## DA（advocate）レビュー依頼

```markdown
# レビュー依頼

## 宛先
report-advocate

## 案件
{案件名}

## レビュー対象
- メイン: work/report-writer/{案件}/04-writer.md
- 参考: 他ファイル（前工程の文脈）

## 重点的にチェックしてほしい観点
- {観点1: 例: 事実確認、読者視点}
- {観点2}

## 厳しさレベル
{standard / strict / lenient}

## 納期
{目安}
```

## DA レビュー結果

`agents/report-advocate.md` の出力フォーマットに準拠。

## 修正依頼（advocate → writer など）

director 経由で再依頼:

```markdown
# 修正依頼

## 宛先
report-writer

## 案件
{案件名}

## 元成果物
work/report-writer/{案件}/04-writer.md

## 修正箇所（advocate 指摘より）
### 🔴 Critical
1. {指摘内容} → {修正指示}

### 🟡 Warning
1. {指摘内容} → {修正指示}

## 修正方針
- Critical を全て反映
- Warning も基本反映（判断難しい箇所は別途相談）

## 納期
{目安}
```

修正後の成果物は `04-writer-v2.md` のようにバージョニング、または上書きしてバックアップを残す（`04-writer.bak`）。
