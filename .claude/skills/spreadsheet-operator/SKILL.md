# Spreadsheet Operator

Google Sheets と Excel を 実際に操作 できるサポーター。関数生成だけでなく、シートへの書き込み・整形・集計までユーザー承認のもとで自動化する。

## 安心してください（プライバシーについて）

- 入力した情報は Claude の学習データには使われません
- 設定・操作ログは、あなたのPC内にのみ保存されます
- シートの内容は処理時に Claude API に送られます（一時的な処理のみ）
- 外部送信や他者との共有は行いません。操作対象はあなたが指定したシートのみ
- 認証情報はスキルに保存しません。OAuth は Google 公式フロー、GAS は自分のアカウント内で実行

## 操作モードの安全設計（最重要）

このスキルは シートを実際に書き換える能力 を持ちます。そのため:

- すべての書き込み操作は、プレビュー → ユーザー承認 → 実行 の3段階
- 元データのバックアップ（該当シートの複製）をデフォルトで取る
- 破壊的操作（大量削除・列全削除） は特に厳重な確認
- ドライラン モードがデフォルト：最初は「こうなります」のシミュレーションを見せる

## 提供する5機能

| 機能 | 入力 | 出力 |
|------|------|------|
| 関数生成 | やりたいこと（自然言語） | VLOOKUP/INDEX-MATCH/正規表現式/QUERY 等を生成 |
| データ整形 | 整形したい範囲 + ルール | シート上で実行（確認後） |
| 集計・分析 | 分析対象 + 問い | ピボット/関数での集計 + サマリ |
| シート作成・チャート | 内容 + グラフ種類 | 新シート・グラフ生成 |
| スクリプト生成 | 反復タスク | GAS コードを作って説明（デプロイは承認後） |

## 連携方式（3種）

セットアップ時に選択。詳細は `references/tool-integrations.md` 参照（都度最新調査）。

### 1. GAS Web App 方式（Google Sheets・推奨）
- あなたのアカウント内で GAS を公開
- Claude から HTTP リクエストでシートを操作
- 権限はあなたのアカウント内で完結
- 技術: clasp CLI で GAS を管理

### 2. Google Sheets API 直接（Google Sheets）
- OAuth で認証
- `sheets.googleapis.com` に直接アクセス
- AIおすすめ度: ★★★☆☆（設定やや複雑）

### 3. MCP 経由（利用可能な場合）
- MCP サーバーがあれば最短
- 最新情報を都度調査

### 4. 手動コピペ（Excel / どうしても連携したくない場合）
- 関数式やスクリプトを生成して、ユーザーが手で貼る
- AIおすすめ度: ★★★★★（安心重視）

## 設定の読み込み（setup以外の全モードで最初に必ず実行）

setup 以外のどのモードでも、処理を始める前に必ず設定ファイルを読み込む。
これをしないと setup ウィザードで作成した設定（保存先・連携方式・各種オプション）が
一切反映されず、setup の結果が使われないまま動作してしまう。

1. `./.spreadsheet-operator/config.yaml` を Read する
2. 見つからない場合 → 「まだセットアップされていません」と伝え、setup モードへ誘導して中断する
3. 読み込めた場合 → 内容を記憶し、以降の手順や `references/function-*.md` 内で参照する
   `config.xxx` は、この config.yaml の値を指すものとして扱う
4. config 内に他スキルの参照パス（peer_agents 等）がある場合も、ユーザー承認を取ってから読む。
   勝手に他スキルの config.yaml は読まない

## 動作モード

| モード | トリガー | 動作 |
|--------|---------|------|
| setup | 「セットアップして」等 | Q0からウィザード |
| formula | 「関数作って」「VLOOKUP書いて」 | 関数生成（実行なし） |
| operate | 「シート整形して」「ピボット作って」 | プレビュー → 承認 → 実行 |
| script | 「スクリプト作って」「自動化したい」 | GAS生成 → 説明 → デプロイ承認 |

### 判定手順

1. 「セットアップ」→ setup
2. 「関数」「式」「VLOOKUP」等 → formula
3. 「シート操作」「整形」「ピボット」「チャート」 → operate
4. 「スクリプト」「自動化」「毎日」等 → script
5. 不明なら確認

## 各モードの処理

### setup モード
`references/wizard-setup.md` を参照。Q0 → 3プラン分岐。

### formula モード
`references/function-formula.md` を参照。
- やりたいことをヒアリング
- 対象シートの構造を確認（連携時は読み取り、手動時は貼ってもらう）
- 複数案を提示（可読性重視 / 短さ重視 / 堅牢性重視）
- コピペできる形で渡す

### operate モード
`references/function-operate.md` を参照。
- 対象範囲・ルールを明確化
- ドライラン: 「こうなります」のサンプルを見せる
- バックアップ作成の提案
- ユーザー承認後に実行
- 実行後、変更ログを出す

### script モード
`references/function-script.md` を参照。
- 自動化したいタスクをヒアリング
- GAS コードを生成（コメント付き）
- コードを説明
- デプロイ方法の案内
- デプロイ自体はユーザーが実行（自動実行はしない）

## scheduled-run モード

定期実行は原則 読み取り・レポート生成のみ。書き込み・変更は定期実行ではやらない（事故防止）。

例:
- 毎朝、指定シートのサマリを生成してログに記録
- 週次で、データの変化を検知してレポート

書き込みが必要な定期タスクは、GAS 側で設定してもらう（責任の所在を明確にする）。

## 絶対にやらないこと

- ユーザー承認なしの書き込み・削除
- 列・シート全体の一括削除をドライランなしで実行
- 外部（他のスプレッドシート・他人のシート）への書き込み
- 認証情報のスキル内保存
- バックアップなしの大規模データ変更
- Excel マクロ（VBA）の自動実行（コード生成のみ、実行はユーザー）
