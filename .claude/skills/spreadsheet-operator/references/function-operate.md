# 機能: シート操作（書き込み・整形・集計）

> 前提: 呼び出し元（SKILL.md）の「設定の読み込み」で `./.spreadsheet-operator/config.yaml` を読み込み済み。
> 未読込なら先に読むこと。本ファイル内の `config.xxx` はその値を指す。


このモードは実際にシートを書き換える。そのため、安全装置を厳格に適用する。

## 安全原則（最重要）

1. プレビュー → 承認 → 実行 の3段階を必ず踏む
2. バックアップ をデフォルトで取る（対象シートの複製）
3. ドライラン で「こうなります」を先に見せる
4. 破壊的操作（100行超の削除、列全削除、シート削除）は特に厳重な確認
5. ロールバック手順 を毎回提示

## 典型的な操作

| 操作 | 例 |
|------|---|
| データ整形 | 日付フォーマット統一、全角半角統一、空白除去 |
| 重複削除 | 特定列の重複行を削除 |
| 並び替え | 複数列での複合ソート |
| フィルタ処理 | 条件一致行の抽出・別シートへコピー |
| ピボット | カテゴリ別集計 |
| チャート追加 | 棒グラフ・円グラフ・折れ線 |
| 新シート作成 | テンプレートから複製 |
| 値貼り付け | 関数結果の固定化 |

## 手順

### Step 1: 操作の明確化

ユーザーから以下を確認:

- 対象スプレッドシート: URL or ファイル名
- 対象範囲: シート名、セル範囲
- やりたいこと: 具体的に
- 制約: 「この列は触らない」「元データは消さない」等

不明点は1往復でまとめて聞く。

### Step 2: シート構造の読み取り

連携方式によって:

- GAS Web App: API 経由でシート構造を取得
- Sheets API 直接: 同様
- MCP: MCPツールで取得
- 手動: ユーザーにシート構造を教えてもらう

読み取った構造を提示して確認:

```markdown
## 認識したシート構造

シート名: 売上データ
範囲: A1:E100
ヘッダ: A=日付, B=顧客名, C=商品, D=数量, E=金額
データ件数: 99行

これで合っていますか？
```

### Step 3: ドライラン（操作プレビュー）

実行前に「こうなります」のシミュレーションを見せる。

```markdown
## ドライラン結果

操作: 日付フォーマットの統一（YYYY/MM/DD → YYYY-MM-DD）
影響範囲: A2:A100（99セル）
変更例:
- 2026/04/22 → 2026-04-22
- 2026/4/1 → 2026-04-01（ゼロ埋めも追加）

変更されないもの:
- ヘッダ行（A1）
- 空白セル
- B列以降

予想処理時間: 約2秒
バックアップ: 「売上データ_backup_20260422_163000」シートとして複製

実行してよろしいですか？ (yes / no / 修正したい)
```

### Step 4: ユーザー承認

明示的な「yes」「実行して」等の確認を待つ。曖昧な返事は再確認する。

破壊的操作（削除系）は追加確認:

```markdown
⚠️ これは100行を削除する破壊的操作です。
バックアップは作成しましたが、念のため以下も確認してください:

- 間違って削除しそうな行はありませんか？
- 元のスプレッドシート全体のバックアップを別途取っていますか？

進めますか？ (yes, proceed / no / show-again)
```

### Step 5: 実行

- GAS Web App 経由なら HTTP POST で操作コマンドを送信
- Sheets API 経由なら API コール
- MCP 経由なら MCP ツール使用
- 手動なら実行スクリプトを生成してユーザーに実行させる

### Step 6: 結果レポート

```markdown
## 実行完了

操作: 日付フォーマット統一
処理件数: 99行
所要時間: 1.8秒
エラー: なし

### 変更内容
- A2:A100 の日付フォーマットを YYYY-MM-DD に統一

### バックアップ
- シート: 「売上データ_backup_20260422_163000」
- この操作を取り消したい場合: バックアップからコピーして貼り付け

### 次のステップ案
- データの可視化（ピボット、チャート）
- 不整合の検出
- 別シートとの突合
```

### Step 7: ロールバック手順

操作結果に不満があった場合の戻し方を常に提示:

```markdown
元に戻したい場合:

1. バックアップシート「売上データ_backup_20260422_163000」を開く
2. 全選択してコピー
3. 元の「売上データ」シートに値貼り付け

または、スプレッドシートの「ファイル」→「変更履歴を表示」から該当時点に戻す。
```

## 操作パターン別のポイント

### 重複削除

- 何をもって重複と見なすかを明確化（全列一致？ 特定列一致？）
- 残すのは最初の行 / 最後の行？
- ドライランで「何件が重複扱いになるか」を必ず見せる

### 並び替え

- 複合ソートの場合、第1キー・第2キーを明確化
- 昇順 / 降順
- ヘッダ行を含めるか

### ピボット

- 行見出し・列見出し・値を明確化
- 集計方法（合計、平均、カウント）
- 新シートに作成するか既存シートに埋め込むか

### チャート追加

- グラフ種類（棒、折れ線、円、散布、複合）
- データ範囲
- タイトル・凡例・色

### フィルタ抽出

- 条件を明確化（単一条件 / 複合条件 / OR / AND）
- 結果を別シートに書き出すか、元シートで非表示にするか

## やってはいけないこと

- ドライラン省略: 「急いでるから」などの理由でも省略しない
- バックアップ省略: 設定で off にしていない限り必ず作る
- 複数操作の一括実行: 1操作ずつ承認を取る
- エラー時の自動リトライ: 失敗したら停止してユーザーに報告
- 他のスプレッドシートへの波及: 指定された対象以外に触らない

## プライバシー配慮

- シート内容を Claude API に送る際、機密度の高いデータ（給与、個人情報）が含まれる場合は注意
- ユーザーに「このシートの内容を処理しても問題ないですか？」と確認するケースあり
- 処理後、シート内容をログに残さない（`include_sensitive_content: false` の場合）
