# スライド作成チーム 連携ルール

## 基本原則

1. 役割を越境しない: 各工程の責任範囲を守る
2. 成果物はファイルに残す: `work/slide-maker/{案件}/` に保存
3. 判断ポイントは明示: 「ここは方針次第」を成果物に書く
4. ディレクター経由: 工程担当同士で直接やり取りしない

## 工程の流れ

```
director (要件整理)
   ↓
composer (ストーリー構成)
   ↓ [承認ポイント 1]
designer (デザイン設計)
   ↓ [承認ポイント 2]
builder (実ファイル生成)
   ↓ [承認ポイント 3]
advocate (品質検証)
   ↓
director (最終化・納品)
```

## 成果物ファイル

```
work/slide-maker/{案件}/
├── 01-director-brief.md
├── 02-composer.md
├── 03-designer.md
├── 04-builder/
│   ├── outline.md
│   ├── theme.yaml
│   ├── final.{形式}
│   └── assets/
├── 05-advocate-review.md
└── final.{形式}  # 納品物
```

## 依頼と完了報告

### 依頼ブリーフフォーマット
`references/handoff-format.md` 参照。

### 完了報告フォーマット
各担当ファイル（`agents/slide-*.md`）の末尾参照。

## 品質ルール

### 必須
- 事実・数値の創作をしない
- 出典を明記（特に引用・数値）
- 配布前提の案件では内部コードネーム・社内固有名詞を含めない
- 著作権侵害リスクのある素材を使わない
- アクセシビリティ（コントラスト比、文字サイズ）を意識

### 自己チェック（advocate 前）
- [ ] 要求を満たしているか
- [ ] 前工程の意図を引き継いでいるか
- [ ] オーディエンスに合った仕上がりか
- [ ] 機密情報の露出はないか

## エスカレーション

以下は director に即エスカレーション:

- 前工程の成果物に問題
- 要件が不明瞭
- 他エージェント連携エラー
- 著作権・法的懸念
- 納期の逼迫

## 並列実行

- 並列OK: 独立した素材収集、アイコン生成
- 並列NG: 前工程依存（designer は composer を待つ）
- director が判断

## 機密情報

- 機密マーカー付き素材は特別扱い
- `config.security.mask_sensitive` が true なら固有名詞をマスキング
- 配布前の最終チェックで、機密情報の露出を必ず確認

## 他エージェント連携

### 発動フロー
1. director が必要性判断
2. ユーザー承認を取る
3. researcher 相当の収集は director が統括（またはスキル内で composer が兼務）
4. 取り込んだ情報の出典を明示

### 連携しない場合
素材は director がユーザーから直接受け取り、composer に転送。
