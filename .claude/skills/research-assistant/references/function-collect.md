# 機能: 情報収集（ディープリサーチ実行）

> 前提: 呼び出し元（SKILL.md）の「設定の読み込み」で `./.research-assistant/config.yaml` を読み込み済み。
> 未読込なら先に読むこと。本ファイル内の `config.xxx` はその値を指す。


調査計画に基づき、WebSearch / WebFetch で実行。

## 手順

### Step 1: 複数キーワード検索

調査計画で準備したクエリを順に実行:

```
Search 1: "SaaS 市場規模 日本 2026"
Search 2: "SaaS market Japan 2026"
Search 3: "BtoB SaaS 統計"
Search 4: "クラウドサービス業界"
```

### Step 2: 信頼できる情報源を優先

検索結果から 信頼度順 に WebFetch:

1. 政府統計・業界団体
2. 大手調査会社
3. 大手メディア
4. 業界誌

### Step 3: 情報抽出

各ソースから:
- 数字（市場規模・成長率・シェア 等）
- 主張（トレンド・予測）
- 引用価値のある発言
- 出典元の情報（公表日・発表者）

### Step 4: 情報の記録

```markdown
## 情報: {主張・数字}

内容: 「{具体的な情報}」
出典: {URL}
発信者: {メディア・著者}
公表日: YYYY-MM-DD
取得日: YYYY-MM-DD
信頼度: ★★★★☆
備考: ...
```

### Step 5: 不足の補完

情報が足りない観点があれば追加検索:
- 違うキーワードで
- 違う期間で
- 違う角度で

### Step 6: クロスチェック

重要な主張は 必ず 3 ソース で確認:
- ソース1: ...
- ソース2: ...
- ソース3: ...

不一致があれば両方記録、考察。

### Step 7: 反証・反対意見

意図的に反対側も調べる:
- 「この主張は正しくない」
- 「代替の解釈」
- 「失敗事例」

### Step 8: 検索停止の判断

以下で完了:
- 主要な問いに答えられる
- 複数ソースで裏付け
- 新しい情報が出てこない（サチる）

## WebSearch / WebFetch の使い方

### WebSearch
- キーワード検索
- 最新結果取得
- 公式サイト発見

### WebFetch
- 特定 URL の詳細読み込み
- 長文記事から抜粋

### 組み合わせ例
```
1. WebSearch: "SaaS 市場規模 日本 2026"
2. 結果から 5つの URL を選定
3. WebFetch: それぞれ詳細取得
4. 数字をクロスチェック
```

## 有料コンテンツの扱い

### NG
- 有料サイトのスクレイピング
- ペイウォールを突破する試み

### OK
- 公開されている概要
- 無料の要約版
- プレスリリース

## 著作権への配慮

- 引用は短く
- 出典明記
- 長大なコピーはしない

## やってはいけないこと

- 1 ソースで結論
- 取得日を記録しない
- 出典を忘れる
- 有料コンテンツの無断転載
- SNS 情報を事実扱い
