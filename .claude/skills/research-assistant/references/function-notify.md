# 機能: 通知配信

> 前提: 呼び出し元（SKILL.md）の「設定の読み込み」で `./.research-assistant/config.yaml` を読み込み済み。
> 未読込なら先に読むこと。本ファイル内の `config.xxx` はその値を指す。


調査結果を関係者に通知する。

## 🔒 重要原則

1. 下書き作成→ユーザー承認→送信 がデフォルト
2. 自動送信は自分宛のみ（他者への自動送信禁止）
3. 送信前に必ずプレビュー
4. 誤送信防止の確認
5. 送信ログを残す

## 通知先

セットアップで設定。詳細は `references/tool-integrations.md`（都度最新調査）。

### 主要通知先

- メール: Gmail / Outlook
- Slack: webhook / MCP
- Microsoft Teams: webhook / Graph API
- Discord: webhook
- Chatwork: API
- LINE: Messaging API
- Google Chat: webhook

## 手順

### 1. 通知する調査結果の特定

```markdown
以下のどの結果を通知しますか？
- 2026-04-24 調査: {テーマ}
- 2026-04-23 調査: ...
```

### 2. 通知先の選定

```markdown
通知先を選んでください:
- [ ] メール（田中さん, 山田さん 等）
- [ ] Slack（#business-research チャンネル）
- [ ] Teams
- [ ] その他
```

### 3. 内容の要約レベル

```markdown
通知の詳細度:
1) 要点のみ（3-5行、リンクで詳細）
2) 標準（エグゼクティブサマリ）
3) 詳細（レポート全体）
```

### 4. 下書き作成

通知ツール別にフォーマット:

#### メール
```markdown
件名: 【調査完了】{テーマ}

{宛名} 様

お世話になっております。

{テーマ} の調査が完了しましたので、ご報告いたします。

## 要点
- {ポイント1}
- {ポイント2}
- {ポイント3}

## 詳細
レポート全文: {パス or URL}

ご確認いただき、ご不明点があればお知らせください。

{署名}
```

#### Slack
```markdown
📊 *調査完了: {テーマ}*

*要点:*
• {ポイント1}
• {ポイント2}
• {ポイント3}

:link: 詳細: {URL or パス}

cc: @{関係者}
```

#### LINE / Discord / Teams
フォーマットは各ツールに合わせて。

### 5. ユーザー承認（必須）

```markdown
## 送信プレビュー

通知先: {メール/チャンネル}
内容:
{下書き全文}

送信しますか？
- [ ] Yes, 送信
- [ ] No, 修正
- [ ] キャンセル
```

### 6. 送信

承認後、設定された方式で送信:
- MCP 経由
- API 経由
- webhook 経由
- 手動コピペ（ユーザーが自分で送信）

### 7. 送信ログ

```yaml
# notifications/YYYY-MM-DD.log
- time: "2026-04-24T10:30:00+09:00"
  research: "SaaS 市場調査"
  recipients:
    - slack: "#research"
  content_hash: "..."
  status: sent
```

## 定期通知

scheduled-run での定期調査・通知:

### 原則
- 自分宛のみ 自動送信
- 他者への定期配信は、毎回ユーザー承認

### 自分宛の例
- 毎朝: 業界ニュースダイジェスト → 自分の Slack DM
- 毎週: 競合動向 → 自分のメール

### 他者への定期送信
- 組織の承認フロー必須
- 初回は手動、2回目以降は簡易承認
- 送信停止機能必須

## 誤送信防止

### チェック項目
- [ ] 送信先は正しいか
- [ ] CC / BCC の区別
- [ ] 添付ファイル
- [ ] 機密情報が含まれていないか
- [ ] 誤字脱字

### 間違えやすいパターン
- ドメイン打ち間違い
- 同姓異名
- グループ宛に個人宛のつもり

### 対策
- 送信前プレビュー必須
- 重要度が高い通知は 2 回確認
- 送信取消機能（可能なツール）

## 機密情報の扱い

### 送信してはいけない内容
- パスワード・API キー
- 個人情報（許可なく）
- 社外秘情報（社外宛）
- ブランドを損ねる内容

### マスキング
必要に応じて `{会社名}` `{金額}` 等に置換してから送信。

## 通知ツール別の注意

### LINE Notify 廃止
- 2025年3月末で廃止済み
- LINE Messaging API 等への移行を推奨
- 都度最新調査 で後継を確認

### Slack Webhook
- URL が漏れると誰でも送信可能
- 環境変数管理

### メール
- 送信ドメイン認証（SPF/DKIM/DMARC）
- 迷惑メール判定回避

## やってはいけないこと

- ユーザー承認なしの送信
- 送信先の誤り
- 機密情報の外部送信
- スパム的な大量配信
- オプトアウト無視（継続配信で）
- 認証情報を通知内容に含める
