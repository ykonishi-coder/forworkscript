# プライバシー詳細ガイド（不安を持つ方向け）

このドキュメントは、採用業務で候補者の個人情報を扱うことに不安を感じる方のための 深掘り説明 です。

## よくある不安とその答え

### Q1. 「Claude に情報を送ると、学習に使われてしまうのでは？」

結論: 使われません。

#### 仕組みの説明

Anthropic の Claude API は、送信データの扱いについて明確なポリシーがあります:

1. API 経由で送信されたデータは、デフォルトでモデル学習に使用されません
2. これは Anthropic 社の公式方針であり、利用規約にも明示されています
3. つまり、履歴書を API に送っても、将来の Claude モデルがその情報を「覚えている」ことはありません

#### 参照

最新の Anthropic プライバシーポリシー・利用規約で明示:
- [anthropic.com/privacy](https://www.anthropic.com/privacy)
- 利用規約（Terms of Service）

### Q2. 「じゃあなぜ情報を送る必要があるの？」

処理のために一時的に必要だから。

- Claude は送信された情報を その場で理解して応答 します
- 例: 履歴書のテキストを送る → 評価ポイントを抽出 → 応答を返す → サーバー側で保持しない
- HTTP 通信で送る → 処理 → 応答 → その後は使われない、というイメージ

### Q3. 「送信中に盗まれたりしない？」

技術的対策が取られています。

- HTTPS 暗号化: 送信中のデータは第三者に見えない
- Anthropic のセキュリティ認証: SOC 2 Type II、ISO 27001 等（最新情報は Anthropic サイト）
- 通信品質・インフラは大手クラウドプロバイダー基準

ただし、完全にリスクゼロは不可能（どんな情報システムも同じ）。だからこそ:

### Q4. 「最も安心なのは、情報を送らないこと」

そのとおりです。本スキルは 最小化 を設計思想にしています。

#### 1. マスキング機能

氏名・住所・電話番号・メールアドレス等を自動的に `{候補者A}` `{住所}` 等の識別子に置換してから処理します。

```
元の情報: 田中太郎、東京都千代田区〇〇1-2-3、090-1234-5678、taro@example.com
送信情報: {候補者A}、{住所}、{電話}、{メール}
```

評価の精度は落ちません: 評価に必要なのは「どんなスキル・経験を持つか」であり、氏名や連絡先ではないため。

#### 2. 最小情報モード

評価に直接関係ない情報を そもそも送信しない:

- 顔写真
- 家族構成
- 配偶者の有無
- 本籍
- 趣味（職務関連性のないもの）

#### 3. 手動コピペ推奨

自動連携（ATS から一括取得）を使わず、あなたが目視で確認した情報だけ を渡す運用。

- 何が送られるか、その場で分かる
- 「この部分は送らない」を自分で判断できる
- 最も安心

### Q5. 「それでも、理論的なリスクが気になる」

理論的なリスクゼロを目指すなら:

#### オプション1: 構造化情報だけを送る

履歴書の生データではなく、自分で構造化した情報だけ送る:

```
年齢: 30代前半
最終学歴: 大学卒
職歴: 5年（ソフトウェアエンジニア）
主要スキル: Python / React / AWS
志望動機の要点: キャリアアップ、技術的挑戦
```

候補者を特定できる情報は一切含まない。評価はこれでも可能。

#### オプション2: Claude for Work / Enterprise 契約

組織で本格的に使うなら、Anthropic の エンタープライズ契約 を検討:
- データ処理契約（DPA）
- より厳格なデータ保護
- SLA

個人利用なら不要。

#### オプション3: 使わない

このスキルを使わず、従来通り手作業で進める選択肢もあります。便利さとプライバシーのバランスは、ご自身の判断です。

### Q6. 「他人のデータなのに自分が判断していいの？」

採用担当者の責任として:

1. 応募者に利用目的を通知: 「AI 評価支援ツールを使用します」等
2. 同意を取る: 応募時の同意文言に含める
3. 最小化: 必要最小限の情報で評価
4. 削除: 選考終了後、不要なら削除

これらは個人情報保護法で求められる内容です。

### Q7. 「同意してもらってないのに使いたい」

使わないでください。これは法的リスクになります。

代替案:
- 採用情報の利用目的に「AI 支援ツールの利用」を明示的に追加
- 既に応募済みの方には、別途同意取得
- または、候補者情報をマスキングして 個人を特定できない形 で利用

### Q8. 「会社のITポリシーで外部サービス利用が制限されている」

その場合:
- IT部門・法務部門に確認
- 社内の既存 AI ツール利用ルールに従う
- Anthropic のエンタープライズ契約があれば、社内承認済みかも

個人判断で勝手に使わない ことが重要。

## 保存データの削除

### 選考終了後の削除

`config.privacy.cleanup.delete_after_days` で自動削除設定可能:

```yaml
cleanup:
  enabled: true
  delete_after_days: 90  # 90日で削除
```

### 手動削除

完全削除したい場合:

```bash
# Mac / Linux
rm -rf ./.hiring-assistant/candidates/  # 候補者データ
rm -rf ./.hiring-assistant/screening/   # 書類選考記録
rm -rf ./.hiring-assistant/interviews/  # 面接FB
```

```powershell
# Windows PowerShell
Remove-Item -Recurse -Force ./.hiring-assistant/candidates/  # 候補者データ
Remove-Item -Recurse -Force ./.hiring-assistant/screening/   # 書類選考記録
Remove-Item -Recurse -Force ./.hiring-assistant/interviews/  # 面接FB
```

または設定フォルダごと（どのOSでもフォルダを削除すればOK）:

```bash
# Mac / Linux
rm -rf ./.hiring-assistant/
```

```powershell
# Windows PowerShell
Remove-Item -Recurse -Force ./.hiring-assistant/
```

### 不採用者の個別削除

```bash
rm ./.hiring-assistant/candidates/{候補者ID}.md
```

ただし、ファイル削除だけでなく、処理時に Claude API に送った情報は送信時点で終わっています（保存されない）。

## git 事故防止

### 必須: .gitignore 設定

```
# .gitignore に以下を追加
.hiring-assistant/
candidates/
screening/
interviews/
comparisons/
```

### git に誤コミットした場合

既に push した場合:
1. 過去コミットから完全削除は難しい（git filter-branch 等で可能だが複雑）
2. リポジトリ自体の作り直しを検討
3. 関係者に事故を通知、法的対応

まだローカルだけの場合:
1. `git reset --soft HEAD~1` で取り消し
2. `.gitignore` に追加してから再コミット

最善: 最初から `.gitignore` を正しく設定する。このスキルはセットアップ時に自動追加を提案します。

## よくある勘違い

### ❌ 「AI は全部覚えている」
→ Claude API はステートレス。各リクエストは独立。前のリクエストの情報は覚えていない

### ❌ 「Anthropic に履歴書が溜まっていく」
→ 学習に使わない設計なので、溜まらない

### ❌ 「匿名なら何送ってもいい」
→ マスキングしても、詳細すぎる経歴から個人が特定可能な場合あり（小さな組織では特に）。最小化の意識は必要

### ❌ 「社員情報は大丈夫」
→ 社員も個人情報。本人同意なしの第三者提供は違法

## まとめ

1. 学習に使われない（Anthropic 方針）
2. マスキング機能で送信情報を最小化
3. ローカル保存のみ
4. 自動削除ポリシー
5. git 事故防止 .gitignore 自動設定
6. 同意取得と利用目的通知はユーザー責任
7. それでも不安なら「手動コピペ + 構造化情報」で使う
8. 極端に不安な候補者はスキル利用対象外にする選択も

プライバシーに完璧なシステムはありません。リスクを理解し、できる限り最小化する意識が大切です。
