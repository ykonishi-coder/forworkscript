# 機能: 面接質問作成

> 前提: 呼び出し元（SKILL.md）の「設定の読み込み」で `./.hiring-assistant/config.yaml` を読み込み済み。
> 未読込なら先に読むこと。本ファイル内の `config.xxx` はその値を指す。


職種・候補者の経歴に合わせた、構造化面接の質問リストを作成する。

## 大原則

1. 評価観点と連動: 求人票の評価基準にリンクした質問
2. 構造化面接: 全候補者に同じコア質問を使う（公平性）
3. 差別的質問の排除: advocate が自動チェック
4. 深掘りの準備: 想定回答に対する追加質問も準備
5. STAR法: Situation / Task / Action / Result の形式を意識

## 入力

1. 職種（役割の概要）
2. 求人票の評価基準（ルーブリック）
3. 候補者情報（あれば。なくても汎用質問は作れる）
4. 面接タイプ（一次 / 二次 / 最終 / カジュアル面談）
5. 面接時間（30分 / 45分 / 60分 / 90分）

## 手順

### 1. 評価観点の整理

求人票から評価観点を抽出、質問のカバー範囲を決める:

```markdown
## この面接でカバーする観点

1. 技術スキル: Python / React / クラウド
2. 問題解決力: 複雑な技術課題への取り組み
3. コミュニケーション: チーム内・他部門との協働
4. カルチャーフィット: 自律性・成長意欲
5. モチベーション: なぜこの会社・職種？
```

### 2. 質問カテゴリ別のドラフト

#### カテゴリA: 経歴・実績（20%の時間）

構造化質問 + STAR 深掘り:

```markdown
### Q1: 自己紹介と直近の職歴
（STAR法を意識して深掘り）

軸: キャリアの方向性、主要な成果

深掘り例:
- S: その時の状況を具体的に教えてください
- T: 何を達成する役割でしたか？
- A: 具体的にどう行動しましたか？
- R: 結果はどうでしたか？数字で示せますか？
```

#### カテゴリB: 技術スキル（30%の時間）

職種に応じた技術質問:

```markdown
### Q2: {職種特有の技術課題}

例（エンジニア）: 最も複雑だった技術的課題とその解決プロセス

評価観点:
- 技術の深さ
- 問題分解能力
- トレードオフの判断

深掘り:
- なぜそのアーキテクチャを選んだ？
- 他の選択肢との比較は？
- うまくいかなかった点は？
```

#### カテゴリC: 問題解決・状況対応（25%の時間）

シチュエーション質問:

```markdown
### Q3: 想定シチュエーション質問

例: 「リリース直前に重大バグが見つかりました。どう対応しますか？」

評価観点:
- 優先度判断
- ステークホルダー考慮
- 再発防止意識
```

#### カテゴリD: コミュニケーション・協働（15%の時間）

```markdown
### Q4: チーム内での意見対立経験

軸: コンフリクト解決、共感力、主張と妥協のバランス

深掘り:
- その時、相手はどう考えていたと思いますか？
- 最終的にどう決着しましたか？
- 学びは？
```

#### カテゴリE: モチベーション・文化適合（10%の時間）

```markdown
### Q5: 志望動機・期待

軸: 本音の動機、期待と現実のギャップ予測

避けるべき質問:
- ❌ 「結婚の予定は？」
- ❌ 「何歳までに管理職に？」
- ✅ 「このポジションで実現したいこと」
```

### 3. 候補者固有の質問

候補者情報が渡されている場合、経歴から深掘りしたい点を個別に作成:

```markdown
### 候補者固有の質問

1. 前職の〇〇プロジェクトについて、もう少し詳しく
2. ブログで書かれていた△△について、実運用ではどう？
3. 学生時代の□□の経験が今の仕事にどう活きている？
```

注意: 経歴への言及は OK、個人的属性への言及は NG（advocate がチェック）。

### 4. 面接時間に合わせた調整

```markdown
## 時間配分（60分の場合）

- 冒頭あいさつ・自己紹介: 5分
- 経歴・実績（カテゴリA）: 10分
- 技術スキル（カテゴリB）: 18分
- 問題解決（カテゴリC）: 15分
- コミュニケーション（カテゴリD）: 7分
- 候補者からの質問: 5分
```

30分の面接なら、カテゴリを絞る:
- 冒頭: 3分
- 経歴・実績: 7分
- 最重要観点1つ（技術 or 問題解決）: 15分
- 候補者からの質問: 5分

### 5. advocate によるチェック

質問リストを `hiring-assistant-advocate` に渡してチェック:

- 差別的質問（年齢・性別・家族等）がないか
- 主観的で曖昧な質問（「印象は？」等）がないか
- 特定候補者だけ有利/不利になる質問がないか

問題があれば修正案を受け取り、反映。

### 6. 出力フォーマット

```markdown
# 面接質問リスト

候補者: {名前またはID}
ポジション: {職種}
面接タイプ: {一次 / 二次 / 最終}
面接時間: {分}
面接官: {名前}
面接日時: YYYY-MM-DD HH:MM

---

## 冒頭（5分）
- あいさつ
- 自己紹介
- 面接の流れ説明
- 候補者の緊張をほぐす軽い質問

---

## セクション1: 経歴・実績（10分）

### Q1: キャリアの流れ
質問: これまでのキャリアを5分程度で教えてください。

深掘り:
- 一番挑戦的だったのは？
- 現職を変えたい理由は？

評価観点: キャリアの方向性、主要な成果

---

## セクション2: 技術スキル（18分）

### Q2: 最も複雑だった技術課題
質問: これまでで最も複雑だった技術的課題と、その解決プロセスを教えてください。

深掘り:
- S: その時の状況は？
- T: 何を達成する役割？
- A: 具体的な行動は？
- R: 結果は？数字で示せる？

評価観点: 技術の深さ、問題分解、トレードオフ判断

期待される回答レベル:
- 🟢 優秀: 複数の解決策を比較検討、トレードオフ説明
- 🟡 標準: 1つの解決策を実装・説明できる
- 🔴 懸念: 表面的な説明、トレードオフに触れない

---

（以下、全質問）

---

## セクション6: 候補者からの質問（5分）
- 「質問はありますか？」
- 会社・ポジション・入社後について

---

## クロージング
- 選考プロセスの次ステップ説明
- 連絡時期の目安
- お礼

---

## 面接官メモ欄（当日の記録用）
- 第一印象:
- 特筆すべき発言:
- 懸念点:
- 総合評価:

---

## バイアス防止チェック（advocate レビュー済み）
- [x] 差別的質問なし
- [x] 構造化・公平性確保
- [x] 職務関連の質問のみ
```

### 7. ファイル保存

```
{保存先}/interviews/prep/{候補者ID}-{面接タイプ}-YYYY-MM-DD.md
```

## 職種別のコア質問サンプル

### エンジニア
- 最も複雑だった技術課題
- コードレビューで重視する点
- 新しい技術の学び方
- 設計判断のトレードオフ

### 営業
- 最大の売上を上げた案件
- 難しい顧客への対応
- 目標未達だった時の振り返り
- 競合に勝つ戦略

### マネージャー
- チームビルディングの経験
- 部下のパフォーマンス管理
- 部門間調整の経験
- 戦略決定のプロセス

### 企画職
- 新規企画の立案から実行
- データ分析の経験
- ステークホルダー管理
- 失敗プロジェクトの振り返り

## やってはいけないこと

- 差別的質問を含める（advocate が自動検出）
- 誘導的質問（「〇〇は当然ですよね？」等）
- 候補者の人格を評価する質問（業務行動を評価）
- プライベート領域への質問（家族・恋愛等）
- 答えがすでにある質問（履歴書に書いてあることを聞く）
- Yes/No で終わる質問（深掘りできない）
