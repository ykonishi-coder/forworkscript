# 機能: 書類選考

> 前提: 呼び出し元（SKILL.md）の「設定の読み込み」で `./.hiring-assistant/config.yaml` を読み込み済み。
> 未読込なら先に読むこと。本ファイル内の `config.xxx` はその値を指す。


履歴書・職務経歴書・志望動機書を、評価基準（ルーブリック）に沿って評価する。

## 大前提: プライバシー保護

書類選考は個人情報処理の中でも特に慎重に。このスキルは以下を徹底:

- マスキング推奨: 設定の `privacy.masking_level`（`maximum` / `strict` / `standard`）に従い、候補者情報を自動マスキング
- 最小化: 評価に必要な情報だけ処理、顔写真等は対象外
- 原文を長期保存しない: 評価サマリのみ保持
- 法令遵守: 個人情報保護法・職業安定法に配慮

## 入力

1. 候補者情報 (履歴書・職務経歴書・志望動機書)
2. 求人票（JD） または評価基準（ルーブリック）

## 手順

### 1. プライバシー確認

最初に必ずユーザーに確認:

```markdown
書類選考を始める前に確認させてください:

1. 候補者情報の マスキング 設定:
   現在: {最厳重 / 厳重 / 標準}
   変更しますか？（または今回のみ最厳重モード？）

2. 情報の取り扱い:
   - ローカル保存: 評価サマリのみ、原文は保存しません
   - 処理後: Claude API に送られたデータは学習に使われません
   - 削除: {cleanup.delete_after_days}日後に自動削除されます

3. 応募者への同意取得:
   応募時に「AI 支援ツールでの選考」への同意を取っていますか？
   （取っていない場合、処理の継続はおすすめしません）

進めてよろしいですか？
```

### 2. マスキング処理

入力された候補者情報を読み取り、以下を自動マスキング（設定レベルに応じて）:

#### 最厳重モード
- 氏名 → `{候補者A}`
- 住所 → `{住所}`
- 電話番号 → `{電話}`
- メール → `{メール}`
- 顔写真 → 処理対象外（入力から除外）
- 家族情報 → 処理対象外
- 本籍 → 処理対象外

#### 厳重モード
- 連絡先 → マスキング
- 氏名 → そのまま
- 顔写真 → 処理対象外

#### 標準モード
- 連絡先 → マスキング
- 氏名・学歴・職歴 → そのまま（評価に使用）

### 3. 求人票（JD）・評価基準の確認

ユーザーから JD と評価基準を受け取る。なければテンプレート（`templates/screening-rubric.template.md`）を元に共作。

```markdown
## 評価基準
1. {必須要件} - 例: Python 3年以上
2. {歓迎要件} - 例: AWS 経験
3. {カルチャーフィット} - 例: チーム協働を重視
4. {成長可能性}
```

### 4. 書類評価

各評価基準について、候補者情報から該当する記述を探し、評価:

```markdown
## 評価

### 必須要件: Python 3年以上
- 結果: ✅ 満たす
- 根拠: 「前職で Python を4年間使用、バックエンド開発を担当」
- 強さ: ★★★☆☆

### 歓迎要件: AWS 経験
- 結果: ✅ 部分的に満たす
- 根拠: 「AWS EC2, S3 の使用経験あり。EKS, Lambda は未経験」
- 強さ: ★★☆☆☆

### カルチャーフィット
- 結果: 情報不足（面接で要確認）
- 聞きたい質問: 「チームでの合意形成の経験」
```

### 5. 強み・懸念の抽出

```markdown
## 総合サマリ

### 強み
1. {具体的な強み - 職歴・スキルから}
2. {強み}
3. {強み}

### 懸念点
1. {懸念 - 業務要件とのギャップ}
2. {懸念 - 書類からは判断できない点}

### 面接で確認したいこと
1. {質問1}
2. {質問2}
3. {質問3}
```

### 6. 推奨ラベル

```markdown
## AI としての推奨

推奨ラベル: 次フェーズ推奨 / 要検討 / 次フェーズ非推奨

（これは参考情報です。最終判断は採用担当者が行ってください）

### 推奨理由
{なぜこの推奨になったか、客観的な根拠}

### 注意事項
- 書類情報だけでの判断には限界があります
- 実際のスキル・人物像は面接で確認してください
- バイアスチェックを `hiring-assistant-advocate` で実施することを推奨
```

### 7. バイアスチェック（必須）

`hiring-assistant-advocate` に評価結果を渡してレビュー依頼:

```markdown
## バイアス防止レビュー（advocate より）

### 🔴 Critical
（なければ空）

### 🟡 Warning
- 「大学のネームバリュー」への言及が見られます
- 代替: 大学名ではなく、在学中の学習内容・成果で評価

### 🟢 Info
- より包括的な書き方の提案: ...
```

### 8. ファイル保存

評価サマリのみを保存（原文は保存しない）:

```
{保存先}/screening/{YYYY-MM-DD}-{候補者ID}.md
```

候補者IDは、マスキング済みの識別子（例: `CAND-001`）を使う。

### 9. ユーザーへの提示

```markdown
## 書類選考結果

候補者: {マスキング or 実名、設定による}
職種: {職種}
日付: YYYY-MM-DD

### 評価
（上記の評価を統合して表示）

### AI 推奨
次フェーズ推奨 / 要検討 / 非推奨

### バイアスチェック
🟢 問題なし / 🟡 指摘 {N} 件 / 🔴 修正必要

### 保存
- 評価サマリ: {ファイルパス}
- 原文データ: 保存されていません（破棄済み）

最終判断は、採用担当者であるあなたがお願いします。

---

次のステップ:
- 「面接質問作って」で、この候補者向けの面接質問を生成できます
- 「候補者比較」で、他候補との比較ができます
- 不要なデータを削除したい場合: `rm {ファイルパス}`
```

## 複数候補者の一括処理

ユーザーから複数候補の書類が渡された場合:

1. 件数確認: 10名以上なら時間がかかることを案内
2. マスキング一括適用
3. 各候補を個別処理
4. 一覧サマリも生成（`comparisons/` に保存）

## やってはいけないこと

- マスキングをスキップ（ユーザー承認があっても慎重に）
- 候補者情報の外部送信（Claude API以外）
- 評価を断定する（参考情報として提示、判断はユーザー）
- バイアスチェックをスキップ
- 候補者情報の長期保存（評価サマリ除く）
- 他の目的への流用（今回の採用以外に使わない）

## 禁則事項（評価に含めてはいけない）

以下の属性は 評価に使わない（含まれていても無視する、または advocate が警告）:

- 性別・性自認
- 年齢（業務上の合理的理由がない限り）
- 国籍・民族
- 出身地・本籍
- 家族構成・配偶者・子
- 宗教・信条
- 病歴（業務と関係しない）
- 外見（顔写真等）

## エラー時の対応

### マスキングが上手くいかない
- 手動でマスキング済みの情報を渡してもらう
- 最厳重モード継続

### 書類から情報が読み取れない（スキャン画質悪い等）
- ユーザーに確認を依頼
- 勝手に推測しない

### 明らかに資格要件を満たさない場合
- 明確に記載（「必須要件: Python 3年以上」を満たさない、等）
- ただし断定せず、「書類からの判断」と明示

## 完了メッセージの例

```markdown
## 書類選考完了

対象: 候補者A（マスキング済み）
ポジション: シニアソフトウェアエンジニア
評価日: 2026-04-23

### 総合評価
- 必須要件: ✅ 満たす
- 歓迎要件: ✅ 部分的に満たす
- カルチャーフィット: 面接で要確認

### 強み
- バックエンド開発経験4年、特に分散システム
- スタートアップでのリード経験
- 公開 OSS への貢献

### 懸念
- AWS のマネージドサービス経験が限定的
- 大規模組織での経験が少ない

### 面接で確認したいこと
1. 複雑な技術的トレードオフをどう判断するか
2. 他部門との協業経験
3. メンタリング経験

### AI 推奨
次フェーズ推奨 — 強みが職務要件に合致、懸念は面接で補完可能

### バイアスチェック
🟢 特に問題なし（advocate レビュー済み）

### 保存
- 評価サマリ: ./.hiring-assistant/screening/2026-04-23-CAND-001.md
- 原文: 保存されていません

最終判断は、採用担当者であるあなたがお願いします。
```
