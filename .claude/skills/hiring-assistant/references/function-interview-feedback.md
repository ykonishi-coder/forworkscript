# 機能: 面接フィードバック整理

> 前提: 呼び出し元（SKILL.md）の「設定の読み込み」で `./.hiring-assistant/config.yaml` を読み込み済み。
> 未読込なら先に読むこと。本ファイル内の `config.xxx` はその値を指す。


面接官の生メモを構造化フィードバックに整理する。

## 大原則

1. 事実と主観を分離
2. 評価基準ベース（単一の軸で比較可能に）
3. バイアス検出: advocate が自動チェック
4. 複数面接官の意見を統合（あれば）
5. 次ステップへの示唆を含める

## 入力

1. 面接官の生メモ（箇条書き・走り書き・録音文字起こし等）
2. 評価基準（interview-prep で使ったもの）
3. 候補者情報（マスキング済み）

## 手順

### 1. メモの読み込み

面接官の生メモを読む。多くの場合、以下のような状態:

```
- 自己紹介、普通
- Pythonできる、言ってた
- AWS経験少ない
- コミュ悪くない
- 熱意あった、志望動機しっかりしてた
- ちょっと年いってる
- 前職でミス多かったって言ってた、管理職経験なし
```

### 2. 情報の分類

以下の3つに分類:

#### A. 事実（観察された行動・発言）
- 「Python 5年使用」
- 「前職で部下3名のマネジメント経験あり」
- 「AWS は EC2, S3 のみ使用経験」

#### B. 主観的評価（印象・感想）
- 「コミュニケーション良好」
- 「熱意が伝わった」
- 「自信がなさそうに見えた」

#### C. バイアスの可能性ある記述（advocate に検出させる）
- 「ちょっと年いってる」← 年齢バイアス
- 「男性らしくて」← 性別バイアス
- 「〇〇大学出身だから期待できる」← 学歴バイアス

### 3. 評価基準別に再整理

```markdown
## 評価基準別 整理

### 技術スキル
事実:
- Python 5年使用、主にバックエンド
- AWS EC2, S3 利用経験、EKS・Lambdaは未経験
- オープンソース貢献なし

主観:
- 技術への興味は感じられた

評価レベル（標準ルーブリック）:
- 🟡 標準レベル: 必須要件は満たすが、歓迎要件は部分的

### 問題解決力
事実:
- 「難しい課題」の例として、分散システムのデバッグを挙げた
- 複数の解決策を比較検討していた

主観:
- 論理的な説明ができた

評価レベル:
- 🟢 高評価: 複数案比較、トレードオフ判断が明確

### コミュニケーション
事実:
- 質問に対して明確に返答
- 自分の経験を具体的に説明
- 不明な点は「分かりません」と正直に答えた

主観:
- 話し方が落ち着いている

評価レベル:
- 🟢 高評価: 明確で誠実

### カルチャーフィット
事実:
- 自律性重視のチームで働いていた
- 「技術的な挑戦を続けたい」という動機
- 過去に部下のマネジメント経験あり

主観:
- 当社のカルチャーに合いそう

評価レベル:
- 🟢 高評価
```

### 4. バイアス検出（advocate）

`hiring-assistant-advocate` に整理中の内容を渡してチェック:

```markdown
### 🔴 Critical
- 「ちょっと年いってる」は年齢バイアスの可能性
  - 採用判断材料にしない
  - 代替: 業務に関係するスキル・経験で評価

### 🟡 Warning
- 「前職でミス多かった」の言い方
  - 文脈が不明確（どんなミス？どう対処？）
  - 代替: 具体的な事実確認が必要、解釈を加えない

### 🟢 Info
- 「熱意あった」→ 具体的な発言で裏付けられるとより客観的
```

事実:
- ...

### 6. 複数面接官の意見統合（該当時）

複数の面接官からFBを受け取る場合:

```markdown
## 面接官別まとめ

### 面接官A（エンジニアリングマネージャー）
- 技術: 🟢 高評価
- カルチャー: 🟡 標準
- 推奨: 次フェーズ推奨

### 面接官B（プロダクトマネージャー）
- 技術: 🟡 標準
- カルチャー: 🟢 高評価
- 推奨: 要検討

### 意見が分かれる点
- 技術レベル: A は高評価、B は標準
  - 理由の違い: A は深さを評価、B は幅を重視
  - 解決策: どちらの観点を重視するか、採用決定会議で議論

### 統合推奨
次フェーズ推奨（両者とも致命的懸念なし）

ただし、次フェーズで以下を確認:
- B が懸念した「幅の広さ」を具体的に
- チームとの相性
```

### 7. ファイル保存

```
{保存先}/interviews/feedback/{候補者ID}-{面接タイプ}-YYYY-MM-DD.md
```

### 8. 次ステップの案内

```markdown
## 次のステップ

このフィードバックを元に:
- 他候補者と比較したい → 「候補者比較」と依頼
- 次フェーズの面接質問を作成 → 「次面接の質問作って」
- オファー判断の材料に → 「オファー判断」
```

## 生メモが少ない場合

面接官のメモが不十分な場合:

1. ユーザーに追加情報を聞く:
   > 面接の内容について、もう少し詳しく聞かせてください:
   > - 技術的な質問で印象的だった回答は？
   > - コミュニケーション面での気づきは？
   > - 懸念を感じた瞬間は？

2. 答えられる範囲で構造化、不足部分は「確認不能」として記録

## 録音・書き起こしからの処理

面接録音の文字起こしが渡された場合:

1. 文字起こしを段階別に分類（質問ごとに）
2. 各回答から事実・主観を抽出
3. 構造化FBを作成

録音原文は、設定に応じて保存 または 処理後破棄。デフォルトは破棄（プライバシー重視）。

## やってはいけないこと

- 事実と主観を混ぜる
- バイアスのある表現をそのまま転記（advocate が修正）
- 面接官の主観を「事実」として書く
- 候補者の人格全体を評価する（業務関連のみ）
- 推薦のない主観的評価（「好印象」だけではNG）

## 完了メッセージ

```markdown
## 面接フィードバック整理完了

候補者: {名前またはID}
面接: 一次面接
日時: YYYY-MM-DD

### 評価サマリ
- 技術スキル: 🟡 標準
- 問題解決: 🟢 高
- コミュニケーション: 🟢 高
- カルチャーフィット: 🟢 高

### 総合推奨
次フェーズ推奨

### バイアスチェック
🟡 指摘 1件（年齢に関する言及を修正済み）

### 保存
- FB: ./.hiring-assistant/interviews/feedback/CAND-001-first-2026-04-23.md
- 原メモ: 設定により{保存 / 破棄}

次のアクション:
- 他候補との比較を見たい → 「候補者比較」
- 次フェーズの準備 → 「次面接の質問作って」
```
