# 採用支援 初回セットアップウィザード

## ウィザード開始時のあいさつ（プライバシー強調）

> これから 採用支援エージェント の初期設定を始めます。
>
> 大切なお知らせ:
> 採用業務は個人情報の宝庫です（履歴書・職務経歴書・連絡先など）。
> このスキルは、プライバシーに特別な配慮をしています。
>
> 🔒 安心していただきたい 5 つのこと:
>
> 1. 学習に使われません: 入力した候補者情報は、Anthropic の API 方針により、将来の Claude モデルの学習には使われません
> 2. マスキング機能: 氏名・住所・電話等を `{候補者A}` 等に自動置換する機能があります
> 3. ローカル保存のみ: 設定・評価記録はすべて あなたのPC内 に保存
> 4. 手動コピペ推奨: ATS（採用管理システム）との自動連携は使わず、あなたが選んだ情報だけを渡す運用が最も安心です
> 5. バイアス防止機能: 別エージェント（DA）が差別・バイアスを検出して警告します
>
> 詳しくは `references/privacy-deep-dive.md` もご覧ください。
>
> それでは、まず1つだけお伺いします。

## Q0: ユーザータイプ

>
> A) まず何ができるか試してみたい（架空のサンプル候補者でデモ）

> C) しっかり設定して、自分に合わせて便利に活用したい
> D) まだよく分からない

   - 1) エンジニア書類選考のデモ

3. デモ実行
4. 続けるか確認

## B プラン: 最小セットアップ（3問）

### BQ1: 使っている採用管理ツール

> Q. 現在、採用管理に使っているツールを教えてください（複数可）。
>
> 1) Excel / Google Sheets（シート管理）
> 2) Notion（採用データベース）
> 3) 採用管理システム（ATS）: Greenhouse / Lever / Workday / 他
> 4) メール + ファイルフォルダ
> 5) 特に決まっていない / 手運用
>
> ※ このスキルはデフォルトで 手動コピペ 運用です。
>   自動連携は初期設定では行いません（セキュリティ重視）。

回答を `config.current_tools` に記録（参考情報）。

### BQ2: 個人情報の扱い方針

> Q. 候補者の個人情報の取り扱いで、どのレベルを選びますか？
>
> 1) 最厳重: 氏名・住所・連絡先・顔写真等を自動マスキング（推奨）
> 2) 厳重: 連絡先と顔写真だけマスキング、氏名は残す
> 3) 標準: 評価に必要と判断した情報はそのまま、法令遵守で運用
> 4) その他（カスタム設定）
>
> 迷ったら 1) を強くおすすめします。評価の精度に影響しません。

### BQ3: 評価記録の保持期間

> Q. 評価記録（書類選考結果・面接FB 等）はどのくらい保持しますか？
>
> 1) 選考終了後すぐ削除（不採用者のみ / 合格者含めすべて）
> 2) 採用活動期間中のみ（数ヶ月）
> 3) 1年間（前年採用からの比較用）
> 4) カスタム
>
> ※ 個人情報保護法の観点からは、不要になったら削除 が原則です。

### 完了後の案内

> セットアップ完了です。
>
> 使い方:
> - 「書類選考して」で書類評価
> - 「面接質問作って」で質問リスト
> - 「面接FB整理して」でフィードバック構造化
> - 「候補者比較」で横並び
>
> 最初は手動コピペでお試しください。慣れてきたら自動連携を検討できます。

## C プラン: フルセットアップ

B プランに加えて:

### Q4: 採用する職種・業種

- 主に採用する職種（エンジニア / 営業 / 企画 / バックオフィス / 他）
- 業界（IT / 金融 / 製造 / サービス / 他）
- これは評価観点のデフォルトを決めるために使用

### Q5: 評価基準（ルーブリック）

- 組織で共通の評価基準がある場合、設定
- ない場合、一般的なルーブリックを提示（`templates/screening-rubric.template.md`）
- 職種別に異なる場合、複数登録可能

### Q6: 面接官設定

- 社内の面接官リスト（名前のみ、個人情報は避ける）
- 各面接官が担当する評価観点
- FB 整理時の参照用

### Q7: バイアス防止レベル

- 厳しめ: advocate が全機能で自動起動、指摘を丁寧に
- 標準: 重要な決定ポイント（書類選考・最終判断）で起動
- 緩め: 明示的に「バイアスチェックして」と言われたときのみ

### Q8: ATS 自動連携（必要な場合のみ）

重要: 自動連携は 個人情報を機械的に API 経由で処理する ため、セキュリティ意識が特に必要。

連携するかどうかを確認:

> ATS の自動連携は、候補者情報を機械的に処理することになります。
> 個人情報保護の観点から、手動コピペでの運用を強く推奨 します。
>
> それでも自動連携が必要ですか？
> - はい、業務効率のため必要
> - いいえ、手動コピペで運用する

「はい」の場合のみ、その場でネット調査 して最新の連携方式を提案:

```
Greenhouse API MCP {今年}
Lever API Claude integration
Workday integration {今年}
ATS Anthropic skills
```

提示テンプレートは `references/tool-integrations.md` 参照。連携先の書き込み権限は 最小限 に。

### Q9: 組織・法的コンプライアンス

- 組織の個人情報保護規程（適用する規程名）
- 応募者への利用目的通知の内容
- 不採用者情報の削除ポリシー
- これらは `config.compliance` に記録、評価時の参照用

## セットアップ完了処理

### 1. 保存先決定

> 設定と評価データの保存先を選んでください:
>
> 1) `./.hiring-assistant/`（推奨・プロジェクト直下）
> 2) 現在のプロジェクト直下
> 3) 任意のパス
>
> 個人情報を含むため、安全なフォルダ（暗号化対応・バックアップ除外等）を選んでください。

### 2. ファイル生成

- `config.yaml`
- `candidates/` フォルダ（候補者別評価）
- `screening/` フォルダ（書類選考記録）
- `interviews/` フォルダ（面接FB）
- `comparisons/` フォルダ（候補者比較）

### 3. .gitignore 追記（必須）

> ⚠️ 採用データは 絶対に git リポジトリに含めてはいけません。
> `.gitignore` に以下を追加します:
>
> ```
> .hiring-assistant/
> ```
>
> これで git コミット時の事故を防げます。追加してよろしいですか？

### 4. 削除ポリシーの自動化

```yaml
cleanup:
  enabled: true
  delete_after_days: 90  # 選考終了後90日で削除
  notify_before_delete: true
```

### 5. 初回テスト提案

> セットアップ完了です。お試しで動作確認しますか？
>
> 1) 架空のサンプル候補者で全機能を試す
> 2) セットアップだけで終える
>
> 実在の候補者情報は、動作に慣れてからお使いください。

## プライバシー詳細 FAQ

### Q. 「学習に使われない」って本当？
> はい。Anthropic は API の利用規約で、送信データをモデル学習に使わないことを明示しています。エンタープライズ契約ではさらに厳格なデータ処理契約（DPA）も可能です。

### Q. それでも不安です
> 送信する情報を最小化する「マスキング」機能があります。また「手動コピペ」運用にすれば、あなたが目で確認した情報だけが Claude に渡ります。

### Q. 処理中に情報が漏れたりしない？
> Claude API は HTTPS で暗号化通信されます。Anthropic 側でもセキュリティ対策（SOC 2 Type II 等）を講じています。ただし理論的な完全ゼロリスクはどの仕組みでもあり得ないため、最も機密な候補者情報は、ご自身の判断で最小化 してください。

### Q. GDPR / 個人情報保護法に対応している？
> スキル自体は ツール であり、法令遵守は使う側（採用担当者・組織）の責任です。このスキルは、法令遵守しやすいように「最小化」「削除ポリシー」「マスキング」等の機能を用意しています。

### Q. 不採用者の情報削除
> `cleanup.delete_after_days` を設定すると、期限切れデータを自動削除できます。手動でも `rm -rf ./.hiring-assistant/`（Windowsは `Remove-Item -Recurse -Force ./.hiring-assistant/`） で完全削除可能。
