# 機能: 既存サイトのテキスト・レイアウト修正

> 前提: 呼び出し元（SKILL.md）の「設定の読み込み」で `./.design-consultant/config.yaml` を読み込み済み。
> 未読込なら先に読むこと。本ファイル内の `config.xxx` はその値を指す。


すでに公開されている、または制作中のWebサイトに対して、部分的な修正を加える機能。

## 想定シーン

- サービス紹介文を差し替えたい
- 誤字脱字の修正
- ボタンの文言や色を変えたい
- レイアウトを少しだけ直したい
- 新しいセクションを追加したい
- 古い画像を新しいものに入れ替えたい
- 表示が崩れている場所を直したい

「大規模リニューアル」ではなく、小〜中規模の修正を安全に加えるのが目的。

---

## 基本原則

### 1. 本番環境に直接触らない
- 本番サーバー・本番リポジトリに直接プッシュしない
- 必ず検証環境（プレビューデプロイ / ローカル）で動作確認
- 確認後にユーザー承認を取ってから本番へ

### 2. 変更前の状態を保全する
- Git で管理されているならブランチを切って作業
- Git 管理されていないなら修正前ファイルをバックアップ
- 差分が明確に見えるようにする

### 3. 差分提案を先に出す
- いきなりファイル書き換えではなく、「こう変えますよ」案を先に提示
- ユーザー承認 → 書き換え の順

---

## 作業ワークフロー

### ステップ1: 現状の把握
- 対象URL or ローカルファイルパス
- 使っているフレームワーク（純HTML/CSS / Next.js / Vue / WordPress 等）
- デプロイ方式（Vercel / Netlify / 自前サーバー / レンタル）
- Git 管理の有無

### ステップ2: 修正範囲の確認
- どのページの、どこを、どう変えたいのか
- 影響範囲の仮説（他ページに波及しないか）
- ブランド・トーンのルールと整合しているか

### ステップ3: 差分提案
Before / After で示す:

```diff
- 従来のテキスト or コード
+ 新しいテキスト or コード
```

複数箇所の場合は一覧で。

### ステップ4: ユーザー承認

### ステップ5: 実施
- ブランチ作成（例: `fix/update-hero-copy`）
- 修正
- ローカル / プレビュー で確認
- スクリーンショット添付

### ステップ6: PR作成（github-flow モードへ引き継ぎ）
- 変更理由・差分サマリ・影響範囲を PR 本文に
- レビュー観点リストを添える

### ステップ7: 本番デプロイ
- PRマージ → Vercel 等の自動デプロイ
- 本番での最終確認
- もし問題あれば即座にロールバック

## 典型的な修正カテゴリ

### テキスト修正
- 誤字脱字・言い回し改善
- サービス名変更・料金改定
- ニュース更新

### リンク修正
- リンク切れ修正
- 内部リンクの見直し
- SNS リンクの追加・変更

### レイアウト微修正
- 余白調整
- 配色微調整
- レスポンシブの崩れ修正

### 画像差し替え
- 古い画像の置き換え
- 画像圧縮・最適化
- OGP 画像の更新（banner モード連携）

### セクション追加・削除
- 「お知らせ」セクションの追加
- 期間限定バナーの追加・削除

### SEO・メタ情報
- title / description の改善
- OGP タグの見直し
- 構造化データの追加

## 影響範囲チェックリスト

修正前に必ず確認:

- [ ] 他ページに同じテキスト・コンポーネントが使われていないか
- [ ] レスポンシブ（スマホ / タブレット / PC）で崩れないか
- [ ] アクセシビリティ（見出しレベル・alt・コントラスト）を損なわないか
- [ ] SEO（titleタグ・descriptionタグ・内部リンク）に副作用がないか
- [ ] ブランドガイドラインに反していないか
- [ ] 景表法・薬機法表記の観点で問題ないか
- [ ] 画像の著作権・肖像権は問題ないか

---

## フレームワーク別の注意

### 純HTML/CSS
- シンプル。ファイル直接編集
- キャッシュ設定に注意

### Next.js / Nuxt 等の静的サイト
- ビルド必要
- `npm run dev` で確認
- 本番ビルド（`npm run build`）でエラーないか必ず確認

### WordPress
- 本体・プラグインの更新と相互作用
- 子テーマで編集するのが基本
- データベース変更が絡む修正は特に慎重に
- バックアップ必須

### ノーコード（STUDIO / ペライチ / Wix）
- ブラウザ操作が中心になるため、コンピュータ操作（Computer Use）機能を検討
- ただし設定は上級者向け

---

## 禁止事項

- 本番環境に直接書き込む
- ユーザー承認なしにファイル保存
- 「動いているように見える」で完了宣言（必ずテスト）
- Git履歴を改変する（force push 等）
- バックアップなしでリスクある修正
- 他社サイトの無断改変（本人・自社サイトのみ対応）

---

## 他エージェントとの連携

- text-quality-checker: 修正後テキストの誤字脱字・文法チェック
- content-creator: 新しい文章の作成依頼
- engineer-assistant: 複雑な実装変更が絡むとき
- security-guard: 設定ファイル（CLAUDE.md・hooks）に触る修正は audit 連携

連携は必ずユーザー承認を取る。
