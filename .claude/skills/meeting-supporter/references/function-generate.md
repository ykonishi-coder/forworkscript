# 機能: 議事録生成

> 前提: 呼び出し元（SKILL.md）の「設定の読み込み」で `./.meeting-supporter/config.yaml` を読み込み済み。
> 未読込なら先に読むこと。本ファイル内の `config.xxx` はその値を指す。


## 入力として受け取るもの

必須:
1. 会議内容（以下のいずれか）
   - 録音の文字起こしテキスト
   - 手書きメモ・走り書き
   - Zoom / Teams 等の自動文字起こし出力
   - 会議の流れを箇条書きで要約したもの

できれば:
2. 会議情報（タイトル、日時、参加者、場所）
3. 特にフォーカスしたいトピック

不明点は1往復でまとめて聞く。

## 手順

### 1. 入力の正規化

- 録音タイムスタンプ付きの場合は時系列を保持
- 発言者タグ（speaker: 〇〇）があれば保持
- 改行・段落の整形

### 2. 会議メタデータの抽出

冒頭や文脈から以下を抽出:
- タイトル
- 日時
- 参加者（肩書き付きで）
- 場所（オンライン/オフィス）
- 会議の目的

不明なものはユーザーに確認。

### 3. 内容の構造化

以下の4セクションに分類:

#### A) 議題と議論
- 各議題について「議論のポイント」「主要な発言」「背景」を整理
- 長い議論は要約、重要な発言は引用として残す

#### B) 決定事項
- 会議で明確に決まったこと
- 「〇〇について、✅実施する / ❌実施しない / 🕒保留」の形で
- 決定の根拠も添える

#### C) To-Do（アクションアイテム）
- 誰が何をいつまでに
- 期限が不明なら `期限未定` と記載（勝手に推測しない）
- 担当者不明なら `担当要確認` と記載

#### D) 次回議題・持ち越し
- 今回結論が出なかった話題
- 次回に回された検討事項

### 4. フォーマット適用

`templates/meeting.template.md` のフォーマットに従う。

### 5. ファイル保存

保存パス:
```
{config.output_dir}/YYYY-MM-DD-{タイトルをスラッグ化}.md
```

例:
```
./.meeting-supporter/meetings/2026-04-22-weekly-sync.md
```

### 6. ユーザーへの報告

```markdown
## 議事録を生成しました

タイトル: 〇〇定例
日時: 2026-04-22 14:00-15:00
参加者: 3名

### 決定事項（抜粋）
- ✅ 〇〇は実施する
- ❌ △△は見送り

### To-Do（3件）
- {担当者}: 〇〇を YYYY-MM-DD まで
- {担当者}: △△を 期限未定
- 担当要確認: □□を次回まで

保存先: {パス}

必要に応じて直接編集してください。
```

## 議事録の品質ガードレール

### 絶対にやらない
- 発言の創作: 文字起こし・メモにない発言を作らない
- 決定の創作: 曖昧な議論を「決定」と書かない
- 担当者・期限の推測: 明示されていないものは `担当要確認` `期限未定`

### 注意
- 冗長な発言の要約: 雑談や余談は省く、ただし重要度判断はユーザーに委ねるメモを残す
- 機微情報の扱い: 給与・人事など機密度の高い発言は、必要最小限の記録にとどめる
- 不整合の指摘: 議論中に矛盾があった場合、議事録末尾に「⚠️ 未解決の不整合」として記載

## 文字起こし品質が低い場合

誤変換が多い・音声が途切れている場合:

1. 明らかに意味が通らない箇所は `{不明瞭}` としてマーク
2. ユーザーに確認を促す:

   > 以下の箇所は文字起こしが不明瞭でした。お手元のメモで補足できますか？
   >
   > - ...

3. 確認なしで推測による補完はしない

## 出力ファイルの構造

詳細は `templates/meeting.template.md` 参照。骨格:

```markdown
# {会議タイトル}

日時: YYYY-MM-DD HH:MM-HH:MM
参加者: ...
場所: ...
目的: ...

## 議題と議論

### 議題1: XXX
{議論要約}

## 決定事項

- ✅ ...
- ❌ ...

## To-Do

| 担当 | 内容 | 期限 |
|------|------|------|
| ... | ... | ... |

## 次回議題・持ち越し

- ...

---
## 文字起こし原文（参考）

<details>
<summary>クリックで展開</summary>

{元の文字起こし（保存オプション有効時のみ）}

</details>
```

## プライバシー配慮

- `include_transcript` が `false` の場合、元の文字起こしは議事録ファイルに保存しない
- 参加者の個人情報（肩書き・連絡先）は最小限に留める
- 機密マーカー（`[CONFIDENTIAL]` など）があれば、より厳重に扱う
