# 機能: To-Do追跡

> 前提: 呼び出し元（SKILL.md）の「設定の読み込み」で `./.meeting-supporter/config.yaml` を読み込み済み。
> 未読込なら先に読むこと。本ファイル内の `config.xxx` はその値を指す。


## 目的

過去の議事録から未完了 To-Do を集計し、担当者別・期限別に整理して提示する。

## 入力

- 対象期間（デフォルト: 過去30日）
- フィルタ条件（任意: 担当者、期限、ステータス）

## 手順

### 1. 議事録フォルダをスキャン

```
{config.output_dir}/*.md
```

各ファイルから `## To-Do` セクションを抽出。

### 2. To-Do の構造化

各 To-Do を以下の形式に正規化:

```yaml
- task: "〇〇を整理する"
  owner: "田中さん"
  deadline: "2026-04-30"
  status: "open"  # open / done / overdue
  source_meeting: "2026-04-15-weekly-sync.md"
  created_at: "2026-04-15"
```

### 3. ステータス判定

- open: 期限到来前
- overdue: 期限超過
- done: 別議事録で「完了」が明示されている
- unknown: 期限未定

### 4. 集計と提示

#### 全体サマリ

```markdown
## To-Do 追跡レポート（{生成日時}）

### 集計
- 未完了: 12件
- 期限超過: 3件 ⚠️
- 完了済み（過去30日）: 8件

### 担当者別
- 田中さん: 5件（うち期限超過 1件）
- 山田さん: 4件
- 担当要確認: 3件

### 期限別
- 今週中: 2件
- 今月中: 5件
- 期限未定: 3件
- 期限超過: 3件
```

#### 詳細リスト

期限超過を最優先で表示:

```markdown
### ⚠️ 期限超過
1. 〇〇を整理する
   - 担当: 田中さん
   - 期限: 2026-04-18（4日超過）
   - 発生議事録: 2026-04-15-weekly-sync.md

### 今週中
...

### 今月中
...
```

### 5. リマインド提案（任意）

ユーザーが「リマインドメール送りたい」と言った場合:

- 担当者ごとにリマインドメールの下書きを生成
- 送信はしない。下書きファイルへの保存のみ
- secretary エージェントの `email-reply` 機能を呼び出して標準フォーマットで作成

```markdown
リマインドメールの下書きを3通用意しました:

1. 田中さん宛（5件のTo-Do）
   → `{保存先}/reminders/2026-04-22-tanaka-san.md`
2. 山田さん宛（4件）
   → ...

送信するかどうかはご自身で判断してください。
```

## やってはいけないこと

- 勝手にリマインド送信: ユーザー承認なしにメール送信
- ステータスの自動更新: 議事録に明示されていないのに「完了」と判定しない
- 担当者への直接通知: 通知先は依頼元ユーザーのみ
- 期限の推測: 「期限未定」を勝手に「1週間後」などにしない

## フィルタ例

ユーザー指示に応じて:

- 「今週の To-Do 教えて」 → `deadline` が今週内のもの
- 「田中さんの宿題」 → `owner == 田中`
- 「期限過ぎてるやつ」 → `status == overdue`
- 「私の To-Do」 → 署名の氏名で絞り込み

## 状態更新

ユーザーが「〇〇は完了したよ」と言った場合:

1. 該当 To-Do を特定
2. 対応する議事録ファイルを開いて、該当項目に `✅ 完了（YYYY-MM-DD）` を追記
3. 変更箇所をユーザーに見せてから保存

元の議事録テキストは改変せず、追記形式で更新する。

## プライバシー配慮

- 担当者名・関係者名は、他者に共有しない
- 機密プロジェクトの To-Do は、通常のリストとは別扱い（マーカー `[CONFIDENTIAL]`）
- リマインド下書きは、送信を想定した内容以外では個人情報を最小限に
