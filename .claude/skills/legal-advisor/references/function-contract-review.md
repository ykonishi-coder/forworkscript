# 機能: 契約書チェック

> 前提: 呼び出し元（SKILL.md）の「設定の読み込み」で `./.legal-advisor/config.yaml` を読み込み済み。
> 未読込なら先に読むこと。本ファイル内の `config.xxx` はその値を指す。


契約書を条項別にレビューし、不利条項・リスクを検出する。

## 大原則

1. マスキング推奨: 相手方名・金額・個人情報を自動マスキング
2. 立場を確認: ユーザーが甲か乙か、発注側か受注側か
3. advocate 連携: 必ず legal-advisor-advocate のレビューを通す
4. 免責明示: 最終判断は弁護士へ、を必ず添える
5. 法令情報は最新: 古い法令知識に基づく指摘を避ける

## 入力

1. 契約書本文（貼り付け or ファイル）
2. 契約タイプ（NDA / 業務委託 / 売買 / 利用規約 / 雇用 / その他）
3. ユーザーの立場（甲 / 乙、発注 / 受注 等）
4. レビューの目的（締結前チェック / 更新判断 / 紛争予防）

## 手順

### 1. プライバシー確認

```markdown
契約書レビューを始める前に確認させてください:

1. マスキング: 設定「{最厳重 / 厳重 / 標準}」で処理します。変更しますか？

2. 送信情報: 
   - 契約書本文は処理時に Claude API に送られます（学習には使われません）
   - 機密性が高い場合、相手方名・金額を自分で伏せた版を送ることをおすすめします

3. 保存: 
   - レビュー結果のサマリをローカル保存します（原文は保存しません）
   - {cleanup.delete_after_days} 日後に自動削除されます

進めてよろしいですか？
```

### 2. 契約タイプ判定

契約書の冒頭・目次から判定:

- 「秘密保持契約書」「NDA」 → NDA
- 「業務委託契約書」 → 業務委託
- 「売買契約書」「物品売買」 → 売買
- 「賃貸借契約書」 → 賃貸借
- 「利用規約」「サービス利用契約」 → 利用規約
- 「雇用契約書」「労働契約書」 → 雇用
- その他 → カスタム

### 3. ユーザーの立場確認

```markdown
ユーザーはこの契約でどの立場ですか？

- [ ] 甲（通常は発注側・強い立場）
- [ ] 乙（通常は受注側・弱い立場）
- [ ] 当事者A / B（対等な場合）

立場によって「どの条項が不利か」が変わります。
```

### 4. 契約書を条項別に分解

各条項を独立して分析:

```markdown
## 条項リスト

### 第1条（目的）
### 第2条（業務内容）
### 第3条（契約期間）
### 第4条（対価）
### 第5条（秘密保持）
### 第6条（知的財産権）
### 第7条（解除）
### 第8条（損害賠償）
### 第9条（管轄裁判所）
```

### 5. 条項別の評価

各条項について:

#### 内容の要約
そのまま読んで何が書いてあるか

#### 評価
- 🟢 妥当: バランスの取れた条項
- 🟡 注意: やや不利 or 曖昧、改善余地
- 🔴 懸念: 明確に不利、要修正

#### 根拠
なぜその評価か

#### 改善案
どう直せばよいか

### 6. よくある不利条項の検出

契約タイプ別に、チェックリスト（`templates/risk-checklist.template.md` 参照）に沿って確認:

#### NDA
- 秘密情報の定義が曖昧すぎる or 広すぎる
- 秘密保持期間が長すぎる（10年以上等）
- 一方的に秘密保持義務を負っている
- 残留情報（従業員の記憶）の扱いが厳しすぎる
- 契約終了後の返還・破棄義務が非現実的

#### 業務委託
- 業務範囲が不明確
- 検収条件が曖昧 → 検収がいつまでも完了しない
- 成果物の著作権が全て発注側に帰属（知財譲渡）
- 瑕疵担保責任の期間が長すぎる
- 再委託禁止が絶対的
- 中途解除権が一方的（発注側のみ）
- 追加・変更作業の対価規定がない

#### 売買
- 契約不適合責任（旧: 瑕疵担保）の期間が短すぎる
- 検収期間が長すぎる（支払遅延）
- 所有権移転時期が曖昧
- 危険負担の規定が不明確

#### 利用規約
- 一方的変更可能（ユーザーが不利）
- 免責範囲が過度に広い
- 準拠法・管轄が外国
- 退会・解約手続きが困難

#### 雇用
- 試用期間が長すぎる
- 競業避止義務が広範囲・長期
- 秘密保持義務が退職後も長期
- 労働時間・賃金の条件が労基法違反

### 7. 必要条項の欠落チェック

その契約タイプで 通常あるべき条項 が欠けていないか:

共通必須:
- 契約当事者の特定
- 契約の目的
- 契約期間・解除条件
- 対価（有償の場合）
- 秘密保持（該当する場合）
- 紛争解決・管轄

欠落があれば指摘:

```markdown
### 欠落: 〇〇条項

この業務委託契約には、瑕疵担保責任 の条項が見当たりません。
- リスク: 成果物に瑕疵があった場合の責任関係が不明確
- 推奨: 「乙は納品後6ヶ月以内に発見された瑕疵について、無償で修補する」等の条項を追加
```

### 8. 法令適合性チェック

日本の法令に照らして:

#### 下請法（発注側が資本金1000万円超 x 受注側が1000万円以下等の場合）
- 支払期日: 60日以内
- 支払遅延の禁止
- 減額の禁止
- 買叩きの禁止
- 返品の禁止（合理的な場合以外）

#### 独占禁止法
- 優越的地位の濫用
- 拘束条件付取引

#### 消費者契約法（B to C）
- 消費者の利益を一方的に害する条項（無効の可能性）
- 平均的な損害額を超える違約金

違反の可能性があれば 🔴 Critical で指摘。

### 9. advocate レビュー

`legal-advisor-advocate` に評価結果を渡してレビュー依頼。advocate の指摘を統合。

### 10. 総合判定

```markdown
## 総合判定

### リスクレベル: 低 / 中 / 高

### 主要な懸念
1. 🔴 {最重要懸念}
2. 🔴 {懸念}
3. 🟡 {注意点}

### 推奨アクション
- [ ] 🔴 Critical 項目の修正を相手方に提案
- [ ] 🟡 Warning 項目の検討
- [ ] 専門家（弁護士）への最終確認

### 交渉のヒント
相手方に修正を求める際の論点:
- 「第〇条の〇〇は一方的なので、双方対等に」
- 「下請法の観点から、支払期日を見直していただきたい」
```

### 11. ファイル保存

レビュー結果のサマリのみ保存:

```
{保存先}/reviews/{YYYY-MM-DD}-{契約ID}.md
```

### 12. ユーザー提示

```markdown
## 契約書レビュー結果

契約タイプ: 業務委託契約
ユーザーの立場: 乙（受注側）
レビュー日: YYYY-MM-DD

### 総評
- リスクレベル: 中〜高
- 主要懸念: 知的財産権の包括譲渡、解除条項の一方性、検収条件の曖昧さ

### 条項別評価
（上記の評価を統合）

### 🔴 Critical（必ず修正交渉を）
1. 第6条（知的財産権）
   - 現状: 「成果物の著作権・特許権は全て甲に帰属する」
   - 問題: 乙が従前から持つノウハウまで譲渡対象に読める
   - 修正案: 「本業務のために新たに作成された成果物の著作権は甲に帰属し、乙の既存ノウハウ・汎用的技術は乙に帰属する」

2. 第7条（解除）
   - 現状: 「甲は任意に解除できる」
   - 問題: 乙に解除権がない、違約金規定なし
   - 修正案: 「甲が任意解除する場合、既履行業務の対価 + 着手済み業務の50%を支払う」等

### 🟡 Warning
1. 第3条の「速やかに」→ 具体的な期間を
2. 第4条の検収条件 → 検収期間を30日以内に明記
3. 瑕疵担保条項の欠落 → 追加提案

### 🟢 Info
- 第9条の管轄裁判所は東京地方裁判所、バランス OK
- 第5条の秘密保持、相互対等で妥当

### 法令適合性
- 下請法: ⚠️ 貴社が資本金1000万円以下の場合、発注側の行為が下請法の規制対象になる可能性。支払期日・減額禁止等を確認
- 独占禁止法: 優越的地位の濫用の兆候なし

### 推奨アクション
1. 🔴 Critical 項目について、相手方に修正交渉
2. 🟡 Warning 項目を見直し提案
3. 最終的な契約締結前に、弁護士の確認を強く推奨

### バイアス / リスクレビュー (advocate より)
{advocate の指摘サマリ}

### 保存
- レビューサマリ: {パス}
- 原文: 保存されていません

---

⚖️ 免責: 本レビューは AI による一般的な指摘です。個別事情の判断・交渉戦略・最終判断は、必ず弁護士・法務専門家にご相談ください。
```

## 長文契約書の扱い

契約書が長い場合（50ページ超等）:

1. ユーザーに概要を確認:
   > 契約書が長いため、セクション単位で進めます。重点的に確認したい条項はありますか？
2. 章・節別に分けて処理
3. 全体サマリを最後にまとめる

## 複数契約書の比較

「A社とB社の業務委託契約を比較したい」等:

1. 各契約書を個別レビュー
2. 比較表を作成
3. どちらがユーザーに有利か整理

## やってはいけないこと

- 「合法です」「違法です」と断定（専門家領域）
- 交渉戦略を具体的指示（弁護士業務）
- 古い法令知識で指摘（最新を確認）
- マスキングをスキップ
- 契約書原文の長期保存（サマリのみ）

## 完了メッセージ

レビュー完了後、次のアクションを案内:

```markdown
### 次のアクション

1. レビュー結果を相手方と共有して修正交渉
2. 疑問点・判断に迷う点は弁護士に相談
3. この契約を管理対象に登録 → 「契約書管理に追加」
4. 別の契約書もチェック → 「次の契約書チェック」
```
