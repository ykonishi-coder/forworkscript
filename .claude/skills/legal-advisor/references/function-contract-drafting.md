# 機能: 契約書作成支援

> 前提: 呼び出し元（SKILL.md）の「設定の読み込み」で `./.legal-advisor/config.yaml` を読み込み済み。
> 未読込なら先に読むこと。本ファイル内の `config.xxx` はその値を指す。


契約書のドラフトを、テンプレート・条項集からユーザーの立場に合わせて生成する。

## 大原則

1. ユーザーの立場に有利な条項を優先
2. 標準的な条項構成を使う（業界慣行に沿う）
3. advocate にバイアス・公平性チェック依頼
4. 最終確認は弁護士へ を明示
5. 相手方の感情も考慮（極端に一方的な契約は締結されない）

## 入力

1. 契約タイプ（NDA / 業務委託 / 売買 / 賃貸借 / その他）
2. ユーザーの立場（甲 / 乙、発注 / 受注）
3. 基本情報:
   - 相手方の概要（大企業 / スタートアップ / 個人）
   - 契約目的
   - 期間
   - 金額（該当時）
   - 特記事項
4. 重視したい条項（あれば）

## 手順

### 1. ヒアリング

```markdown
契約書ドラフトを作成します。以下を教えてください:

### 基本情報
1. 契約タイプ: {NDA / 業務委託 / 売買 / etc}
2. あなたの立場: {甲 / 乙}
3. 相手方:
   - 組織規模（大企業 / 中小 / 個人）
   - 業種
   - 関係性（既存取引先 / 新規 / 競合）

### 契約の目的
4. 何のための契約？
5. 期間はどのくらい？
6. 金額（該当時）

### 重視したいこと
7. 特に注意したい観点（例: 秘密保持を強く、解除権を確保、知財を守る）
8. 譲れない条件
9. 避けたい条件（相手方から求められそうなもの）

### 提出先
10. この契約書を誰に見せますか？（相手方 / 社内確認 / 弁護士相談前の叩き台）

これらを踏まえてドラフトを作成します。
```

### 2. 契約タイプ別の骨組み生成

`templates/` の雛形から、契約タイプに合う骨組みを選ぶ:

- NDA: `templates/nda.template.md`
- 業務委託: `templates/service-agreement.template.md`
- （他の契約タイプも順次追加）

### 3. ユーザーの立場に合わせた条項選定

#### 立場別の重点

発注側（甲・強い立場）の場合:
- 成果物の著作権帰属を明確に
- 瑕疵担保責任を十分に確保
- 解除権を確保
- 検収権限を確保

受注側（乙・弱い立場）の場合:
- 業務範囲を明確化（範囲外は別料金）
- 検収期限を明記（いつまでも検収完了しないリスク防止）
- 既存ノウハウの留保
- 中途解除時の対価保全
- 瑕疵担保責任の期間限定

対等な関係:
- バランスの取れた条項
- 紛争解決メカニズム

### 4. 標準条項の組み合わせ

`references/standard-clauses.md` から条項を選んで組み合わせ（このファイルは必要に応じて別途作成）。

一般的な契約書の条項構成:

```markdown
# {契約タイプ} 契約書

第1条（目的）
第2条（{契約タイプ特有の中核条項}）
第3条（対価）
第4条（支払方法）
第5条（契約期間）
第6条（秘密保持）
第7条（個人情報）
第8条（知的財産権）
第9条（解除）
第10条（損害賠償）
第11条（反社会的勢力の排除）
第12条（不可抗力）
第13条（協議事項）
第14条（管轄裁判所）

締結日
甲・乙の署名押印
```

### 5. ユーザー情報の反映

マスキング設定を尊重しつつ、適切な箇所に情報を埋め込む:

```markdown
### 第1条（目的）

本契約は、甲 （{甲の情報}） と乙 （{乙の情報}） との間で、
{業務内容または契約目的} に関し、その条件を定めることを目的とする。

### 第3条（対価）

甲は乙に対し、本業務の対価として、金 {金額} 円（消費税別）を支払う。
```

未確定部分は `{プレースホルダー}` として残し、ユーザーに埋めてもらう。

### 6. 相手方が受け入れにくい条項への配慮

極端に一方的な契約は、相手方が拒絶して締結されないリスクがある:

```markdown
### 交渉現実性チェック

本ドラフトの以下の条項は、相手方（{相手方プロファイル}）が拒絶する可能性があります:

- 第X条: {条項}
  - 拒絶リスク: 中
  - 代替案: {より受け入れやすい形}

- 第Y条: {条項}
  - 拒絶リスク: 高
  - 代替案: {現実的なライン}
```

### 7. advocate レビュー

`legal-advisor-advocate` にドラフトを渡してチェック:

- 法令適合性
- バランス（あまりに一方的すぎないか）
- 欠落条項
- 曖昧な表現

指摘を踏まえて調整。

### 8. ユーザー提示

```markdown
## 契約書ドラフト: {タイトル}

契約タイプ: 業務委託契約書
作成日: YYYY-MM-DD
ユーザーの立場: 乙（受注側）

---

{契約書本文（プレースホルダー付き）}

---

## ドラフトのポイント

### ユーザー（乙）に有利な条項
- 第2条（業務範囲）: 範囲を明確化、範囲外は別料金条項あり
- 第4条（検収）: 検収期間を30日以内と明記（支払遅延防止）
- 第8条（知的財産）: 既存ノウハウは乙に留保、成果物のみ甲に帰属
- 第9条（解除）: 対等な解除権、中途解除時の対価保全

### 交渉ポイント
- 第8条の知財条項は、相手方が包括譲渡を求める可能性あり
  - 代替案: ライセンス方式を提案
- 第10条の損害賠償上限は、相手方が上限撤廃を求める可能性
  - 代替案: 故意・重過失を除く免責として残す

### 要埋め項目（プレースホルダー）
- `{甲の情報}`: 相手方の会社名・代表者
- `{乙の情報}`: あなたの情報
- `{業務内容}`: 具体的な業務内容
- `{金額}`: 対価
- `{期間}`: 契約期間

### advocate バイアスチェック
🟢 問題なし（公平なバランス）
🟡 注意: 第10条の損害賠償条項が標準よりやや限定的。相手方が受け入れるかは交渉次第

### 次のステップ
1. プレースホルダーを埋める
2. 自社内で確認
3. 弁護士・法務専門家に最終確認を依頼
4. 相手方と交渉
5. 締結後は「契約書管理」に登録

---

⚖️ 免責: 本ドラフトは AI による一般的な雛形です。個別事情への対応・法的適合性の最終確認は、必ず弁護士にご相談ください。
```

### 9. ファイル保存

```
{保存先}/drafts/{YYYY-MM-DD}-{契約タイプ}-{連番}.md
```

## 契約タイプ別のポイント

### NDA（秘密保持契約）

必須条項:
- 秘密情報の定義
- 秘密保持義務
- 使用目的の制限
- 秘密保持期間
- 複製・開示の制限
- 返還・破棄義務
- 違反時の措置

ポイント:
- 秘密情報の定義は 具体的に（広すぎると無効、狭すぎると保護不足）
- 相互NDAか一方的NDAか

### 業務委託契約

必須条項:
- 業務範囲（SOW）
- 成果物
- 対価
- 検収
- 瑕疵担保 / 契約不適合責任
- 知的財産
- 再委託
- 秘密保持

ポイント:
- 業務範囲の明確化（追加作業の扱い）
- 検収基準の明確化
- 再委託の可否

### 売買契約

必須条項:
- 目的物の特定
- 価格
- 納期
- 引渡方法
- 所有権移転時期
- 危険負担
- 契約不適合責任

### 賃貸借契約

必須条項:
- 目的物
- 賃料
- 期間
- 更新条件
- 原状回復義務

### 利用規約

必須条項:
- サービス内容
- 利用条件
- 禁止事項
- 免責
- 変更条項
- 準拠法・管轄

ポイント:
- 消費者契約法への適合（B to C の場合）
- 変更可能性の規定は厳格化傾向

## 業界特有の配慮

### IT・ソフトウェア
- 知的財産権（特許・著作権）
- ライセンス条件
- SaaS の場合: SLA、データ管理

### 製造業
- 品質保証
- 瑕疵担保
- PL法

### 金融
- 金商法遵守
- 説明義務

### 医療
- 患者情報保護
- 個人情報保護法（要配慮個人情報）

## やってはいけないこと

- 完璧な契約書だと断言する
- 専門家確認不要と誤認させる
- 一方的すぎて現実的でないドラフト
- 法令違反の条項を提示
- 相手方の情報を勝手に使う

## 完了メッセージ

```markdown
## 契約書ドラフト完成

契約タイプ: 業務委託
保存先: ./.legal-advisor/drafts/2026-04-23-service-agreement-001.md

### このドラフトの位置付け
- 初期案、交渉のたたき台
- 弁護士確認前

### 必須の次のステップ
1. ⚠️ プレースホルダー（{}）を埋める
2. ⚠️ 自社の法務・責任者確認
3. ⚠️ 弁護士・法務専門家の最終確認
4. 相手方との交渉
5. 締結後、契約管理に登録

### サポート
- 相手方からの修正要求が来たら → 「契約書チェック」で修正版を分析
- 別バージョン作成 → 「同じ契約タイプで別案」
- 専門家相談の準備 → 「弁護士相談用のサマリ作って」

⚖️ このドラフトは一般的な雛形です。必ず専門家確認を。
```
