# 機能: 社内規程整備

> 前提: 呼び出し元（SKILL.md）の「設定の読み込み」で `./.legal-advisor/config.yaml` を読み込み済み。
> 未読込なら先に読むこと。本ファイル内の `config.xxx` はその値を指す。


会社・組織の中で運用する規程類（就業規則・プライバシーポリシー・情報セキュリティ規程・利用規約 等）を、雛形からドラフト作成・既存規程の法改正追従・運用ルール整備まで支援する機能。

## 何をする機能？（初心者向け）

- 会社を運営していると、必ず何本かの「社内規程」を持つ必要があります
  - 従業員を雇うなら 就業規則
  - 個人情報を扱うなら プライバシーポリシー
  - PCや AI を使うなら 情報セキュリティ規程
  - サービスを提供するなら 利用規約
  - その他、倫理規程・反社対応規程・ハラスメント防止規程 など
- 規程はいちど作って終わりではなく、法改正・社会情勢・組織変化に合わせて更新し続ける必要があります
- このスキルは、雛形からの初期作成と、既存規程の差分更新をサポートします

---

## 重要な免責

- このスキルで作成する規程は 雛形・ドラフト です。最終版は 社労士・弁護士・専門家 の確認を経て導入してください
- 就業規則は常時10人以上雇用する事業所では労働基準監督署への届出が必要（労働基準法）
- プライバシーポリシーは事業実態と整合していないと法的効力が弱まります
- 情報セキュリティ規程は運用実態とズレると形骸化します

---

## 扱う主要規程

### 1. 就業規則
- 労働時間・休憩・休日・休暇
- 賃金・賞与
- 退職・解雇
- ハラスメント・服務規律
- 副業・兼業
- 懲戒
- テレワーク規定
- 10人以上の事業所は労基署への届出が必須

### 2. プライバシーポリシー（個人情報保護方針）
- 個人情報の取得項目・利用目的
- 第三者提供・委託
- 安全管理措置
- 開示・訂正・利用停止への対応
- Cookie / 広告 ID / 海外移転の扱い
- 問い合わせ窓口

### 3. 情報セキュリティ規程
- 情報資産の分類
- アクセス権限
- 認証・パスワード管理
- 端末管理
- 外部サービス・SaaS 利用ルール
- インシデント対応
- 退職・外注解除時の対応
- AI 利用ルール（近年特に重要）

### 4. 利用規約（サービス運営者）
- サービス内容・料金
- 禁止事項
- 退会・解除
- 責任範囲・免責
- 知的財産権
- 準拠法・紛争解決

### 5. その他
- 反社会的勢力排除規程
- ハラスメント防止規程
- 内部通報規程
- 慶弔見舞金規程
- 旅費交通費規程
- 守秘義務規程

## ワークフロー

### ステップ1: 整備対象の確認
- どの規程を整備するか
- 既存版があるか（あれば差分更新、なければ新規作成）
- 前回改定日
- 従業員数・事業規模（就業規則は規模で要件が変わる）

### ステップ2: 法改正情報の確認
必ず WebSearch で直近の改正情報を確認。たとえば:

```
就業規則 改正 {今年}
個人情報保護法 改正 {今年} ガイドライン
電子帳簿保存法 改正
労働時間 上限規制 改正
フリーランス保護新法
```

対応必須の改正があれば、規程に反映するポイントを整理。

### ステップ3: 実態ヒアリング
規程は実態とズレると機能しない。以下を確認:

- 実際の勤務時間・休暇運用
- 実際に扱っている個人情報の種類・ルート
- 使っている SaaS / AI / 外部サービス
- 現在のセキュリティ対策レベル（security-guard と連携）
- 実際に発生している契約・取引
- 外注・業務委託の関係

### ステップ4: ドラフト作成
- 雛形（templates/）をベースに、実態に合わせてカスタマイズ
- 用語定義セクションを先頭に
- 適用範囲・例外を明記
- 問い合わせ窓口・改定履歴を末尾に

### ステップ5: 法的視点でのレビュー
- legal-advisor-advocate に渡して批判的レビュー
- 既存の他規程との整合性
- 契約書との整合性
- 矛盾する条項がないか

### ステップ6: 専門家確認の案内
- 社労士（就業規則・労務関連）
- 弁護士（プラポリ・利用規約・反社）
- 個人情報保護士・DPO（プラポリ）
- 情報セキュリティ専門家（情報セキュリティ規程）

重要規程は必ず専門家の最終確認を通す。

### ステップ7: 導入・周知
- 従業員への周知方法
- イントラ・社内Wikiへの掲載
- 就業規則は労基署届出手続き
- 発効日・改定履歴の明記

### ステップ8: 定期見直し
- 年1回以上の見直しサイクルを推奨
- scheduled-run モードで「前回改定から X ヶ月経過」アラート

## 規程運用の実務アドバイス

### プライバシーポリシーの実務ポイント
- 「個人情報を適切に扱います」だけの抽象的な記述は弱い
- 取得している項目・利用目的・第三者提供先を具体的に列挙
- Web サービスなら Cookie / 広告ID / クロスデバイストラッキングの扱いも
- 問い合わせ窓口（メール / 電話 / フォーム）を必ず稼働
- 委託先（クラウド・SaaS）の監督方法も触れる
- 海外移転がある場合は移転先国・保護水準への言及

### 情報セキュリティ規程の実務ポイント
- AI / 生成AI の業務利用ルールを明記（何を入れていいか、悪いか）
- BYOD（私物端末）の扱い
- 退職・外注解除時のアカウント削除・端末回収手順
- インシデント発生時の連絡経路（security-guard と連携）
- テレワーク時の扱い

### 就業規則の実務ポイント
- 最新の労働法（時間外上限・年休取得義務化・育休関連）への対応
- 副業・兼業ルール（許可制 / 届出制）
- テレワーク規定
- メンタルヘルス・ハラスメント関連
- 懲戒事由の具体化

### 利用規約の実務ポイント
- 消費者契約法・特定商取引法との整合
- 定型約款（民法548条の2以降）の要件
- 変更手続きの明示
- 免責の限度（消費者契約法で無効になる条項に注意）

## advocate との連携

ドラフトを legal-advisor-advocate に渡して:

- 「直近の法改正を反映しているか」
- 「他規程・契約書と矛盾しないか」
- 「抽象的すぎて機能しない条項はないか」
- 「消費者契約法・労働法で無効になる可能性のある条項はないか」

を批判的にレビューしてもらう。

---

## 他エージェントとの連携

- security-guard: 情報セキュリティ規程の策定・AI利用ルールの整合
- hiring-assistant: 就業規則・採用関連規程
- customer-support-advisor: 利用規約・クレーム対応規程
- accounting-helper: 経費精算規程・出張旅費規程

連携は必ずユーザー承認を取る。

---

## 絶対にやらないこと

- 「これで完全」と断定（専門家確認が必ず必要）
- 実態とかけ離れた雛形コピペをそのまま採用
- 法改正追従をせずに古い雛形を使い続ける
- 他社の公開規程を丸写しする（法的リスクと整合性の問題）
- 就業規則で労働基準法以下の条件を規定（無効）
- 利用規約で消費者契約法違反の条項を放置
