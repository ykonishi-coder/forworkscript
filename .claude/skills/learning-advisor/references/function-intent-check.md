# 機能: 意図確認（最重要）

> 前提: 呼び出し元（SKILL.md）の「設定の読み込み」で `./.learning-advisor/config.yaml` を読み込み済み。
> 未読込なら先に読むこと。本ファイル内の `config.xxx` はその値を指す。


教育は目的で全く違うので、意図を丁寧に確認 する。

## なぜ重要か

### よくある失敗
- 「英語」と言っても、TOEIC / 日常会話 / ビジネス / 留学 で全く別
- 「プログラミング」も Web / データ分析 / 組込 / ゲーム で別
- 「リーダーシップ」も上司向け / プロジェクト / チームビルディング で別

曖昧なまま進めると、提案がズレる。

## 意図確認の質問

### 5W1H で深掘り

- Who: 誰の学習？（自分 / 誰か / チーム / 組織）
- What: 何を学ぶ？（具体的に）
- Why: なぜ？（動機・背景）
- When: いつまで？（期間・締切）
- Where: どこで？（環境・文脈）
- How: どうやって？（制約・リソース）

### 深掘り質問例

「〇〇を学びたい」と言ったら:

```markdown
もう少し具体的に教えてください:

1. なぜ学びたい？
   - 仕事で必要
   - 転職のため
   - 趣味・教養
   - 子どもに教えるため
   - その他

2. 学んだ後どうしたい？
   - 実務で活用
   - 資格を取得
   - 人に教える
   - 単に知りたい

3. 現状のレベル
   - 初心者
   - 基本は分かる
   - 実務で使ったことある
   - 専門的

4. 使える時間
   - 週何時間？
   - 何ヶ月以内に？

5. 制約・好み
   - 予算
   - 学習スタイル（自学自習 / オンライン / 対面）
   - 集中 / 分散
```

### 組織向けの深掘り

```markdown
1. 対象者は？
   - 新人 / 中堅 / 管理職 / 全員
   - 人数
   - 背景（業種・経験）

2. 教育の目的
   - 業務スキル向上
   - 昇進準備
   - 組織文化醸成
   - 問題解決

3. ビジネス課題との関連
   - なぜこの教育が必要？
   - 教育以外で解決できない？

4. 制約
   - 予算
   - 時間（業務時間？時間外？）
   - 強制 / 任意

5. 成功基準
   - 何ができたら成功？
   - どう測定？
```

## 意図確認の落とし穴

### 落とし穴1: 表面的な答えで済ませる

ユーザー: 「英語を学びたい」
AI: 「英語学習ロードマップです」→ ❌

本当は: 海外転職希望？ TOEIC 点数？ 日常会話？
→ 深掘りして確認

### 落とし穴2: 先に手段を考える

「英会話スクールがおすすめ」と言う前に、
- 対面必要か？
- 予算は？
- 継続できるか？

### 落とし穴3: 組織で個人の意図を無視

「全社員に英語研修」と言っても、
- 必要な人・不要な人
- モチベーションの差
- 強制の是非

### 落とし穴4: 過去の成功体験の押し付け

「私はこう学んだ」をそのまま他人に提案しない。
個人差・時代の違いを考慮。

- 答えを押し付ける

- 「あなたに必要なのはこれ」と断定
